# 团队蓝图废除与职责出处定案

## 用户洞察（原话要点）

团队蓝图是冗余的中间产物：最终生成的团队 Profile 就是蓝图的内容，两者冲突；蓝图若只是生成前的草稿说得通，作为持久化文件就是一份会带偏 LLM 的文档。职责在 Agent 的 IDENTITY/SOUL 有定义，团队定义的是总体业务流程与协作方法；从市场招聘回来的团队若本身已符合要求，根本连蓝图都不用——纯属浪费输出 token。

## 实证（支撑废除的证据）

1. daemon 代码零蓝图消费方：`mindx` 仓 grep `blueprint` 只命中 SKILL.md 自身与 notes，无任何代码读取 `.agents/plans/team-blueprint.md`——蓝图落盘后无人消费，唯一效果是留在磁盘上被后续会话读到。
2. 执行期 LLM 一旦看到蓝图文件，会把它当唯一事实源：无视 TEAM.md Profile 与成员 IDENTITY/SOUL 的既有定义，把职责与协作流程锁死在招聘时刻的快照上（marketing 推广团队蓝图已实测带偏，该文件 L3 自声明「不转录职责」仍被判定为带偏源）。
3. 已有反面教训在案：`.agents/notes/2026-11-17-glm-决策-空心Agent判据与派工阶梯量化定案.md`——蓝图曾让整队复用检索零字评估（team-blueprint.md 通篇复用论证停在 Agent 层）。
4. `.agents/memory/20261114-182425-assistant-pitfall-蓝图重复抄写岗位职责造成大面积冗余.md`：蓝图重复抄写岗位职责造成大面积冗余，同一痛点早有记录。

## 定案（用户裁决）

- 彻底废除强制蓝图，不为市场/本地已符合要求的团队生成注定删除的文档。
- 职责唯一出处 = Agent IDENTITY/SOUL；团队协作流程唯一出处 = TEAM.md Profile。执行期职责/流程与老板要求不符时，由计划技能在执行层补充。
- 复用检索闸不能删但顺序前置：先整队检索（本地 + 市场 `--kind team`，全流程词），命中契合 → 会话内确认 → 整队复用免考古免拆解；未命中才考古 → MECE 拆解 → 编制设计 → 会话内确认 → 建制。
- 编制决策记录按随手记规则落 `.agents/notes/`（决策类、轻量），禁止落 `.agents/plans/` 持久蓝图。
- 用户比喻：没有 HR 在招聘时就把每个岗位的做事细节抠死。

## 经验（可复用判据）

「中间产物是否该持久化」的判据：落盘后若有活跃消费方（代码/流程读取）才落盘；只服务于「生成下一样东西」的草稿留会话内，确认结论落轻量决策记录。持久化的设计中间件会被执行期 LLM 当事实源，与正式定义文件（TEAM.md / IDENTITY / SOUL）形成双源冲突。
