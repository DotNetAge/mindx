# runtime 技能中文名整改与假技能清理

- 记录时间：2026-11-17
- 记录人：glm（Trae 会话）
- 分类：事实
- 触发：用户否定直译中文名（「智能体创建」不是人话）与职位化中文名（规划师/铸造师），并发现混入的假技能

## 事实

1. 技能中文名规矩（已固化进 skill-creator v1.12.0 模板）：name_zh 必须是地道中文能力名（动宾或偏正短语，如 组建团队/派工），禁职位后缀（师/官/器）与英文名直译。
2. 全库 23 个 runtime 技能中文名已逐一整改：7 改（招募智能体/组建团队/插件立项/目标规划/技能铸造/搭建组织/搭建仪表板），15 个本来是人话的未动。
3. agent-creator 与 team-creator（原 team-planner）完成单/团边界重切：团队组建唯一入口是 team-creator（team-design.md 迁入其 references/），agent-creator 只管单个 Agent。
4. mx-release 是混入 mindx/runtime/skills 的假技能——真身在 mindx-work/.agents/skills/mx-release（其 notes 完整包含假壳内的全部 11 份进化档案且更新）；假壳目录与 ~/.mindx/skills/ 下两个陈旧安装拷贝（team-planner、mx-release）已删除，注册表无旧名残留。
5. scheduler 技能已删除（用户定案「直接删不合并」）：其 60% 正文是 Cron 工具说明书复述（三种形态/排程卫生/速查），40% 真内核随之弃置——派工判断三条件（可异步/验收明确/重复发生）、负责人匹配（先对能力画像再查过载）、派工日志 Content 四件套（目标/验收标准/上下文位置绝对路径/产出与去向）。此三项要点留痕于此备查；若未来派发质量劣化（一句话派工、派错人），首查此处。
6. dispatch-gate（派工闸门）定位澄清：不做工作分解（leader 职责）、不管何时跑（Cron 工具承载），只管派发前的规模与预算决策（三变量 + 0-3 档 + 渐进升级）；原 scheduler 中文名「派工」与「派工闸门」撞名是用户困惑根源，删除后消除。
7. 派工估算章法的归属经三轮演进定案：独立技能 dispatch-gate → 用户否决「负责人专设」（负责人接到任务第一步是出计划并估算工作量，估算以 LLM 工作方式进行而非把活当人做）→ 用户定案「goal-planner 职能，因为要共用」——章法最终收编 goal-planner v0.2.0 第二步「派工前估算定档（共用章法，所有负责人通用）」，dispatch-gate 删除。经验：能力先问「谁用、是否共用」，共用能力进职能技能，专岗能力进编制规范（SOUL 范式），不轻率立独立技能。

## 教训

- skill add 会把技能全文拷贝到 ~/.mindx/skills/<name>/，目录更名后旧拷贝不会自动消失，会以旧名残留在注册表——更名技能必须同步清理 ~/.mindx/skills/ 旧拷贝。
- 往 runtime/skills 添加技能前先确认技能归属仓（mindx vs mindx-work），防止跨仓混入。
