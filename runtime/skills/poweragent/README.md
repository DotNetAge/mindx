# 天工.skill

> "承古法之精微，启今用之新章。"
>
> **天工.skill** 是一套为 AI 智能体赋予专业灵魂的设计方法论与工具链。它不是简单地"写一段 prompt"，而是像匠人打磨器物一样，经历需求萃取、模板填充、技法注入、质量内控、最终交付五个阶段，产出一个真正有性格、有边界、可验证的专业 Agent。

---

## 为什么需要天工.skill？

写 prompt 容易，写好 prompt 很难。天工.skill 解决三个核心问题：

| 痛点 | 天工的解法 |
|------|-----------|
| "写出来像个客服机器人" | 身份五字段 + 表达 DNA 七维度 + 极限行为设计，让角色有温度、有缺点、有锋芒 |
| "规则写一堆，跑起来互相打架" | 内置规则冲突检测引擎（DO vs DON'T 语义交叉矩阵），在交付前自动揪出矛盾 |
| "交付了但不知道质量如何" | 两套验证脚本 + J4 质量内控 + 五场景回测，退出码决定能否交付 |

## 两种设计范式

天工.skill 提供两条截然不同的路线。判断标准只有一句话：

> **这个智能体在模仿一个人，还是在承担一个岗位？**

### 人物蒸馏 — 由内而外

适合场景：你想复刻某位思想家、作家、行业领袖的思维方式和表达风格，让 Agent 用 Ta 的视角看世界。

- **起点**：真实人物的著作、访谈、公开表达，从中提取心智模型
- **过程**：蒸馏 0（素材收集）→ 蒸馏 1（心智模型四重验证）→ 蒸馏 2（表达 DNA 量化）→ 蒸馏 3（决策启发式）→ 蒸馏 4（质量自检）→ 蒸馏 5（最终交付）
- **核心产出**：3-7 个心智模型（每个含跨域表现 + 典型引用）、5-10 条决策启发式、七维度表达 DNA
- **模板**：`examples/persona-template.md`（16 个必选章节）
- **验证**：`scripts/verify-persona.py`（16 项检查，一手来源占比 < 30% 触发低可信度警告）

### 岗位型专家 — 由外而内

适合场景：你需要一个律师、医生、税务顾问、代码审查员——角色不一定要像某个人，但必须像这个岗位上的靠谱专家。

- **起点**：岗位描述、职责清单、交付标准
- **过程**：J1 需求萃取 → J2 模板填充 → J3 技法注入 → J4 质量内控 → J5 最终交付
- **核心产出**：身份五字段（角色/个性/价值观优先/记忆/经验）、DO/DON'T 规则（按合规/流程/质量/沟通四组分类）、可量化 KPI（≥3）、领域知识图谱
- **模板**：`examples/job-template.md`（12 个模块）
- **验证**：`scripts/verify-skill.py`（岗位型深度 11 项校验 + 规则冲突检测）

### 范式对比速查

| 维度 | 人物蒸馏 | 岗位型专家 |
|------|---------|-----------|
| 设计方向 | 由内而外：心智模型 → 外部表达 | 由外而内：岗位职责 → 人格一致性 |
| 核心方法论 | 四重验证心智模型提取 | J1→J5 五阶段流水线 |
| 身份来源 | 真实人物的言行记录 | 岗位描述 + 领域知识 |
| 规则体系 | 决策启发式（软约束，5-10 条） | DO/DON'T（硬约束，四组分类） |
| 质量焦点 | 心智模型可信度、表达 DNA 可识别性 | KPI 可量化、规则可执行性 |
| 失败模式 | 素材不足、心智模型无法通过排他性验证 | KPI 模糊、DO/DON'T 互相矛盾 |
| 模板 | `examples/persona-template.md` | `examples/job-template.md` |
| 验证脚本 | `scripts/verify-persona.py` | `scripts/verify-skill.py` |
| 端到端示例 | — | `examples/tax-advisor-example.md` |

> **拿不准走哪条路？** 一句判断：「它在模仿一个人，还是在承担一个岗位？」详见 `SKILL.md` 快速导航表与路由决策树。

## 岗位型专家流水线：J1 → J5

这是天工.skill 最核心的设计流程。每一步都有明确的输入、输出和质量门禁。

### J1 需求萃取

**目标**：从用户的一句话需求中提取岗位骨架。

输入："帮我创建一个税务顾问智能体"

输出一张萃取表：

| 维度 | 萃取结果 |
|------|---------|
| 岗位 | 税务顾问 |
| 部门 | 专业服务 / 税务咨询 |
| 核心职责 | 税务筹划、合规咨询、风险评估 |
| 推荐 color | `#1A5276`（深海蓝，象征专业与权威） |

> 信息不足时，使用 [岗位型快速启动默认推导规则表](references/job-details.md) 自动填充。

### J2 模板填充

**目标**：将 J1 的骨架填入 12 模块模板，产出初版 SKILL.md。

关键模块包括身份与记忆五字段（角色/个性/价值观优先/记忆/经验）、核心使命与反使命、认知思考协议、职业判断模型等。每个字段都有推导规则——比如身份字段默认取 `{领域} + {职能} + {限定词}` 三要素拼接。

### J3 技法注入

**目标**：从 `references/job-details.md` 中注入领域技法，让角色从"能用"变为"专业"。

注入三层内容：

| 层 | 注入内容 | 来源 |
|----|---------|------|
| 硬规则 | DO/DON'T 按四组分类（合规/流程/质量/沟通） | 岗位 SOP + 行业规范 |
| 软技能 | 沟通风格 3 标签 + 拒绝方式 + 极限行为设计 | 行业语气基调查表 |
| 领域知识 | 知识库三层（核心/应用/扩展）+ 知识图谱 | 三步注入法 |

技法注入需要遵循三步法：
1. 识别领域知识类型（法规型 / 流程型 / 判断型）
2. 按岗位职责优先级注入（P0 > P1 > P2）
3. 验证可执行性（每条规则必须可操作、可判定、可验证）

### J4 质量内控

**目标**：在交付前进行五维度评估，不通过则回退修复。

| 维度 | 检查内容 | 门禁标准 |
|------|---------|---------|
| 身份清晰度 | 5 字段是否完整、是否有性格而非仅名称 | 全部非空 + 个性字段 ≥20 字 |
| 规则可执行性 | DO/DON'T 每条是否含触发场景 + 具体行为 + 理据 | 100% 通过 |
| KPI 可量化 | 是否 ≥3 条、每条含数字或可验证标准 | ≥3 条含数字 |
| 沟通独特性 | 3 标签是否可区分于其他岗位、拒绝方式是否自然 | 盲测通过 |
| 规则一致性 | DO 之间、DON'T 之间、DO vs DON'T 无冲突 | 矩阵检测零致命冲突 |

> J4 调用 `verify-skill.py` 执行自动化校验，退出码 0 才可进入 J5。

### J5 最终交付

**目标**：将完整的 SKILL.md 写入 `output/` 目录，并附质量报告。

完整示例见 [`examples/tax-advisor-example.md`](examples/tax-advisor-example.md)——从"帮我创建一个税务顾问"开始，完整展示 J1→J5 每一步的输入输出，最终产出 302 行带颜色标签的职业角色 SKILL.md。

## 人物蒸馏流水线：蒸馏 0 → 5

### 蒸馏 0：素材收集与分级

素材按可信度分为三级，权重不同：

| 级别 | 定义 | 权重 | 最低门槛 |
|------|------|------|---------|
| 一手素材 | 本人著作、访谈原话、公开发言录音转写 | 3 分 | ≥3 篇，含 1 篇 ≥3000 字长文 |
| 二手素材 | 他人转述、传记、分析评论 | 2 分 | ≥5 篇 |
| 推断素材 | 基于上下文逻辑推导 | 1 分 | 不可独立支撑任何心智模型 |

> 达不到深度蒸馏门槛 → 降级到标准／精简模式。连精简模式也达不到 → 标注"⚠️ 低信度原型"并交付。

### 蒸馏 1：心智模型提取（四重验证）

这是人物蒸馏的核心环节。每个候选心智模型必须通过四重验证：

| 验证 | 问题 | 不通过后果 |
|------|------|-----------|
| 跨域复现 | Ta 在写作、演讲、访谈等不同场景是否反复体现？ | 标记为"情境特例"，降级 |
| 生成力 | 这个模型能不能推导出新的具体行为？ | 标记为"事后归因"，移除 |
| 排他性 | 换成同领域的其他人，这个模型是否还成立？ | 标记为"行业共性"，移除 |
| 职业合规 | 是否符合该职业的基本规范？ | 一票否决 |

> **防 NPC 铁律**：职业规范是底线，不是特征。遵守职业道德 ≠ 心智模型。

### 蒸馏 2：表达 DNA 量化

对人物的语言风格进行七维度量化：

| 维度 | 示例 | 取值 |
|------|------|------|
| 句式偏好 | 短句为主 / 长句嵌套 / 混合 | 短句占比 80% |
| 语气停顿 | 高频使用"但是"转折 | 每 200 字 1 次 |
| 高频词汇 | 特有的概念词汇 | "涌现""基底" |
| 确定性风格 | 绝对 / 保留 / 反问 | 保留型 |
| 幽默方式 | 冷幽默 / 自嘲 / 无 | 冷幽默 |
| 情绪基线 | 冷静 / 热情 / 批判 | 冷静 |
| 默认姿态 | 建设者 / 解构者 / 观察者 | 建设者 |

### 蒸馏 3：决策启发式

基于心智模型推导出 5-10 条决策启发式，每条含场景映射——"当遇到 X 情况时，Ta 倾向于怎么做"。

### 蒸馏 4：质量自检

执行两套测试：

| 测试 | 方法 | 门禁 |
|------|------|------|
| 内容完整性清单 | 逐项检查 16 个必选章节 | 100% 覆盖 |
| Prompt 注入测试 | 用边界问题测试角色是否按预期回答 | 4 项全通过 |
| 盲测 | 删除名字后，能否仅凭表达 DNA 识别身份？ | 可通过 |

### 蒸馏 5：最终交付

产出一份完整的 SKILL.md，包含 YAML frontmatter（name/description/color）和全部 16 个章节。运行 `verify-persona.py` 验证，退出码 0 即交付。

## 质量体系全景

天工.skill 的质量保障不是事后补救，而是嵌入设计流程的 **三道防线**。

### 第一道防线：设计过程质量

由 [`references/quality-design-process.md`](references/quality-design-process.md) 定义：

- **反膨胀检查**：DO/DON'T 各 ≤10 条，工作流 ≤5 步，核心信息占比 ≥60%
- **规则冲突检测**：三模式完整矩阵（DO vs DON'T / DO vs DO / DON'T vs DON'T），分致命/严重/轻微三级
- **失败回退策略**：7 种场景各有"一线修复 → 仍失败兜底"的处理路径
- **迭代黄金法则**：能改一行不改一段，能改一段不改一页

### 第二道防线：验证测试体系

由 [`references/quality-verification.md`](references/quality-verification.md) 定义：

- **五场景回测**：阳光场景（正常输入）/ 边界场景（极限输入）/ 红线场景（违规测试）/ 长尾场景（罕见情况）/ 跨轮场景（多轮对话一致性）
  - 全部通过 → 交付；任一失败 → 回退修复后重新验证
- **五维度专家级验证**：功能性 / 认知交互 / 可信安全 / 业务价值 / 标准化评测
- **事实正确性一票否决**：0 捏造，0 幻觉

### 第三道防线：输出规范

由 [`references/quality-output-spec.md`](references/quality-output-spec.md) 定义：

- **五大设计原则**：鲜明性格 / 明确交付 / 可量化成功 / 验证工作流 / 持续记忆
- **踩坑清单**：6 组反例 → 正例对比
- **PR 提交模板**：结构完整性 3 项 + 行为可执行性 3 项 + 交付物质量 3 项 + 类型专项 2 项
- **输出格式变体**：5 种场景分别对应不同输出格式（完整交付 / prompt 文本块 / 评估报告等）

## 验证脚本

### verify-skill.py — 通用结构验证

```bash
python scripts/verify-skill.py [--skill path/to/SKILL.md] [--json] [--quiet]
```

**7 大维度**：

| 维度 | 内容 | 通过标准 |
|------|------|---------|
| YAML frontmatter | name / description / version / domain / author | 五字段齐全 |
| Gate 标记 | CHECKPOINT 分布与行号 | 3 个硬门禁全部存在 |
| H2 标题统计 | 蒸馏流程 / 设计模式 / 工具类标题 | 覆盖完整 |
| 规则冲突检测 | DO vs DON'T 语义交叉矩阵（关键词预筛 + 语义分析 + 冲突报告） | 零致命冲突 |
| 反模式索引 | 不触发条件（4 条）+ 蒸馏红线（5 条） | 全部可校验 |
| 引用文件校验 | 代码围栏配对 + H2 去重 + 最低 100 字符 | 全部通过 |

## 设计哲学

天工.skill 的名字来源于《天工开物》——"天工"指自然造物的精妙，"开物"指人类对规律的掌握与运用。天工.skill 追求的正是这种平衡：

- **结构，但不僵化**：模板提供骨架，但每个字段都鼓励个性化填充
- **验证，但不教条**：两套脚本是门禁不是镣铐，退出码之后还有人工判断的空间
- **范式，但不分裂**：两条路径共享同一套质量体系，且支持融合
- **反膨胀，但不停滞**：每一条规则都有存在的理由，任何不能证明自身价值的规则都可以被删除
