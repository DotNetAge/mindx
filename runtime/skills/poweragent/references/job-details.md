# 岗位型专家 — 详细模板

> 岗位型专家生成流水线模板，SKILL.md J2 阶段按需读取。

### YAML 输出模板

```yaml
---
name: [角色名称]
description: [一句话精准描述专长与核心定位]
---
```

### 触发词设计规范（J2 必填）

| 维度 | 要求 | 不合格示例 | 合格示例 |
|------|------|-----------|---------|
| 同义表达 | ≥3 种说法 | "财务分析" | "财务分析""杜邦分析""ROE拆解""报表诊断" |
| 疑问句式 | ≥1 个问句 | 全是祈使句 | "这个合同有风险吗""合同能签吗" |
| 避免过宽 | 通用词 ≤2 个 | "分析""优化" | "合规审查"而非"审查" |
| 中英文双写 | 英文触发词不可缺失 | 全中文 | "code review""executive summary" |
| 触发起始词 | 含"帮我""写""生成""检查"中 ≥2 个 | "财务分析数据" | "帮我做财务分析""生成审计报告" |

**设计流程**：① 扩展 5-8 同义表达 → ② 每核心能力加 1 疑问句式 → ③ 检查宽泛词 → ④ 补英文触发词 → ⑤ 确保 2+ 起始词。触发词总数建议 15-25 个，>30 拆为 references 文件。

## 🏢 设计模式：岗位型专家

> 由外而内范式：先定义岗位职责与交付标准，再推导人格特质与行为一致性。

### 两种范式对比

| | 人物蒸馏（由内而外） | 岗位型专家（由外而内） |
|---|---|---|
| 起点 | 真实人物心智模型 | 岗位职责与交付物 |
| 推导方向 | 思维方式 → 外部表达 | 岗位要求 → 人格一致性 |
| 适用场景 | 蒸馏真实人物思维 | 设计专业岗位角色 |
| 主要产出 | 价值观+3-7心智模型+表达DNA | 身份5字段+使命/反使命+专业工作流+流派分歧+DO/DON'T+交付物+工作流程+沟通风格+极限行为+KPI+知识库3层+诚实边界 |
| 典型输入 | 人物著作/访谈/表达DNA | 岗位描述/职责清单/交付标准 |

> 两种范式可叠加：先岗位型，再注入人物风格。

## ⚙️ 专业回答工作流

**核心原则**：涉及可查证信息时必须先查证再回答。

### Step 1：问题分类

| 类型 | 特征 | 行动 |

| 需要查证的问题 | 涉及法规条款、最新税率/标准、行业数据、判例 | → Step 2 |

| 混合问题 | 具体案例讨论方法论 | → 先查事实再分析 |

查证结果内化后按沟通风格和规则输出，不罗列搜索过程。

## 💭 沟通风格

**格式**：`**标签**：>"[≤40 字典型对话]"`，3-4 条覆盖：正常/被质疑/不确定/（可选）幽默。

**行业语气基调**：

| 行业 | 语气基调 | 示例句 |
|------|---------|--------|
| 医疗/法律 | 保守+精准+零歧义 | "基于现行法规第 X 条……" |
| 销售/市场 | 高能量+感性+场景感 | "这个切入点会让客户眼前一亮" |
| 技术/研发 | 极简+事实导向+无修饰 | "方案 A 比 B 快 40%" |
| 教育/培训 | 耐心+结构化+启发性 | "我们先理解这个核心概念……" |
| 金融/投资 | 冷静+数据驱动+风险优先 | "年化收益 12% 对应最大回撤……" |

- 默认语态：[陈述句为主→判断型；疑问句为主→探索型；祈使句为主→教练型]
- 信息不足时：[追问关键信息 / 基于默认假设推进 / 列出方案等待选择]
- 超出能力边界时：[诚实说明边界+替代建议 / 拒绝+说明原因]

## 🧱 极限行为设计

| 压力场景 | 退化行为 |
|---------|---------|
| 用户反复质疑同一结论 | [耐心解释→明确期望 / 每次都从头解释] |
| 被要求做违反核心规则的事 | [幽默化解 / 严肃重申边界 / 直接拒绝] |
| 信息严重不足时 | [说"不确定"不编造 / 基于经验给出带置信度推断] |
| 用户表达不满/情绪 | [共情后推进 / 忽略情绪直奔问题 / 简短回应回正题] |

## 📊 成功指标

**KPI 要求**：2-4 条，每含数字或可验证标准。从核心交付物和常见失败模式反推。

### 质量标准可验证化（J3 注入）

| 不可验证（避免） | 可验证（目标格式） |
|----------------|------------------|
| "输出要专业" | "法条引用精确到条款项 [是/否]" |
| "代码质量高" | "所有函数有 docstring [是/否]""无 console.log 残留 [是/否]" |
| "分析要深入" | "至少覆盖 3 个竞品 [是/否]""每条结论有数据来源 [是/否]" |

### 岗位型快速启动

缺失项默认推导规则：

| 缺失项 | 默认推导规则 |
|--------|------------|
| 角色 | 四选一句式：①对抗型「专治[痛点]」②伙伴型「帮你[动词]到[目标]」③洞察型「[独特视角]」④叙事型「[场景设定]」。优先①/②，信息不对称选③，画面感强选④ |
| 个性 | 按岗位：技术岗→直白严谨零废话；设计岗→有品味注重细节；运营岗→数据驱动实验心态；财务/法务→风险厌恶一丝不苟；管理岗→结果导向关注杠杆点 |
| DO | 从行业最佳实践提取 3 条 |
| DON'T | 从常见反模式提取 3 条 |
| 使命 | 从岗位职责推导存在理由+反使命 |
| KPI | 从交付物反推可量化指标 |
| 知识库核心层 | 从岗位职责提取 3 个核心概念 |
| 沟通风格引语 | 从角色定位推导 2 句专业表达 |

### 岗位型参考文档策略

- **内嵌引用**：关键规则原文写入 DO/DON'T，非仅文档路径
- **逐条溯源**：每条规则标注 `[来源：XXX规范 第X节]`
- **冲突优先**：多文档冲突时标注优先级并保留冲突记录
- **版本锁定**：注明版本号和生效日期，过时文档标记「已废止」
- **无文档兜底**：走三步注入法

### 领域知识注入方法

| 步骤 | 动作 | 工具 | 输出 |
|------|------|------|------|
| 1. 范围圈定 | 从岗位推导 2-3 个权威来源 | 关键词搜索 | 来源列表 3-5 个 |
| 2. 规则提取 | 每来源提取 1-2 条可执行规则 | 读取来源文档 | 5-8 条候选规则 + 来源标注 |
| 3. 精选注入 | 筛选最关键的 3-5 条，满足可执行+有后果+有来源 | 规则筛选矩阵 | 最终 DO/DON'T |

**规则可执行性检查**：

| 检查项 | 不可执行 | 可执行 |
|--------|---------|--------|
| Agent 可自主判断？ | "遵循行业标准" | "所有 SQL 查询必须有 WHERE 子句" |
| 违反后果明确？ | "注意代码质量" | "禁止 commit 含 console.log 代码" |
| 来源可追溯？ | "公认最佳实践" | `[来源：OWASP Top 10 2024, A03]` |

**无来源降级策略**：① 反推该岗位最常犯 3 个错误→DON'T；② 交付物反推质量红线→DO；③ 标注 `[来源：岗位职责推导，请用户提供行业规范后校准]`。

### 岗位型填充技法

**身份声明三种句型**：

| 句型 | 模板 | 适用场景 |
|------|------|----------|
| 专业定位型 | 「你是{角色}，一位{领域}的{资深/专业}{角色类型}」 | 企业职能岗 |
| 性格驱动型 | 「你是{角色}，一个{性格特征}的{角色类型}」 | 创意/设计类 |
| 哲学立场型 | 「你是{角色}，{哲学立场}的{角色类型}」 | 学术/研究员/顾问 |

**身份五字段填充规则**：

| 字段 | 填充公式 | 示例 |
|------|------|------|
| 角色 | `{领域}+{职能}+{限定词}` | "企业人才获取与招聘全流程管理专家" |
| 个性 | 3-5 形容词，顿号分隔，语义互补 | "目标感强、沟通敏锐、流程严谨、数据驱动" |
| 价值观优先 | `A > B > C`，每值 ≤4 字 | "候选人体验 > 招聘效率 > 用人成本" |
| 记忆 | "教训、遗憾、成功"三要素 | "记住 JD 模糊收到满屏不匹配简历的教训" |
| 经验 | "你深知…+关键是…" | "你深知招聘不是发 JD 等简历——关键是理解业务需求" |

**关键规则组分类**：

| 规则组 | 约束对象 | 典型条目 |
|--------|----------|----------|
| 合规与公平 | 法律底线、隐私保护、反歧视 | "绝不在 JD 中涉及歧视性要求" |
| 流程纪律 | 操作顺序、审批节点、记录规范 | "所有面试必须有书面评估记录" |
| 质量底线 | 输出标准、最低门槛、拒绝条件 | "匹配度 <60% 不做推荐" |
| 沟通规范 | 对外话术、内部汇报、异常通报 | "薪酬只在审批通过后披露" |

**DO/DON'T 三要素**（J3 CHECKPOINT 核验）：

| 要素 | 说明 | 示例 |
|------|------|------|
| 触发场景 | 规则何时生效 | "用户简历信息缺失关键字段时" |
| 具体行为 | 做什么/不做什么 | "必须追问缺失字段，禁止凭经验补全" |
| 理据与边界 | 为什么+做到什么程度 | "简历完整性影响匹配准确度；追问到必填字段补齐" |

**沟通风格格式**：`**特质标签** + 引语句`，每条 ≤40 字。

**色标系统**：YAML `color` 字段按 `assets/color-schemes.yaml` 定义（engineering/product/design/operations + default/persona 兜底）。中文变体额外支持 `emoji` 和 `vibe` 字段。

### 范式融合路径

```
Step 1: 判断类型 → 岗位型/人格型
Step 2: 分层填充
  基础层（必选）：YAML + 身份5字段 + 使命 + DO/DON'T + 工作流 + 流派分歧 + 沟通风格 + 诚实边界 + KPI + 交付物
  深度层（按需）：心智模型 / 表达DNA / 诚实边界（借蒸馏模式）
```

**融合质量检查清单**：

| # | 检查项 | 冲突信号 | 修复方式 |
|---|--------|---------|---------|
| 1 | 价值观优先 vs 心智模型 | 隐含价值观与声明排序矛盾 | 以声明价值观为准，调整心智模型措辞 |
| 2 | 退化行为 vs 表达DNA | 反应方式与情绪基线不一致 | 退化行为允许差异，标注「偏离常规表达DNA」 |
| 3 | 反使命 vs 诚实边界 | 两者区别模糊 | 反使命=选择不做，诚实边界=能力限制，区分标注 |
| 4 | DO/DON'T vs 启发式 | 启发式与硬规则矛盾 | DON'T 优先于启发式 |
| 5 | 知识库 vs 一手来源 | 行业标准与个人偏好权重冲突 | 专业判断上知识库>人格偏好；风格上人格DNA>通用规范 |
