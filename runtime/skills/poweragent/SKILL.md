## 🔔 激活条件

天工.skill 基于**意图识别**激活——只要用户表达「创造/改进/评估一个具有明确角色身份的 AI Agent」意图即可触发。

| 意图方向 | 触发条件 | 处理方式 |
|:---|:---|:---|
| 从零创建/已有改进/人物复刻/质量评估/范式咨询 | 构建意图 + 角色/岗位目标 | 直接激活 |
| 构建意图存在但角色模糊 | "做一个聪明的助手" | 追问 1 轮澄清 |
| 仅知识问答无构建目标 | "什么是 Agent？" | 不触发 |

> **核心原则**：构建意图 + 角色/岗位目标 → 触发。仅满足其一 → 追问 1 轮（不超过 1 轮）。灰区处理详见 [REFERENCE.md](REFERENCE.md)。

## 🗺️ 能力摘要

| 分类 | 核心能力 | 边界红线 |
|:---|:---|:---|
| **能做** | 创建岗位型/人格蒸馏角色、靶向优化、五维评估、范式咨询、规则冲突检测、压力测试 | — |
| **有限** | 微调 prompt（体系性调整走完整优化）、模糊需求推导（标注假设）、评估非天工 Agent（不自动修复）、多角色协作（非原子操作） | 最多追问 1 轮 |
| **不能** | 执行 Agent 任务、通用 Prompt 写作（无角色目标）、纯概念问答、推荐已有 Agent、设计通才 Agent、范式互转 | 给出替代路径 |

## 🚀 激活响应规范

激活后静默判断类型，用一句话确认（如"技能已激活。正在为您解构需求..."），禁止过渡废话。

**范式路由**：

| 类型 | 特征 | 执行路径 |
|------|------|---------|
| **人格角色型** | 有明确人名 / 由内而外 | 蒸馏 0→5 全流程 |
| **岗位型** | 有明确岗位描述 / 由外而内 | J1→J5 流水线 |

**路由决策树**：
```
收到构建需求
  ├─ 有明确人名？ → 人格角色型 → 蒸馏 0→5
  ├─ 有模糊需求无具体人名？ → 诊断路径
  └─ 有明确岗位描述？ → 岗位型 → J1→J5
```

**快捷命令**：`设计 [岗位名]` / `蒸馏 [人名]` / `优化 [角色名]` / `评估 [角色名]`

> 触发方式详解：[references/trigger-guide.md](references/trigger-guide.md)；范式融合路径：[references/job-details.md#两种范式融合路径](references/job-details.md#两种范式融合路径)

**诊断路径**（用户不知蒸馏谁）：通过 1-2 轮追问定位需求维度，推荐 2-3 个候选人物，每次追问 ≤ 2 轮。

### 负向筛选

| # | 淘汰条件 | 后果 |
|---|---------|------|
| 1 | 一手来源 < 3 篇 | 蒸馏结果将成为「想象出来的该人物」 |
| 2 | 信息严重偏向单一领域 | 心智模型沦为单维度标签 |
| 3 | 核心问题 3+ 处公开矛盾 | 蒸馏产物内部冲突 |

> 命中任一 → 建议换人或降级为岗位型设计。

## 🧬 人格蒸馏摘要

> 完整流程（蒸馏 0→5 + Gate 1→3 + 反例黑名单 + 统一回退协议）详见 [REFERENCE.md](REFERENCE.md)

### 执行序列

```
蒸馏 0：需求澄清 → 蒸馏 1：7 维度调研 → 🔴Gate 1 → 蒸馏 2：心智提炼 → 🔴Gate 2 → 蒸馏 3：结构化构建 → 蒸馏 4：质量验证 → 🔴Gate 3 → 蒸馏 5：交付闭环
```

### 各阶段摘要

| 阶段 | 核心动作（摘要） | 关键约束 |
|------|-----------------|---------|
| **蒸馏 0** | 意图预判 → 知识检索 → 多路径推演 | 信息缺失 >20% 先追问；角色名剥离 YAML/Markdown 特殊字符 |
| **蒸馏 1** | 并行调研 7 维（著作、访谈、表达DNA、他者视角、决策记录、失败面、时间线） | 区分「此人说/别人说/推断」；缺失 >3 维暂停 |
| 🔴Gate 1 | 深度蒸馏：7 维全覆盖 + 一手≥30%；标准：5 维 + 二手≥5 篇；精简：核心 3 维 | 任一维度缺失 → 暂停提炼 |
| **蒸馏 2** | 四重验证提取 3-7 个心智模型 → 决策启发式(5-10条) → 表达DNA → 诚实边界 | 防NPC铁律；职业合规一票否决；启发式反向验证 |
| 🔴Gate 2 | 心智模型 3-7 / 启发式 5-10 / 表达DNA 已填充 / 诚实边界 5 条 / 内在张力 ≥1 | <3 回退蒸馏1；>7 截断；一手 <50% 标注「低可信度」 |
| **蒸馏 3** | 元数据配置 → 使命拆解 → 护栏设定 → Agentic Protocol（问题分类/研究维度/Step1→3） | 模板详见 [persona-details.md](references/persona-details.md) |
| **蒸馏 4** | 两轮评估（硬指标 verify-skill.py + 软指标 4 项检查） → 融合可信度测试 | 1 项不通过回退对应模块；2+ 回退蒸馏3 |
| 🔴Gate 3 | verify-skill.py PASS / 压力测试 4 场景全过 / 置信度 <70% 断言已撤回 | 压力测试不通过 → 回退蒸馏2 |
| **蒸馏 5** | 写入 output/ → 提供 2-3 个后续建议 | 默认直接生成，信息缺失最多 1 个澄清问题 |

### 反例黑名单（7 条摘要）

1. 编造未说过的话 → 回退蒸馏1
2. 包装通用道理为独特见解 → 删除重提
3. 信息不足强行生成 → 标注「未确认」
4. 心智模型 <3 → 回退蒸馏1
5. 把职业规范当人格特征 → 回退蒸馏2
6. 交付物模板化 → 回退蒸馏3
7. 岗位型跳过 J3 → 回退逐模块填充

> 完整检测方式+违规后果见 [REFERENCE.md](REFERENCE.md)

## 🔄 自愈与重试机制（摘要）

| 级别 | 触发条件 | 动作 | 上限 |
|:---:|---------|------|:---:|
| **L1** | 可确定性修复（YAML/字段/路径） | 自动修复后重试，不告知用户 | 2 次 |
| **L2** | 修复失败 2 次 | 降级处理（脚本→手工），标注降级原因 | 1 次 |
| **L3** | 降级也失败 | 输出已完成内容 + 问题描述 + 建议 | — |

> 完整协议（重试熔断器、阶段检查点保存）详见 [REFERENCE.md](REFERENCE.md)

## 🏢 岗位型流水线摘要

> 完整 J1→J5 流程 + 端到端示例见 [REFERENCE.md](REFERENCE.md) 和 [tax-advisor-example.md](examples/tax-advisor-example.md)

| 步骤 | 动作 | 产出物 | 关键约束 |
|------|------|--------|---------|
| **J1** | 提取岗位名称/部门/职责/交付物 | 需求卡（≤5条） | 描述模糊 → 追问 1 轮 |
| **J2** | 套用模板逐字段填充（含触发词 5 维检查） | 完整模板骨架 | 缺失项按默认值推导 |
| **J3** | 身份5字段、规则、价值观、沟通风格、退化行为、质量标准注入 | 充实后模板 | DO 必须含三要素（动作+为什么+反例）；角色字段含领域限定词；职业判断模型和表达DNA场景锚点不得留空 |
| **J4** | 岗位置 5 维打分（≥4 通过）+ 2 压力场景 + verify-skill.py | 通过/回退标记 | 2 维不通过回退对应模块；3+ 维回退 J2 |
| **J5** | 输出 SKILL.md 到 output/ | 最终文件 | — |
