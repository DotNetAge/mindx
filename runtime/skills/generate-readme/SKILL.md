# 生成 README

## README 的目的

让人与 Agent **看完即知这个目录是关于什么方面、有些什么内容**。写任何内容前先过两问：关于什么（frontmatter 的 `abstract`）、有什么（正文的「目录内容」清单）。与这两问无关的内容不加。

## README 元数据约定（frontmatter）

README.md 头部携带强类型 frontmatter（机读事实），正文保持纯 Markdown：

```yaml
---
name: <项目名>       # 缺省用根目录名
logo: <路径或 URL>   # 可选
type: <项目形态>     # 应用 / 库 / 频道 / 作品集 / 品牌 / 产品 等，取最贴切的一个名词
abstract: <一句话摘要>
---
```

四项为标准集，缺一要补；允许追加自定义字段（`tags`、`homepage` 等）。

## 核心守卫：frontmatter 是第一交付物

生成前**必须**检查项目根目录是否已有 README（`README.md`、`readme.md`、`README.*` 均算）：

| 情况                      | 动作                                         |
| ------------------------- | -------------------------------------------- |
| 无 README                 | 整体生成（frontmatter + 正文）               |
| 有 README、无 frontmatter | 文件头部插入 frontmatter，正文一字不动       |
| 有 README、有 frontmatter | 逐字段核对：缺失则补、过时则改，正文一字不动 |

已有 README 不是不做事——更新 frontmatter 是最重要的交付；仅当四字段完整且与扫描证据一致时才告知"无需更新"。

## 第一步：扫描收集

以仓库证据为准，按优先级取值：

| 信息     | 来源                                                                  |
| -------- | --------------------------------------------------------------------- |
| name     | 身份文件（包管理 `name` / 清单或简介文档标题）→ 根目录名              |
| logo     | 仓库内图像（`assets/`、`docs/`、`.github/`、封面图）→ 用户指定 → 缺省 |
| type     | 按目录内容判断形态，取最贴切的名词                                    |
| abstract | 身份文件描述字段 → 简介文档首段 → 用户口述                            |
| 目录内容 | **顶层目录与关键文件逐个过**：每个是什么、放什么——这是正文主体素材    |

摘要与说明必须来自真实证据或用户口述，禁止编造。

## 第二步：缺项提问

仍缺的关键字段逐项问，先给假设选项，一次只问一个缺口；有依据的项直接采用。

> 我判断这个目录是 <形态>，摘要写"<假设>"对吗？按此生成 / 换一种说法。

## 第三步：生成或更新

### 无 README：整体生成

```markdown
---
name: <项目名>
logo: <Logo 路径或 URL>
type: <项目形态>
abstract: <一句话摘要>
---

# <项目名>

<p align="center">
  <img src="<logo>" alt="<项目名> logo" width="120">
</p>

> <一句话摘要>

## 目录内容

- <目录或文件> — <一句话说明它是什么>
- ...

<可选段落：软件加安装与使用；创作加作品与联系方式；商业加产品与联系>
```

- 「目录内容」是主体，每个条目一句话说清是什么；深层目录只列到能看懂结构为止
- 无 Logo 省略 `logo` 字段与 Logo 段；命令只写扫描到的真实命令

### 已有 README：只动 frontmatter

- 在头部 `---` 区块内精确插入或更新字段，禁止触碰正文：不重排、不改写、不顺手美化
- 字段值必须来自扫描证据或用户确认
- 完成后 diff 自查：正文零变化、四字段与证据一致

## 样式规则

- 平实语言，面向所有人而非仅技术用户；条目说明一句话，不堆术语。
- 层级不超过三级；先摘要后细节。
- 生成或更新后通读自查：frontmatter 与证据一致、无编造、无占位残留。
