# 落地页生成器

根据产品/服务需求简报，生成完整的、以转化为导向的落地页原型。默认交付方式是使用 Agent 的 Web 应用构建能力（`app_builder`、`create_html`、WebPage 或等价能力）产出一个经过验证的在线页面。仅当用户明确要求 HTML 文件/源码、离线单文件 HTML 或本地文件路径时，才创建本地 HTML/CSS 文件。只有在真实的集成、内容、可访问性、安全性、数据统计与目标环境全部验证通过后，才能将产出称为「可上线（production-ready）」。

## 用法

```
/landing-page-generator "面向远程团队的项目管理 SaaS，$29/月，免费试用"
/landing-page-generator brief.txt
/landing-page-generator "自由职业网页开发者作品集 —— 预约通话 CTA"
```

尽可能提供充分的上下文：
- 产品/服务是什么
- 目标受众
- 主要 CTA（注册、购买、预约通话、下载）
- 定价（如适用）
- 关键功能/收益点
- 品牌色（可选，默认使用专业的蓝色/深色主题）

## 页面生成流程

### 第 1 步：分析需求简报

提取以下信息：
- **产品类型**：SaaS、实体商品、服务、作品集、引流资料（lead magnet）、活动
- **目标受众**：页面给谁看？
- **主要 CTA**：希望访客采取什么行动？
- **价值主张**：他们为什么要在意？
- **语气风格**：专业、轻松、大胆、极简、奢华

### 第 2 步：选择页面模板

根据产品类型选择：

| 类型     | 包含版块                                       | 典型篇幅 |
| -------- | ---------------------------------------------- | -------- |
| SaaS     | Hero、功能、工作原理、定价、客户评价、FAQ、CTA | 长       |
| 服务     | Hero、服务、流程、作品集、客户评价、CTA        | 中       |
| 作品集   | Hero、作品展示、关于、服务、联系方式           | 中       |
| 引流资料 | Hero、收益点、社会证明、表单、CTA              | 短       |
| 电商     | Hero、产品功能、图库、评价、购买 CTA           | 中       |
| 活动     | Hero、嘉宾/详情、日程、购票、FAQ               | 中       |

### 第 3 步：生成页面

为 Agent 的 Web 应用构建能力准备完整的页面规格说明。交付的页面必须移动端自适应、以转化为导向，并可通过经过验证的在线 URL 访问。

如果用户明确要求 HTML 文件/源码、离线单文件 HTML 或本地文件路径，则创建内嵌 CSS 的单个自包含 HTML 文件。除 Google Fonts 外不允许任何外部依赖。

**必需版块**（按产品类型调整）：

#### Hero 区
```
- 主标题：清晰的价值主张（不超过 10 个词）
- 副标题：辅助说明（不超过 25 个词）
- CTA 按钮：高对比、行动导向的文案（「免费开始试用」，而非「提交」）
- 可选：Hero 图片占位或背景
- 可选：用户提供的、经核实的社会证明徽章；否则省略，或以醒目方式标注为占位文案
```

#### 功能/收益点
```
- 3-4 张功能卡片，带图标（使用 Unicode/emoji 图标）
- 每张卡片：图标 + 功能名 + 1-2 句收益描述（聚焦结果，而非功能本身）
- 网格布局：桌面端 3 列，移动端 1 列
```

#### 社会证明
```
- 仅当用户提供可归属、经核实的评价时，才放 2-3 张评价卡片；否则省略该版块，或使用带醒目标注的占位内容，确保不会被误认为真实背书：
  - 评价正文
  - 姓名与职务/公司
  - 星级评分（如适用）
- 可选：客户/合作伙伴 Logo 墙（带公司名称的占位框）
```

#### 工作原理（如适用）
```
- 3 步流程，带编号
- 步骤标题 + 简要描述
- 步骤之间的视觉连接线
```

#### 定价（如适用）
```
- 1-3 个定价档位，卡片形式
- 高亮推荐档位
- 功能对比清单
- 每个档位配 CTA 按钮
```

#### FAQ
```
- 4-6 个常见问题
- 手风琴式（点击展开），用纯 CSS/HTML 的 <details> 实现
```

#### 尾部 CTA
```
- 重复主要 CTA，制造紧迫感
- 与 Hero 区不同角度（化解剩余顾虑）
- 强对比背景
```

### 第 4 步：设计系统

应用以下设计原则：

**字体排版**：
- 字体：Google Fonts 的 `Inter`（干净、现代、高可读性）
- 标题字号阶梯：3rem、2rem、1.5rem、1.25rem
- 正文：1rem / 1.6 行高
- 最大行宽：65ch，保证可读性

**配色**（默认值，如用户提供品牌色则覆盖）：
```css
--primary: #2563eb;        /* 蓝色 - CTA 与链接 */
--primary-dark: #1d4ed8;   /* 悬停态 */
--bg: #ffffff;             /* 背景 */
--bg-alt: #f8fafc;         /* 交替版块背景 */
--text: #1e293b;           /* 正文文字 */
--text-light: #64748b;     /* 次要文字 */
--accent: #f59e0b;         /* 高亮、徽章 */
```

**布局**：
- 最大宽度：1200px，居中
- 版块内边距：垂直 80px（移动端 48px）
- 统一的间距阶梯：4、8、16、24、32、48、64、80px

**响应式断点**：
- 桌面端：1024px 以上
- 平板：768px - 1023px
- 移动端：< 768px

### 第 5 步：转化优化

对生成的页面应用以下转化原则：

1. **首屏**：无需滚动即可看到主标题 + CTA
2. **单一 CTA 聚焦**：一个主要动作，全页重复 2-3 次
3. **对比度**：CTA 按钮必须满足 WCAG AA（至少 4.5:1）
4. **加载速度**：无外部 JS、CSS 精简、无图片（仅占位）
5. **可扫读性**：用户 5 秒内能看懂提供的是什么
6. **顾虑化解**：FAQ 与客户评价回应常见疑虑
7. **紧迫感/稀缺性**：可选 —— 仅在真实时使用（「内测名额有限」，而非虚假倒计时）

### 证据与安全门槛

1. 不得编造客户数量、客户评价、Logo、评分、价格、资质认证、基准测试结果、转化提升数据、部署日志或用户验证结论。
2. 将模拟数据、示例人物、评分权重、阈值、预测数据和占位文案标注为未经校验的演示假设。
3. 区分本地文件、静态演示、测试部署与生产系统。生成的文件或可访问的 URL 不能证明表单、认证、数据持久化、数据统计、支付或合规能力真实可用。
4. 在发布、接入真实数据、发送通知、收款或改动外部系统之前，说明目标、范围、所需权限、回滚与验证方案，并取得明确授权。
5. 用于招聘、医疗、法律、金融、投资或其他重大决策场景时，页面及任何内嵌评分流程仅限信息展示或决策辅助用途；必须由可问责的人工与适用的专业审查把关。

### 第 6 步：输出

默认输出：

- 使用 Agent 的 Web 应用构建能力（`app_builder`、`create_html`、WebPage 或等价能力）。
- 在确认页面可打开、主 CTA 可见、FAQ 交互正常、移动端宽度无横向溢出后，返回经过验证的在线页面 URL。
- 除非用户明确要求该格式，否则不要以本地源码、ZIP 或文件路径作为最终交付物。

仅当用户明确要求本地 HTML 文件时，才保存到 `output/landing-page/`：

```
output/landing-page/
  index.html          # 完整的自包含页面
  README.md           # 给客户的自定义指南
```

**`README.md`** 包含：
- 如何自定义配色（文件顶部的 CSS 变量）
- 如何替换占位内容
- 如何添加真实图片
- 如何把表单接入客户的邮件服务
- 如何部署（Netlify 拖拽部署、GitHub Pages、任意静态托管）

### 第 7 步：向用户展示

展示以下内容：
1. 生成结果的简要总结
2. 关键设计决策
3. 经过验证的在线页面 URL；仅当用户明确要求本地 HTML 文件时，才给出本地文件路径
4. 给客户的自定义建议（图片、客户评价、具体文案）
5. 确切的状态：实际生成并验证了什么、哪些仍是占位或未经验证、以及是否未进行任何部署

## 质量标准

- [ ] 在线页面 URL 可成功打开；若用户明确要求本地 HTML，则文件可打开且除 Google Fonts 外无外部依赖
- [ ] 在 320px、768px、1200px 宽度下完全响应式
- [ ] 所有 CTA 按钮有悬停态
- [ ] 颜色对比度满足 WCAG AA
- [ ] 页面有正确的 `<meta>` viewport 标签
- [ ] 语义化结构（`<header>`、`<main>`、`<section>`、`<footer>`）在生成的页面或本地 HTML 中体现
- [ ] 任何断点下均无横向滚动
- [ ] FAQ 版块可交互（展开/收起）
- [ ] 用户明确要求本地 HTML 时，文件体积小于 50KB
