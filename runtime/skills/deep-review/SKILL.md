## 何时使用

- 用户要求"复盘项目、总结经验、沉淀规则"
- 周期性收尾节点（如每日/每周结束时）主动询问用户是否复盘
- notes 或会话经验积累到需要归并提炼时（多条踩坑指向同一根因、多个技能出现同类缺陷）

## 主题澄清（动手前必做）

用户未指明复盘对象或范围时，禁止自行猜测。先用 AskUser 提供 2-4 个假设选项让用户选择，用户不选再开放提问：

- **复盘对象不明**（"复盘一下"未指明项目）→ 列出候选：当前会话项目 / 最近活跃项目（`mindx project list` 结果）/ 用户口述的其他项目。
- **范围不明** → 列出候选：只复盘本项目 / 全项目盘点 / 只做某一路分析（公共规则 / 技能沉淀 / 技能优化 / 招募提议 / 日报）。
- **深度不明** → 列出候选：快速复盘 / 完整五路分析。

每项给具体选项 + "其他（自由输入）"兜底。对象与范围明确后进入工作流。

## 第一步：采集输入

进入工作流前先 `TaskCreate` 建立任务清单（采集 → 五路分析（A-E 各一项）→ 汇报，含每步产出），推进中用 `TaskUpdate` 标记完成状态，中断恢复时用 `TaskList`/`TaskGet` 读取进度，不凭回忆对齐工作点。

依次读取以下载体，全部为空时如实告知并终止：

1. **notes**：`<项目目录>/.agents/notes/` 全量踩坑记录（无上次复盘时间记录时读全量）；
2. **skills 清单**：`<项目目录>/.agents/skills/` 各技能的 SKILL.md（frontmatter：name/version/description）；
3. **长期记忆**：读取 `<项目目录>/.agents/memory/` 下本 Agent 与相关 Agent 的记忆文件（文件名四元组：记录时间-agent名-分类-标题，先按分类粗筛再按需读取正文）。围绕项目名与近期任务主题挑选相关条目；
4. **Agent 信息**：多 Agent 协作复盘时用 `mindx agent list` 查看成员角色供分派；单人会话以当前 Agent 身份执行。

## 第二步：五路分析

### A. 公共规则发现（产出：AGENTS.md 修订提议）

从 notes 与记忆中找重复出现的模式，归纳为三类条目：该做的事 / 不该做的事 / 注意事项与踩坑经验。

- 只提炼"跨会话重复 ≥2 次"的模式，偶发事件不入选——防止把偶发路径固化成错误经验；
- 产出为修订提议清单（新增哪条、修改哪条、依据是什么），**必须逐条询问用户，用户授权后路由 generate-agents-md 技能按其规范执行写入**——本技能不直接改写 AGENTS.md，保证格式与既有结构一致（分层归位、@片段、token 纪律）；
- 被拒绝的提议不落盘，仅在日报中记录"已提议、用户未采纳"。

### B. 可复用技能沉淀（产出：新技能提议）

当某类操作满足"步骤固定 + 跨会话重复 + 可独立描述"时提议技能化：

- 写入 `<项目目录>/.agents/skills/<skill-name>/SKILL.md`，格式对齐现有技能（frontmatter：name/version/description + 指令正文，注释用中文）；
- 技能名：小写字母/数字/连字符，≤64 字符（与 mindx skillstore 校验规则一致）；
- 提议时给出：技能名、一句话 description、大纲。**用户确认后才写入**。

### C. 技能优化检查（产出：修订提议）

对照 A 路发现的踩坑逐个检查现有技能：

- 某技能正是踩坑根源（流程缺陷、判据缺失、格式过时）→ 只产出修订提议（写入 `.agents/notes/`，按缺口词汇表分类），**不直接修改技能文件**——修订由技能进化流程（skill-creator 技能）执行，单写者原则；
- 提议内容包含：技能名、问题定位、修订方向、建议版本号（结构或流程变更 x.0 +1；内容修正 x.y +1）。

### E. 角色化经验检查（产出：招募提议）

检查素材中是否存在"角色级缺口"——某领域工作反复出现，但现有 Agent 概览覆盖不到、技能也承载不了。三个条件同时满足才提议招募新 Agent：

- **技能承载不了**：缺的不是操作指令（那是 B 路技能化的事），而是独立的职责边界——需要 SOUL 的职责门控、价值观排序与两层边界来约束行为；
- **跨任务反复**：同类专家需求在 ≥2 次独立任务中出现（单次需求走 agent-creator 的用户显式触发，不经本路）；
- **边界可辨**：设想中的角色与现有 Agent 概览并排可区分（对照 agent-creator 概览选择验证标准）。

满足则产出招募提议：角色名、领域、职责概述、建议携带技能。**用户裁决后路由 agent-creator 技能执行招募**——本技能不直接创建 Agent。三条件缺一即不出提议，"技能够用却创建智能体"是 agent-creator 明列的反模式。

### D. 日报落盘

调用 `daily-report` 技能，将本次复盘的目标、事项、结果、状态、下一步建议生成为报告。

## 第三步：汇报

向用户汇报五路结论的落盘情况：哪些已写入（含路径）、哪些待定、哪些被拒绝。不重复报告内容细节（报告里已有）。

## 硬约束

- 一切写入 skills/ 的操作必须先获用户授权，禁止静默沉淀；存量技能的修订与 AGENTS.md 的改写不在本技能直接执行——技能修订路由 skill-creator，AGENTS.md 修订经用户授权后路由 generate-agents-md；Agent 的招募提议经用户裁决后路由 agent-creator 执行，本技能不直接创建 Agent；
- 禁止时间估计；
- notes 只读不删：已转化为规则/技能的踩坑记录保留原文件，防止溯源断链；
- 记忆文件缺失不是阻塞项：跳过并在日报中注明，用 notes 与 skills 完成复盘。
