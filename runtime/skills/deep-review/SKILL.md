## 何时使用

- 用户要求"复盘项目、总结经验、沉淀规则"
- 周期性收尾节点（如每日/每周结束时）主动询问用户是否复盘
- notes 或会话经验积累到需要归并提炼时（多条踩坑指向同一根因、多个技能出现同类缺陷）

## 第一步：采集输入

依次读取以下载体，全部为空时如实告知并终止：

1. **notes**：`<项目目录>/.agents/notes/` 全量踩坑记录（无上次复盘时间记录时读全量）；
2. **skills 清单**：`<项目目录>/.agents/skills/` 各技能的 SKILL.md（frontmatter：name/version/description）；
3. **长期记忆（回忆）**：调用 `MemorySearch` 工具（goharness 回忆工具）。参数：`query`（必填，语义查询，多主题用逗号分隔，如"技能沉淀,复盘"；至少 2 个字符）、`limit`（默认 5，最大 20，复盘建议传 20）、`project_dir`（可选，默认当前项目目录）。围绕项目名与近期任务主题做 3~5 组关键词查询；
4. **Agent 信息**：调用 `TeamList` 工具（无参数）列出当前会话的团队及成员状态，供 Leader 汇总分派；会话无团队时以当前 Agent 身份执行单人复盘，身份不明时询问用户。

## 第二步：四路分析

### A. 公共规则发现（产出：AGENTS.md 修订提议）

从 notes 与记忆中找重复出现的模式，归纳为三类条目：该做的事 / 不该做的事 / 注意事项与踩坑经验。

- 只提炼"跨会话重复 ≥2 次"的模式，偶发事件不入选（防把偶发路径固化成错误经验，与 PR-SELF-EVOLUTION 的开放问题 3 对齐）；
- 产出为修订提议清单（新增哪条、修改哪条、依据是什么），**必须逐条询问用户，用户授权后才写入 AGENTS.md**；
- 被拒绝的提议不落盘，仅在日报中记录"已提议、用户未采纳"。

### B. 可复用技能沉淀（产出：新技能提议）

当某类操作满足"步骤固定 + 跨会话重复 + 可独立描述"时提议技能化：

- 写入 `<项目目录>/.agents/skills/<skill-name>/SKILL.md`，格式对齐现有技能（frontmatter：name/version/description + 指令正文，注释用中文）；
- 技能名：小写字母/数字/连字符，≤64 字符（与 mindx skillstore 校验规则一致）；
- 提议时给出：技能名、一句话 description、大纲。**用户确认后才写入**。

### C. 技能优化检查（产出：技能更新）

对照 A 路发现的踩坑逐个检查现有技能：

- 某技能正是踩坑根源（流程缺陷、判据缺失、格式过时）→ 修订该 SKILL.md；
- 版本规则（frontmatter `version:`）：结构或流程变更 x.0 +1；内容修正 x.y +1（如 1.0 → 1.1）；
- 更新前向用户展示 diff 要点，**确认后写入**。

### D. 日报落盘

调用 `daily-report` 技能，将本次复盘的目标、事项、结果、状态、下一步建议生成为报告。

## 第三步：汇报

向用户汇报四路结论的落盘情况：哪些已写入（含路径）、哪些待定、哪些被拒绝。不重复报告内容细节（报告里已有）。

## 硬约束

- 一切写入 AGENTS.md 与 skills/ 的操作必须先获用户授权，禁止静默沉淀；
- 禁止时间估计；
- notes 只读不删：已转化为规则/技能的踩坑记录保留原文件，防止溯源断链；
- 记忆检索失败不是阻塞项：跳过并在日报中注明，用 notes 与 skills 完成复盘。
