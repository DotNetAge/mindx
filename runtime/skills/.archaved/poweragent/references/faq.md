# ❓ 常见问题 FAQ

> 集中问答区。此处仅收录使用中的高频问题；反模式清单见蒸馏 2「蒸馏红线与反模式清单」，设计失败回退见统一回退协议。

| # | 问题 | 答案 |
|---|------|------|
| 1 | 我选了一个人物，但发现一手来源太少怎么办？ | 查看蒸馏 0 的「负向筛选」三个淘汰条件。若命中条件 1（一手来源 < 3 篇），建议换人或降级为岗位型设计——硬上只会得出"想象出来的该人物"。 |
| 2 | 人格蒸馏和岗位型到底选哪个？ | 一句话判断：问自己「它在模仿一个人，还是承担一个岗位？」。拿不准时看 [README.md](README.md) 的 5 题快速诊断表。 |
| 3 | 蒸馏到一半发现素材不够，要重来吗？ | 素材缺失先走蒸馏 1 的「外部搜索降级策略」；搜索后仍不够则看统一回退协议蒸馏 1 行——缺失 >3 维度时暂停，否则标记「外部来源待补充」继续推进。 |
| 4 | verify-skill.py 报错了怎么办？ | 按报错信息定位问题模块（YAML 格式 / CHECKPOINT 标记 / 规则冲突），回退到对应蒸馏阶段修复。脚本不可用时回退到人工矩阵检测，详见 [quality-design-process.md](quality-design-process.md) §规则冲突检测。 |
| 5 | 设计出来的角色回复像"通用 AI"，不像是那个人 | 通常因为未通过蒸馏 4 的「角色一致性」检查。重点排查：身份 5 字段是否只填了名称没填性格；表达 DNA 是否只是"职业术语 + 人格语气"的机械拼接（防 NPC 铁律）；心智模型是否通过了四重验证筛选。 |
| 6 | 岗位型设计中，J3 技法注入后效果不明显 | 检查 DO 规则是否满足「具体动作 + 为什么 + 反例」三要素。缺少反例的 DO 是空泛口号，加上反例后角色行为边界立刻清晰。 |
| 7 | 人物存在公开矛盾（同一话题前后立场翻转）怎么办？ | 这属于负向筛选条件 3，提示该人物不适合蒸馏。如果仍要坚持，取最新公开立场为准，旧立场写入「智识谱系」标为"已修正/已演变"，不可调和。 |
| 8 | 角色设计好了但对话时经常崩人设 | 跑蒸馏 4 的压力测试——用角色最不擅长的边缘场景测试其是否仍保持人设。崩人设的原因是价值观排序不够清晰或诚实边界未定义，回退蒸馏 2 重新梳理。 |
| 9 | 设计过程中脚本（verify-skill.py）报错了怎么办？ | Agent 会自动按「异常自动处理协议」处理：解析报错→自动修复→重试（上限 2 次）。若仍失败则降级为手工矩阵检测，不会阻塞流程。你在对话中只需等待即可，无需手动排查。 |
| 10 | 角色定义太长，输出被截断了 | Agent 会自动识别截断点，按「核心模块→扩展模块」分两轮输出。核心模块（身份卡+心智模型+关键规则+回答工作流）优先交付，扩展模块（时间线+附录等）随后补上。 |
| 11 | 蒸馏到中途发现目标人物的公开资料太少 | 先走蒸馏 1 的「外部搜索降级策略」让 Agent 自动搜索补充。搜索后仍不足则看负向筛选三个条件——命中任一条件建议换人或降级为岗位型。如果素材刚好在精简模式门槛上（≥1 一手+≥2 二手），可以走精简模式先出原型。 |
| 12 | 想设计一个既有真人思维烙印又有明确岗位职责的角色 | 这正是两种范式的融合场景。先走岗位型流水线（J1-J5）定义岗位骨架，然后在身份卡和关键规则中注入该人物的心智模型和决策启发式。详见 [范式融合路径](job-details.md#两种范式融合路径)。 |
| 13 | 设计了一个岗位型角色但对话时感觉和通用AI没区别 | 通常是因为 J3 技法注入被跳过或执行不充分。检查 DO 规则是否含「具体动作+为什么+反例」三要素，身份卡「角色」字段是否有领域限定词，退化行为是否定义了 4 个压力场景。缺少任何一项都是空壳角色。 |
| 14 | 角色交付后想微调某一个模块，需要重走全流程吗？ | 不需要。定位受影响模块做靶向编辑即可——能改一行不改一段，能改一段不改一页。参考 [迭代优化指南](quality-design-process.md#🔄-迭代优化指南)。 |
| 15 | 怎么判断设计质量已经可以交付了？ | 同时满足三个条件：① verify-skill.py PASS（或手工矩阵检测通过）；② Gate 3 门禁全部通过（压力测试 4 场景+置信度检查）；③ 角色在 2 个真实场景对话中不崩人设。三个条件缺一不可。 |
