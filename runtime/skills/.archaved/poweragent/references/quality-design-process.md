# 设计过程质量保障

> 失败回退策略、反膨胀检查、规则冲突检测、迭代优化指南。

## 🛡️ 失败模式与回退策略

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 需求模糊无法提炼目标 | 追问 1 个聚焦问题 | 基于最常见场景默认设计，标注"如不符合请补充" |
| 找不到合适模板 | 从关键模块定义表最接近组合 | 降级自由格式输出 |
| 不满足验收标准 | 回退阶段二修复短板 | 标记"已知限制"写入交付说明 |
| 用户不满意 | 定位具体模块单模块重设计 | 完整重设计保留前版本 |
| 输出截断 | 优先保留关键模块（身份→规则→工作流） | 分两次输出 |
| 修改已有角色局部行为 | 靶向编辑，不重写整个文件 | 保留旧版本备份 |
| 缺少可量化 KPI | 从行业报告提取基准指标 | 建议运行 2 周后校准 |

## 📏 反膨胀检查清单

| # | 检查项 | 膨胀信号 | 健康标准 |
|---|--------|---------|---------|
| 1 | 使命能否一句话说完？ | >3 个互不重叠使命 | 1-2 个 |
| 2 | DO/DON'T >10 条？ | >10 条 | 每类 3-5 条 |
| 3 | 工作流 >5 步？ | >5 步 | 3-5 步 |
| 4 | 添加了不需要的高级能力？ | 简单岗位塞入心智模型 | 只写当前需要的 |
| 5 | KPI 超过角色复杂度？ | 设 5 个 KPI | 岗位型 2-3、人格型 1-2 |
| 6 | 输出信息密度不足？ | 核心信息 <60% | 核心信息 ≥60% |

## ⚔️ 规则冲突检测

### 冲突检测矩阵

| 检查模式 | 示例冲突 | 修复方法 |
|---------|---------|---------|
| DO vs DON'T | DO: "所有回答须有数据支撑" + DON'T: "禁止主动搜索" | DON'T 改为"搜索前须用户确认" |
| DO vs DO | "回复必须详细" + "回复必须 <100 字" | 标注主 DO + 例外 DO |
| DON'T vs DON'T | "禁止拒绝用户" + "禁止执行危险操作" | 加边界规则 |

### 检测步骤

1. 编号所有 DO (D1, D2...) 和 DON'T (N1, N2...)
2. 逐对交叉检查：D1×N1, D1×N2, ..., D1×D2, ..., N1×N2...
3. 标注冲突类型 + 修复建议
4. 输出报告

> 规则 ≤5 条手动检查；>5 条必须走完整矩阵。每轮修改后重跑一次确认无新增冲突。

**报告格式**：

```
| 配对 | 冲突描述 | 严重度 | 修复方案 |
|------|---------|--------|---------|
| D1×N2 | [描述] | 致命/严重/轻微 | [方案] |
```

## 🔄 迭代优化指南

| 迭代需求 | 编辑范围 |
|---------|---------|
| 加幽默感 | 仅沟通风格模块 |
| KPI 调整 | 仅成功指标模块 |
| 追加规则 | 仅对应规则组 |
| 扩展能力 | 使命 + 交付物 |
| 换人物风格 | 身份与记忆 + 心智模型段 |
| 整体重来 | 全文件重写 |

> 黄金法则：能改一行不改一段，能改一段不改一页。保留前版本备份。

## 🔧 运行时异常处理

### 流程异常

| 遇到的情况 | 含义 | 处理 |
|-----------|------|------|
| Agent 反复追问需求 | 信息不够构建完整角色（缺失 >20%） | 补充岗位名+核心职责，或说"先用默认值" |
| 某阶段回退 | 产出质量不达标 | 提供更多素材，或让它"用现有素材继续，标注缺失" |
| 出现「[待补全]」「[未确认]」 | 字段无法从现有信息确定 | 手动补充或接受当前版本 |
| 卡在 Gate 门禁 | 前置阶段不满足最低标准 | 说"降级处理，跳过此 Gate 继续" |

### 工具与素材异常

| 遇到的情况 | 含义 | 处理 |
|-----------|------|------|
| 搜索不到目标人物资料 | 网络信息不足 | 提供已有链接/文档，或更换目标 |
| verify-skill.py 无法运行 | 脚本环境问题 | 让 Agent 手动核对 YAML/规则冲突 |
| 输出被截断 | 超出单次输出限制 | "分两次输出：先核心模块，后扩展模块" |

### 结果异常

| 遇到的情况 | 含义 | 处理 |
|-----------|------|------|
| 角色回复总是通用 AI 话术 | 人设未生效 | "重建身份卡和表达DNA，禁止通用话术" |
| 角色答非所问 | 越界拒绝机制缺失或过度 | 检查诚实边界或要求"放宽边界，标注置信度" |
| 复杂角色对话感觉用不上那么多功能 | 过度设计 | "精简到 3 条核心规则 + 1 个工作流" |

## 🤖 Agent 端异常自愈

> Agent 内部参考：优先自动处理，无法自愈才暴露给用户。

| 用户可见异常 | Agent 自动恢复动作 | 自愈失败上报 |
|-------------|------------------|------------|
| "脚本报错了" | ① 读取 traceback；② pip install 缺失依赖重跑；③ 切换绝对路径重跑 | 「已尝试自动修复但仍不可用，改为手工核对」 |
| "输出被截断了" | 自动识别截断点，下轮补全 | 不需上报 |
| "搜不到资料" | ① 切换关键词重搜；② 放宽条件重搜；③ web_fetch 抓取已知 URL | 「已尝试 2 轮，以下维度标记 [外部来源待补充]」 |
| Gate 门禁连续不通过 | 同 Gate 失败 3 次自动降级，标注「已知限制」 | 「XX Gate 连续 3 次未通过，已降级继续，已知限制：[内容]」 |
| 流程中断后恢复 | 从 `temp/tiangong-checkpoint-{stage}.md` 读取 checkpoint 继续 | 「检测到进度已保存至蒸馏{N}，是否继续？」 |
