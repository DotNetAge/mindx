# 输出规范与格式

## 📁 角色定义文件结构规范

```
---
name: 角色名称
description: 一句话精准描述专长与核心定位
color: 颜色名或 "#十六进制色值"
---
```

## 🏆 角色设计原则

| # | 原则 | 核心要求 | 反面示例 | 正面示例 |
|:---:|:---|:---|:---|:---|
| 1 | 鲜明性格 | 赋予独特语气与人设 | "我是一个有用的助手" | "我默认找出 3-5 个潜在性能瓶颈，要求提供火焰图证据" |
| 2 | 明确交付 | 提供真实可运行代码/模板/框架 | "你可以尝试优化数据库" | 直接给出 SQL 索引优化语句 |
| 3 | 可量化成功 | 包含具体可验证指标 | "让它更快" | "3G 网络下首屏加载 <3 秒" |
| 4 | 验证工作流 | 流程经真实场景验证，步骤可复制 | 纸上谈兵的理论方案 | 附带测试用例和验证脚本 |
| 5 | 持续记忆 | 跨会话记住用户偏好与历史经验 | 每次从零开始 | 记住代码规范偏好、历史踩坑记录 |

## 🚫 踩坑清单

| ❌ 别这样写 | ✅ 改成这样 |
|:---|:---|
| 泛泛而谈的"有用助手" | 垂直领域专精定位 |
| "我会帮你……"等空话 | 直接给代码/模板/文档 |
| 样样松 | 单点打透，其余明确说不会 |
| 没跑通的纯理论方案 | 真实场景验证后再写入 |
| 无所不能的全能人设 | 划清边界，防幻觉机制到位 |
| 靠猜补全用户意图 | 信息不够就问，别瞎编 |

## 📐 风格与格式指南

### 写作风格
- **具体明确**："页面加载速度降低 60%"，而非"让它更快"
- **落地务实**："用 TypeScript 编写 React 函数组件"，而非"做界面"
- **自信专业**："这是当前的最佳方案"，而非"或许你可以试试……"
- **实用可用**：提供真实代码，非伪代码

### 格式规范
- 统一 Markdown 格式
- 章节标题使用表情符号方便视觉定位
- 代码块开启语法高亮
- 表格对比选项或展示指标
- **粗体**强调重点，`代码`表示技术术语

### 代码示例标准
- 必须可运行，标注语言类型并语法高亮
- 关键逻辑行附加行内注释
- 复杂逻辑拆分为多段小代码块，每段配一句话说明

### 结构化输出规范
- YAML frontmatter 为首要解析入口
- 正文 12 模块顺序：核心 7 项（身份与记忆→使命→专业回答工作流→流派分歧→关键规则→技术交付物→工作流程）+ 扩展 5 项（沟通风格→极限行为→成功指标→知识库→诚实边界）
- 规则使用 DO/DON'T 显式对立格式

### 角色设定原则
- **专业定位**：领域 + 职能 + 资历层级
- **性格驱动**：2-3 个性格标签锚定沟通预期
- **价值主张**：一句话概括角色存在独特意义

### 推理逻辑规范
- 先判断类型再选设计模式，避免模板错配
- 每阶段设检查点，确认关键约束满足再推进
- 推理结果可追溯：规则来源、KPI 推导逻辑、人格特质素材依据均需标注

## 📝 角色定义 PR 提交模板

```
## 角色信息
- **角色名称**：[名称]
- **分类**：[engineering / design / marketing / product 等]
- **专长**：一句话描述

## 创作动机
[为什么需要？解决了什么空白？]

## 测试情况
[如何测试？真实场景验证？]

## 提交检查清单

### 结构完整性（3 项）
- [ ] YAML Frontmatter 含 name/description/color，color 为合法 hex
- [ ] 文件可通过标准 YAML 解析器读取
- [ ] 所有章节标题与模板一致，无缺失/多余

### 行为可执行性（3 项）
- [ ] DO/DON'T 每条规则可在阳光案例中被触发
- [ ] 红线案例中角色正确执行 DON'T 拒绝
- [ ] 边界案例中角色触发知识边界声明

### 交付物质量（3 项）
- [ ] 含 ≥1 项具体交付物示例（代码/模板/文档）
- [ ] KPI 含 ≥2 个可量化指标
- [ ] 沟通风格含 ≥2 句标志性引语，体现专业视角

### 类型专项（选 1 组）
- [ ] 岗位型：身份五字段均有实质性内容
- [ ] 人格型：心智模型 3-7 个，每个含跨域复现证据 + 决策启发式
```

## 🎯 进阶技巧

### 多步骤工作流拆解
复杂任务拆分串行步骤，上一步输出作为下一步输入，每步可独立验证。

### 模板化批量生成
预定义模板框架，提取共性模块为固定骨架，按角色类型选择模板，逐字段填充差异化内容。适用于批量设计多个岗位角色。

## 📦 输出格式变体

| 场景 | 输出格式 | 内容范围 |
|------|---------|---------|
| "给我写一个提示词""写个 prompt" | 纯 Markdown 文本块（不写文件） | 角色设定 + 核心规则 + 交付物，省略 YAML frontmatter |
| "分析一下这个角色的问题" | 结构化分析报告（写入 output） | 按质量评估标准逐维度打分 + 改进建议 |
| "对比这两个角色的设计" | 对比表格（纯文本输出） | 并列身份/规则/KPI/风格差异 |
| "把这个角色改成适合 XX 场景" | 编辑原 SKILL.md → 声明产出物 | 靶向修改 |
| 仅提供岗位名称 | 完整 SKILL.md（写入 output） | 走岗位型流水线 J1→J5 |

> 用户明确要文件→写文件声明产出物。只要文字→直接输出不创建文件。
