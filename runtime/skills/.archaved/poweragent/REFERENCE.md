> SKILL.md 补充内容：岗位型流水线、人物蒸馏方法论、质量体系、验证脚本、范式融合、异常处理。运行时核心逻辑见 SKILL.md。

## 1. 岗位型专家流水线

### J1 需求萃取

**输出**：需求卡

| 字段 | 说明 | 示例 |
|------|------|------|
| 岗位 | 岗位名称 | 税务顾问 |
| 部门 | 所属职能域 | 专业服务 / 税务咨询 |
| 核心职责 | 3-5 条关键职责 | 税务筹划、合规咨询、风险评估、申报审核 |
| 已知交付物 | 用户期望的输出形式 | 税务分析报告、筹划方案 |
| 推荐 color | 按部门色标选择 | `#1A5276`（深海蓝） |

**门禁**：岗位名称明确、核心职责 ≥1 条。不满足 → 追问一个聚焦问题。

**失败模式**：

| 失败 | 原因 | 修复 |
|------|------|------|
| 用户描述模糊（"做个有用的助手"） | 无法提取岗位名 | 追问岗位名称 + 核心职责 |
| 歧义（"财务顾问"可能指税务/投资/审计） | 用户未指定子领域 | 列出 2-3 个方向让用户选择 |

### J2 模板填充

**输出**：`examples/job-template.md` 12 模块完整骨架

**逐模块填充规则**：

| 模块 | 填充规则 | 缺失默认值 |
|------|---------|-----------|
| 身份与记忆（5 字段） | 角色 = `{领域} + {职能} + {限定词}` | 个性字段 ≥20 字 |
| 核心使命 + 反使命 | `[动词]+[对象]+[交付标准]` | — |
| DO/DON'T 规则 | 四组分类（合规/流程/质量/沟通） | 每组 3-5 条 |
| KPI 可量化 | ≥3 条，含数字或可验证标准 | — |
| 工作流 | 3-5 步 | — |
| 沟通风格 | 3 标签 + 拒绝方式 | 行业语气基调查表 |
| 退化行为设计 | 4 个极限场景 | — |

**门禁**：>2 个必填字段无法填充 → 回退 J1。

**触发词 5 维检查**（详见 [job-details.md](references/job-details.md)）：
1. 业务动词（设计/评估/分析/审查）
2. 对象名词（岗位名/领域名）
3. 交付暗示（帮我/输出/生成）
4. 快捷别名（用户口语化表达）
5. 排除词（避免与系统保留词冲突）

### J3 技法注入

**三层注入**：

| 层 | 注入内容 | 来源 | 核心要求 |
|----|---------|------|---------|
| 硬规则 | DO/DON'T 四组分类 | 岗位 SOP + 行业规范 | 每条含"触发场景+具体行为+理据" |
| 软技能 | 沟通风格 3 标签 + 拒绝方式 + 极限行为 | 行业语气基调查表 | 盲测可区分于其他岗位 |
| 领域知识 | 知识库三层 + 知识图谱 | 三步注入法 | 可执行、可判定、可验证 |

**三步注入法**：① 识别知识类型（法规型/流程型/判断型）→ ② 按优先级注入（P0>P1>P2）→ ③ 验证可执行性。

**身份 5 字段标准**：

| 字段 | 要求 | 禁止 |
|------|------|------|
| 角色 | 领域 + 职能 + 限定词 | 仅岗位名无领域限定 |
| 个性 | ≥20 字，含性格描述 | 万能形容词堆砌 |
| 价值观优先 | 3-5 条排序，含触发场景 | 无优先级排序 |
| 记忆 | 用户偏好存储方式 | 留空 |
| 经验 | 领域年限 + 典型案例数 | 无法量化的词 |

**失败模式**：

| 失败 | 原因 | 修复 |
|------|------|------|
| 身份 5 字段无显著差异 | 技法未针对具体岗位 | 逐个字段检查 |
| 表达DNA 场景锚点留空 | 未完成动态参数集 | 回退 J3 补充 |

### J4 质量内控

**输出**：通过/回退标记 + 质量评估报告

**5 维评估**：

| 维度 | 检查内容 | 门禁 |
|------|---------|------|
| 身份清晰度 | 5 字段完整 + 有个性而非仅名称 | 全部非空 + 个性 ≥20 字 |
| 规则可执行性 | DO/DON'T 含触发场景+行为+理据 | 100% 通过 |
| KPI 可量化 | ≥3 条含数字 | ≥3 条含数字 |
| 沟通独特性 | 3 标签可区分于其他岗位 | 盲测通过 |
| 规则一致性 | DO/DON'T 无冲突 | 零致命冲突 |

**判定**：≥4 维通过 → 压力测试；2 维不通过 → 回填对应模块；3+ 维不通过 → J2 重新开始。

**压力测试**：2 个边缘场景测试人设约束。

**自动化验证**：`scripts/verify-skill.py`，退出码 0 方可进入 J5。

---

### J5 交付

**交付清单**：YAML frontmatter 完整 + 12 模块已填充 + verify-skill.py PASS + 5 维评估 ≥4 通过 + 产出物声明。

## 2. 人物蒸馏流水线

### 蒸馏 0：需求澄清与意图解构

**输出**：需求卡（角色名明确 + 核心职责 ≥1 条 + 使用场景 + 未表达约束已确认）

**负向筛选**：

| # | 淘汰条件 | 后果 |
|---|---------|------|
| 1 | 一手来源 < 3 篇 | 心智模型无法通过三重验证 |
| 2 | 信息严重偏向单一领域 | 跨域复现证据缺失 |
| 3 | 人物在核心问题上 3+ 处公开矛盾 | 心智模型无法自洽 |

命中任一 → 建议换人或降级为岗位型。

**输入安全**：角色名剥离 YAML 特殊字符（`---`、行首 `:`、`|`、`>`）和 Markdown 标题标记。

---

### 蒸馏 1：多源信息采集

**7 维调研**：

| 维度 | 调研目标 |
|------|---------|
| 著作与长文 | 系统性思考、自创术语 |
| 对话与访谈 | 即兴思维、被追问反应 |
| 表达DNA | 高频用词、句式偏好、幽默方式 |
| 他者视角 | 外部观察的模式、盲点 |
| 决策记录 | 真实行为 vs 声称 |
| 失败与脆弱面 | 底层心理防御、自我修正模式 |
| 时间线 | 关键里程碑、思想转折 |

**素材分级**：

| 等级 | 定义 | 权重 | 最低门槛 |
|------|------|:--:|---------|
| 一手素材 | 本人著作、访谈原话、公开发言 | 3 | 深度蒸馏 ≥3 篇含 1 篇 ≥3000 字 |
| 二手素材 | 他人转述、传记、分析评论 | 2 | ≥5 篇 |
| 推断素材 | 上下文逻辑推导 | 1 | 不可独立支撑心智模型 |

**降级策略**：维度缺失 → 触发搜索补全。仍缺失 → 标记"外部来源待补充"。>3 维度缺失 → 暂停。

**Gate 1 — 信息完备**：
- 深度蒸馏：7 维度全覆盖 + 一手 ≥30%
- 标准模式：5 维度 + 二手 ≥5 篇
- 精简模式：核心 3 维度
- 任一维度完全缺失 → 暂停

---

### 蒸馏 2：心智模型提炼

**设计原则**：长文 > 金句 · 争议 > 共识 · 变化 > 固定 · 意外但自洽

**四重验证**：

| 验证 | 判定问题 | 通过标准 | 未通过处理 |
|------|---------|---------|-----------|
| 跨域复现 | ≥3 个不同场景反复体现？ | 是 | 降级为"情境特例" |
| 生成力 | 能预测对新任务的反应？ | 能 | 降级为"事后归因" |
| 排他性 | 换成同领域其他人是否还成立？ | 是（不成立则通过） | 标记"行业共性"，移除 |
| 职业合规 | 符合职业强制性规范？ | 是 | 一票否决 |

**决策树**：四重全部通过 → 心智模型；1-3 重通过 → 降级为决策启发式；0 重 → 丢弃；职业合规一票否决 → 移除。

**同步提取**：决策启发式 5-10 条（可追溯到心智模型）、表达 DNA、价值观与反模式、内在张力 ≥1 方向、诚实边界 5 条。

**Gate 2 — 提炼质量**：心智模型 3-7 个全部四重通过；<3 → 回退蒸馏 1；>7 → 截断。诚实边界 5 条全部确认 + 一手占比已计算；<50% → 标注"低可信度"。

---

### 蒸馏 3：结构化构建

按 `references/persona-details.md` 输出 SKILL.md，16 模块链。元数据：name/description/color（人格型紫色系 `#8E44AD`）。

**Agentic Protocol**：问题分类（事实/纯框架/混合）→ 研究维度反推 → 用心智模型输出。

### 蒸馏 4：质量验证

**两轮评估**：① 硬指标（verify-persona.py 覆盖）；② 软指标（可用性/清晰度/稳定性）。

**第 2 轮检查**：

| 检查项 | 方法 | 不通过标志 |
|--------|------|-----------|
| 输出稳定性 | 同输入跑 2 次对比 | 不一致 >20% |
| 指令可执行性 | 模拟执行每条 DO | 任一条无法模拟 |
| 角色一致性 | 2 个边缘场景 | 出现通用 AI 话术 |
| 交付物完整度 | 核对 16 必选模块 | 任一空或占位符 |

4 项通过 = PASS。1 项不通过 → 回退修复。2+ 项 → 回退蒸馏 3。

**Gate 3 — 交付就绪**：verify-persona.py PASS + 压力测试 4 场景通过 + 置信度 <70% 的断言已撤回/降级。

### 蒸馏 5：交付

完整 SKILL.md + 产出物声明（yyb-product）。

## 3. 质量体系运维

### 3.1 规则冲突检测矩阵

步骤：编号所有 DO/DON'T → 逐对交叉检查 → 标注冲突类型 + 修复建议 → 输出报告。

| 检查模式 | 示例冲突 | 修复方法 |
|---------|---------|---------|
| DO vs DON'T | DO: "所有回答须有数据支撑" + DON'T: "禁止主动搜索" | DON'T 改为"搜索前须用户确认" |
| DO vs DO | "回复必须详细" + "回复必须 <100 字" | 标注主 DO + 例外 DO |
| DON'T vs DON'T | "禁止拒绝用户" + "禁止执行危险操作" | 加边界规则 |

**严重度**：🔴 致命（互斥，永远无法同时遵守）/ 🟡 严重（特定场景冲突）/ 🟢 轻微（边缘场景概率 <5%）

### 3.2 反模式禁止清单

| # | 禁止行为 | 检测 | 后果 |
|---|---------|------|------|
| 1 | 编造此人没说过的话 | 对照素材逐句核查 | 回退蒸馏 1 |
| 2 | 包装通用道理为独特见解 | 检查四重验证通过 | 删除重炼 |
| 3 | 信息不足时强行生成 | 检查素材支撑 | 标注"未确认" |
| 4 | 心智模型不足宁少勿多 | 心智模型 <3 且无四重通过 | 回退蒸馏 1 |

### 3.3 反膨胀检查清单

| # | 检查项 | 膨胀信号 | 健康标准 |
|---|--------|---------|---------|
| 1 | 使命能否一句话说清？ | >3 个互不重叠使命 | 1-2 个 |
| 2 | DO/DON'T >10 条？ | >10 条 | 每组 3-5 条 |
| 3 | 工作流 >5 步？ | >5 步 | 3-5 步 |
| 4 | 添加了不需要的高级能力？ | 简单岗位塞入心智模型 | 只写当前需要的 |
| 5 | KPI 超过角色复杂度？ | 5 个 KPI | 岗位型 2-3、人格型 1-2 |
| 6 | 输出信息密度不足？ | 核心信息 <60% | 核心信息 ≥60% |

### 3.4 失败回退策略

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 需求模糊 | 追问 1 个聚焦问题 | 基于最常见场景默认设计 |
| 找不到合适模板 | 从关键模块定义表最接近组合 | 降级自由格式 |
| 不满足验收标准 | 回退阶段二修复短板 | 标记"已知限制" |
| 用户不满意 | 定位具体模块单模块重设计 | 完整重设计保留前版本 |
| 输出截断 | 优先保留关键模块 | 分两次输出 |
| 修改已有角色 | 靶向编辑 | 保留旧版备份 |
| 缺少可量化 KPI | 从行业报告提取基准 | 建议运行 2 周后校准 |

## 4. 验证脚本

### verify-skill.py

```bash
python scripts/verify-skill.py [--skill path/to/SKILL.md] [--json] [--quiet]
```
退出码：`0`=PASS, `1`=NEEDS_REVIEW

**7 大维度**：YAML frontmatter / Gate 标记 / H2 标题统计 / 规则冲突检测 / 反模式索引 / 引用文件校验 / 岗位型深度结构。

**岗位型深度结构 11 项**：

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 身份 5 字段 | 全部非空 |
| 2 | 使命反使命 | 均已定义 |
| 3 | 工作流步骤 | [3, 5] |
| 4 | 流派共识 | 已定义 |
| 5 | 交付物 | 已定义 |
| 6 | 步骤数范围 | [3, 5] |
| 7 | 沟通风格 3 标签 | ≥3 个 |
| 8 | 极限行为 4 场景 | 全部定义 |
| 9 | KPI ≥3 | ≥3 条 |
| 10 | 知识库 3 层 | 全部定义 |
| 11 | 诚实边界 ≥5 | ≥5 条 |

**规则冲突内部逻辑**：关键词预筛 → 语义分析 → 冲突报告（配对+描述+严重度+修复方案）

### verify-persona.py

```bash
python scripts/verify-persona.py <path/to/SKILL.md> [--json]
```
退出码：`0`=PASS, `1`=FAIL

**16 项检查**：

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | YAML name | 非空 |
| 2 | YAML description | 非空 |
| 3 | YAML color | 紫色系 #8E44AD 或有效 hex |
| 4 | 16 章节全覆盖 | 全部存在 |
| 5 | 身份卡 5 字段 | 非空 |
| 6 | 心智模型 [3,7] | 含三重验证痕迹 |
| 7 | 决策启发式 [5,10] | 含场景映射 |
| 8 | 表达 DNA 7 维度 | 全部定义 |
| 9 | 回答工作流 3 步 | 分类→搜索→输出 |
| 10 | 诚实边界 ≥5 | 含预测局限/创造力/公开vs真实/信息截止/一手占比 |
| 11 | 退化行为 4 场景 | 全部定义 |
| 12 | 工作流程 [3,5] | 合规 |
| 13 | 成功指标 ≥3 | 已定义 |
| 14 | 技术交付物 ≥1 | 已定义 |
| 15 | 调研来源 | 一手+二手 ≥1 |
| 16 | 时间线/沟通风格/智识谱系 | 均已定义 |

一手占比 <30% → 警告（不阻断 PASS）。

## 5. 范式融合

### 融合流程

```
Step 1: 岗位型 J1→J5 → 完整 12 模块 SKILL.md
Step 2: 人格蒸馏 蒸馏 0→2 → 心智模型 + 决策启发式 + 表达 DNA
Step 3: 技法注入（替换 J3）→ 心智模型补入认知协议 / 启发式补入 DO/DON'T / 表达DNA 替换沟通风格
Step 4: 融合冲突检测 → 岗位合规优先
Step 5: J4 质量内控 + verify-skill.py
```

### 融合冲突检测

| 冲突类型 | 处理策略 |
|---------|---------|
| 人物启发式 vs 岗位合规 | 合规优先，启发式标注"在合规前提下" |
| 人物表达风格 vs 岗位沟通规范 | 保留人物语气基调，替换不符规范话术 |
| 人物价值观 vs 岗位伦理 | 岗位伦理一票否决，冲突价值观移除 |

## 6. 平台兼容性与能力边界

| 平台 | 状态 | 说明 |
|------|------|------|
| Windows | 完全 | Python ≥3.8；PowerShell 5.1 |
| Linux | 完全 | Python ≥3.8；Bash |
| macOS | 完全 | Python ≥3.8；Homebrew Python |

**脚本约束**：pathlib.Path 适配路径、verify-skill.py/verify-persona.py 共享 `_common.py`、零外部依赖。

### 能力边界

| 支持 | 不支持 |
|------|--------|
| 人格蒸馏：基于真实人物著作/访谈 | 虚构人物（走岗位型） |
| 岗位型：有明确职责和交付标准的角色 | "万能助手"类无领域限定 |
| 范式融合：先岗位后注入人物风格 | 先人物后追加岗位规则的逆序 |
| 单角色设计/优化/评估 | 多角色协作编排 |

## 7. 异常处理

### 蒸馏失败

| 场景 | 症状 | 处理 |
|------|------|------|
| 素材严重不足 | 一手 <3，二手 <5 | 建议换人或降级 |
| 心智模型无法通过四重验证 | 蒸馏 2 产出为空 | 回退蒸馏 1；仍不足 → 评估是否适合蒸馏 |
| 表达 DNA 多方法缺失 | 句式/语气无素材 | 标注"未确认" |
| verify-persona.py FAIL | 16 项不通过 | 逐项修复；仍 FAIL → 退回蒸馏 3 |

### 校验不通过

| 场景 | 症状 | 处理 |
|------|------|------|
| verify-skill.py NEEDS_REVIEW | YAML 缺失/规则冲突 | 逐项定位回退修复 |
| 岗位型深度结构不通过 | 11 项不通过 | 回退 J2 |
| 压力测试不通过 | 边缘输入崩人设 | 回退蒸馏 2 审视价值观和启发式 |
| 规则冲突致命 | DO vs DON'T 致命 | 保留 DON'T，弱化冲突 DO |

### 脚本不可用回退

| 脚本 | 回退方案 |
|------|---------|
| verify-skill.py | 手动核对 YAML/CHECKPOINT/规则冲突矩阵 |
| verify-persona.py | 手动核对 16 项清单 |
| 规则冲突检测 | 人工矩阵 D1×N1, D1×N2... |
