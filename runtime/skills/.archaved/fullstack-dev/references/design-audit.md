# 设计审计与改造（既有页面 / 既有项目）

> 本文件是 `frontend-design` 的**改造场景**补充参考，不作为独立子技能计数，也不提供 `@` 显式调用入口。命中"页面太丑 / 看着很 AI / 优化一下 UI / 改版 / 重构样式 / 不专业 / 像模板"等信号时按需加载；**从零新建页面**走 `frontend-design.md`。
>

## 一、先分诊：改造、重做，还是先还债

改造最容易出错的地方是**没诊断就动手**。接到需求先分诊：

| 症状 | 处置 |
| ------------------------ | ---------------------------------------------------------------------- |
| 结构尚可，只是"不好看" | **视觉层改造**：重跑 `frontend-design` 第四步（设计系统）+ 本文第三节修序 |
| 结构本身就是模板节奏 | **结构改造**：重选宏观结构（macrostructure，见 `frontend-design.md`「反 AI 模板式设计」） |
| 无 token、行内样式遍地、z-index 混乱 | **先还债**：先立 token 与层级常量（见「CSS/SCSS 工程约束」），再谈视觉 |
| 用户只说"丑"，说不清哪里丑 | **先审计取证**：按下节输出问题清单 + 截图，让用户选方向（**禁止直接开改**） |

**纪律**：改造前必须先拿到"当前状态证据"（截图 / DOM 结构 / 关键 CSS 值）；没有基线就无法证明改好了。

## 二、审计清单（先取证，再动手）

### 2.1 布局与对齐（"不专业"的最高频来源）

- **光学居中 vs 数学居中**：文字 / 图标在按钮、徽章、圆形头像中是否*看起来*居中——数学居中常因字体基线而视觉偏下，图标类元素需手调 1px 级偏移。
- **卡片组底部对齐**：同一排卡片若标题行数不同，底部 CTA / 元信息必须**底部对齐**（`display:flex` + 内容区 `margin-top:auto`），不允许随内容高度漂浮。
- **垂直节奏一致**：相邻区块间距取**同一节奏基数**（全部为 8 的倍数），不出现 24 / 27 / 32 混用。
- **栅格对齐**：各区块左边界是否落在同一条栅格线；表格数字列是否等宽右对齐。
- **图片网格轨道**：用 `minmax(0,1fr)` 而非裸 `1fr`（后者会被长内容撑破）。

### 2.2 层级与可读性

- 首屏 **3 秒内**能否读出"这是什么 + 要我做什么"。
- 标题与正文对比是否足够（字号差 ≥1.5 倍，或字重差 ≥2 档）。
- 正文行宽 45–75 字符、行高 1.5–1.7；中文行高取 1.7–1.8。
- 是否出现"全部同权重"的卡片堆——应分出主次。

### 2.3 色彩与主题

- **暗色模式一致性**：同一页内是否混用两套主题（深色卡片 + 浅色背景 + 未适配的输入框是典型症状）。
- 对比度：正文 ≥4.5:1、大字（≥18.66px 粗体或 ≥24px）≥3:1。
- 是否用了"AI 紫蓝渐变"作默认背景（除有意选择外应重做）。
- 强调色是否只用于**真正需要强调**的点（每屏 ≤2 处）。
- 色彩配比是否遵循 **60-30-10**（主色 / 辅助色 / 强调色）。

### 2.4 组件与状态

- 交互元素是否具备 **四态**：默认 / hover / focus-visible / disabled（异步的还应有 loading）。
- 可点击元素 `cursor: pointer` 是否**全覆盖**（含自定义 div 按钮）。
- 空状态 / 错误态 / 加载态（骨架屏优先于转圈）是否处理。
- 表单错误是否**就近**提示并把焦点移到首个错误字段。

### 2.5 动效

- 是否**只动** `transform` 与 `opacity`（动 width/height/top/margin 会触发重排）。
- 是否存在无意义循环动画（呼吸、闪光、粒子飘浮）→ **默认删**。
- 是否尊重 `prefers-reduced-motion: reduce`（空间动效降级为 ≤150ms 的 opacity 交叉淡入）。
- `:focus-visible` 环是否**即时**显示（不得做出现动画）。

### 2.6 内容与文案真实性

- 是否编造指标（"+47% 转化"、"50000+ 团队信赖"、"10× 更快"）→ 换成真实值，或用占位块标注"待确认指标"。
- 是否有模板残留：Lorem、TODO、"示例文本"、图片版权小字、语言切换条、章节编号式眉标。
- 文案是否具体到业务——**换成任何品牌都成立 = 不合格**。

### 2.7 响应式

- 断点逐一验证：**375 / 768 / 1024 / 1440**。
- 移动端横向溢出：`overflow-x` 应用 `clip` 而非 `hidden`（后者会破坏 sticky 定位）。
- 移动端大视频 / 大背景图是否有静图降级。
- **字号不受视口绑架**：用 `vw` 定字号必须设上限（`clamp()` 或 `min(…, Nrem)`），否则超宽屏上字会大得离谱；正文与界面字号优先 `rem`。
- **浏览器兼容**：旧版 iOS Safari 对 flex `gap` 支持不全 → 用 `margin` 替代或加 `@supports` 回退；需要前缀的属性确认有 Autoprefixer / PostCSS 兜底（AI 常按"最新规范"生成，不查真实兼容性）。

## 三、修序（按投入产出排序，禁止乱序）

1. **结构层**（若命中模板节奏）——重选宏观结构，其余先别动。
2. **对齐与节奏**（§2.1）——收益最大、成本最低，**永远先做这一步**。
3. **层级与对比**（§2.2）。
4. **色彩与暗色一致性**（§2.3）。
5. **组件四态与可点击反馈**（§2.4）。
6. **文案真实性与模板残留清理**（§2.6）。
7. **动效**——**先删后加**（§2.5）。
8. **响应式收口**（§2.7）。
9. **最终打磨**——阴影层级、圆角体系、发丝线、图标风格统一。

**纪律**：每步改完**截图 / 复验后**再进下一步；**禁止一次性大爆改**（改完无法定位回归，也无法向用户解释改了什么）。

## 四、按行业的反模式（选相关行自检）

| 行业 / 页面 | 常见 AI 味做法（禁） | 应改为 |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------- |
| SaaS 落地页 | 紫蓝渐变 hero + 三卡特性 + emoji 图标 | 单焦点 hero 讲清价值主张；图标改用 SVG 图标库（Lucide / Heroicons） |
| 电商 / 商品页 | 满屏"限时抢购"红标 + 密集角标 | 只保留 1 个真实促销信号；让价格与 CTA 成为视觉重心 |
| 后台 / 管理系统 | 装饰性大图 + 低密度表格 + 多层弹窗 | 高密度、可排序筛选、批量操作明确、危险操作二次确认 |
| 官网 / 品牌页 | 模板化 banner + 无品牌特征的通用插画 | 品牌色 / 字体 / 语气贯穿；用真实产品截图而非手绘假 UI |
| 内容 / 博客 | 全屏 hero + 无限滚动 + 弹窗订阅 | 阅读优先：窄栏、清晰层级、目录、相关阅读 |
| 活动 / 大促页 | 元素堆满、每屏 5 种颜色 | 单一主视觉 + 1 个主 CTA；倒计时与库存**只用真实数据** |
| 数据看板 | 彩虹色图表 + 3D 饼图 + 无标注坐标轴 | 中性灰阶 + 语义状态色；按数据关系选图（趋势用折线、构成用堆叠、排名用条形） |

## 五、微交互参考（"高级感"的具体来源）

| 场景 | 做法 | 参数建议 |
| -------------- | ------------------------------------------ | --------------------- |
| 按钮按压 | 轻微缩放 + 阴影收窄 | `scale(.98)`，100ms |
| 卡片悬停 | 微抬升 + 边框提亮（不是放大图片） | `translateY(-2px)`，150–200ms |
| 输入聚焦 | 边框变色 + 轻描边光环（不用粗阴影） | 150ms |
| 列表项进入 | 逐项错峰淡入 | 每项间隔 20–40ms，总时长 ≤400ms |
| 加载 | 骨架屏优于转圈；进度可见 | 超过 300ms 才显示加载态 |
| 成功反馈 | 就地提示（toast / inline），不用全屏弹窗 | 3s 自动消失 |
| 数字变化 | 滚动或渐变过渡，非突变 | 400–600ms |
| 滚动揭示 | 一次性揭示，不反复触发 | `IntersectionObserver` + 只播一次 |

**纪律**：微交互是"手感"不是"节目"——**每屏同时进行的高级动效 ≤1 个**；`prefers-reduced-motion` 下全部降级为即时切换。

## 六、灵感源与"扒站"工作法

**灵感源目录**（用于找参考、建立审美词汇）：

| 站点 | 适合 |
| ------------------ | ------------------------------- |
| awwwards.com | 获奖创意站，结构与动效参考 |
| godly.website | 高质量设计信息流 |
| dribbble.com | 按行业 / 风格检索 |
| 21st.dev | 组件级参考（现代 React 生态） |
| mobbin.com | 真实 App / Web 流程与状态截图 |
| fonts.google.com | 字体配对与排版规范 |
| codepen.io | 交互与动效原型 |
| animista.net | 现成 CSS `@keyframes` 动画片段（按效果 / 速度筛选，可直接抄改） |

**扒站工作法**（学"怎么做到的"，不是抄）：

1. **选 3 个参考站**：同类型 + 同调性，截图留档。
2. **拆结构**：标注它们的宏观结构、栅格、区块顺序、留白节奏。
3. **拆词汇**：把你"描述不出来"的细节记下来（间距比例、字重搭配、圆角 / 阴影层级、缓动曲线）。
4. **提规律**（不是复制像素）：如"标题行高 1.25 倍 + 紧字距"、"卡片间距是内容间距的 2 倍"。
5. **精炼提取**（只带走关键行，别整块复制）：在 DevTools 的 Styles 面板**逐项取消勾选**属性，观察到底哪个才产生效果——很多时候"高级感"来自**多层 `box-shadow`** 的叠加，或"其实就是 `backdrop-filter: blur(10px)`"。定位到关键几行后**只提取这几行**再交给实现，而不是把整段臃肿样式搬进项目。
6. **落到自己项目**：用本项目 token 复现**规律**，禁止直接搬配色 / 文案 / 图片。

**主观词降级路径**（"要更高级 / 太空了 / 没质感 / 不够大气"这类**无法直接执行**的诉求）：

主观词不能直接翻译成动作——**禁止**把它兑现为"加阴影 / 换亮色 / 加动效"（那正是 AI 味的来源）。走三步降级：

1. **找参考**：要一张同调性的参考图（高端手表、家具、奢侈品、精品酒店官网）。
2. **翻译成具体细节**：指出可执行的客观特征——标题字体的**纤细程度**、**留白尺度**、**图文重叠方式**、颜色**克制度**、动效**速度与幅度**。
3. **用本项目 token 复现**：把这些细节映射到现有 token 与组件上，并给出改前 / 改后对比。

**纪律**：参考站仅用于**建立词汇与验证方向**；产出物不得与参考站在结构、配色、文案上高度雷同——既是品味问题，也是版权问题。

## 七、交付前硬门禁（改造 / 新建通用，逐条打勾）

- [ ] 无横向溢出（移动端用 `overflow-x: clip`）
- [ ] 可点击文本未折成两行（按钮 / 导航 / CTA）
- [ ] 图片网格轨道用 `minmax(0,1fr)`
- [ ] 无 AI 紫蓝渐变（除有意选择）
- [ ] 无 emoji 充当图标（使用 SVG 图标库）
- [ ] 全部可点击元素有 `cursor: pointer`
- [ ] hover / focus 过渡 150–300ms，`focus-visible` 可见
- [ ] 正文字对比度 ≥4.5:1，大字 ≥3:1
- [ ] 尊重 `prefers-reduced-motion`
- [ ] 四断点验证：375 / 768 / 1024 / 1440
- [ ] 加载有骨架 / 进度态（>300ms 才显示）
- [ ] 字体 ≤3 族，层级清晰
- [ ] 色彩遵循 60-30-10，语义色仅表意
- [ ] 图片已优化 + `loading="lazy"`（首屏主图除外）
- [ ] favicon 与 meta（title / description / og）齐备
- [ ] 无编造数据、无模板残留（Lorem / 示例文本 / 版权小字 / 语言条）
- [ ] 暗色模式同一页不混用两套主题
- [ ] `vw` 字号有上限（`clamp()` / `rem`），超宽屏不失控
- [ ] 旧 iOS Safari 下 `gap` 有回退（`margin` 替代或 `@supports`）
- [ ] 网格 `minmax` 数值经 375px 验证（不过宽，必要时降数值或切纵向）
- [ ] 每步改造有截图 / 复验证据
