# 技术战略与演进（technical-strategy）

> 工程纪律层专项：把「要不要做 / 什么时候还债 / 何时抽象为平台 / 何时下线」从直觉变成可判定的动作。不替代 `architecture-decision`（单次方案取舍）与 `engineering-metrics`（度量口径与成本核算）。

**触发**：技术路线图、技术规划、技术债、技术债台账、偿还节奏、平台化、中台、抽象时机、弃用、下线、deprecated、兼容窗口、版本演进。

## 适用边界

- **加载**：跨期技术规划、技术债登记与排序、平台化判断、功能或接口弃用与迁移、兼容窗口制定。
- **跳过**：单次功能实现（走 `code-generation`）；单任务方案取舍（走 `architecture-decision`）；度量口径与成本核算（走 `engineering-metrics`）；排期与工时估算（本技能边界外）。
- **范围声明**：本 reference 产出**判据与模板**；组织级战略决策、资源调配与跨团队推动不在范围内——对外公告与迁移期推动由 `tech-influence.md` 的载体承载，决策权仍归组织。

**铁律**：写不出启动条件的「下一步」，一律移入「明确不做」。

## 执行流程

### 第一步：技术路线图（三栏法）

| 栏位 | 必须回答 | 判据（答成什么样算过） |
| - | - | - |
| **现在做** | 正在解决哪个**已发生**的问题 | 每条指向一个事实锚点：工单 / 事故编号 / 指标异常 |
| **下一步** | **什么条件出现时启动** | 条件须可观察、可判定（如「日活 > 10 万且列表 P95 > 800ms」）；写不出 → 移入「明确不做」 |
| **明确不做** | 拒绝理由 + **重新评估条件** | 理由取自 `architecture-decision.md`「必须拒绝的引入信号」之一（未来时 / 从众 / 纯优雅 / 为技术而技术 / 隐藏复杂度） |

- 路线图**写条件不写时间点**：排期属项目管理，不在本技能范围。
- 「下一步」条数不限，但每条都要有独立触发条件，禁止多条共用一句「资源允许时启动」。

### 第二步：技术债台账

表字段（七列，缺列即不合格）：

`ID | 债务描述 | 来源 | 利息（每月成本） | 偿还成本 | 触发条件 | 状态`

规则：

1. **无利息的不算债务**：算不出利息的，先按「影响面 × 频次」做定性排序；连影响面都举不出的（纯风格偏好）→ **不登记**。
2. **只增不删**：偿还后状态改 `closed`，条目保留（保留历史以支持「同类债务是否复发」判断）。
3. 利息口径与 `engineering-metrics.md`「技术债量化」一致（利息法），禁止两套算法并存。

### 第三步：偿还节奏（20% 配额）

- 每期工程容量预留 **20%** 用于偿还；**不跨期累积**（上期未用完不结转）。
- 破例（可超过 20%）仅三种情形：① 利息季度增幅 > 50%；② 债务已阻塞新需求交付；③ 安全 / 合规类债务（**无配额上限**，可立即处置）。
- 禁止行为：把偿还全部推给「专项治理期」——等价于无限延期，须指出该行为并在路线图中改为常态配额。

#### 债务预警与巡检（挂第三步，区别于 20% 配额）

配额管"每期还多少"，本节管"什么时候必须出手"。巡检时机与 `project-memory-management.md`「工作产物生命周期」一致（Step 6 复盘）。

**预警阈值**（任一命中即产出预警项，不依赖人工回忆）：

| # | 预警类型 | 判据（二值可判） | 建议动作 |
| --- | --- | --- | --- |
| 1 | 利息加速 | 单条债务利息季度增幅 > 50% | 提级偿还，可突破 20% 配额（复用第三步破例①） |
| 2 | 总量越线 | 未偿债务总利息 > 当期工程容量 × 20% | 排入下期偿还计划；仍超则重排需求优先级 |
| 3 | 触发条件已满足 | 台账 `触发条件` 列的判据已成立但仍为 `open` | 立即处置，或显式降级为「接受并记录」并写重估条件 |
| 4 | 逾期未偿 | 同一 ID 连续 2 期未排入偿还 | 出预警并说明阻塞原因；第三期仍无动作 → 移入「明确不做」并记重估条件 |

**登记入口（强制）**：交付中出现以下任一情形，须在收尾时登记台账（`ID | 债务描述 | 来源 | 利息 | 偿还成本 | 触发条件 | 状态`）：

- 采用 workaround 而非 proper fix（来源标 `workaround`，并写明未做 proper fix 的理由）；
- 功能降级 / 范围收窄后遗留的缺口；
- 审查或复盘发现、但本轮不修的缺陷；
- 因豁免评估而跳过的既有债务。

**产出**：预警清单 `ID | 预警类型 | 依据 | 建议动作`，写入项目记忆 Decision Record；无预警时显式声明「本期无债务预警」，禁静默略过。

### 第四步：平台化判断（三条件同时满足才做）

| 条件 | 判据 | 不满足时 |
| - | - | - |
| 重复需求 | ≥3 个业务方存在同一需求，且能列出**各方名称 + 重复点** | 为 2 个业务方建平台 = 过度抽象 |
| 边界稳定 | 列出近 N 期的变化历史，确认无结构性变动 | 边界未定就抽象 = 返工源 |
| 收益当期可见 | 省下的人力 / 故障 / 成本**可量化** | 收益不可量化 → 记入「明确不做」 |

- 任一不满足 → **不做**，写入路线图「明确不做」并标明重新评估条件（对齐 `architecture-decision.md`「不做的判断」）。
- 反模式：「以后业务方会更多」属**未来时信号**，不作为依据。

### 第五步：弃用与演进（三阶段）

| 阶段 | 动作 | 出口判据 |
| - | - | - |
| **公告** | 标注 deprecated + 给出替代方案与时间表 | 使用方名单已列出且已通知到人 / 到团队 |
| **双跑** | 新旧并存，旧路径埋点统计调用量 | 旧路径调用量 = 0，或仅剩**书面豁免名单** |
| **移除** | 删除旧路径并清理引用 | `grep` 旧标识残留 = **0** |

**兼容窗口判定**（窗口长度 = f(使用方数量, 迁移成本)）：

| 使用方数量 | 迁移成本 | 最短窗口 |
| - | - | - |
| 1–2 个（可控范围内） | 低 | 1 个发布周期 |
| 3–10 个 | 中 | 2 个发布周期 |
| >10 个，或含外部调用方 | 高 | 公告 + 双跑 ≥ 1 个季度 |

- **含外部调用方时，窗口不得单方面决定**——须用 `tech-influence.md` 的 RFC 承载公告与迁移期。
- 表中数值为下限；不得低于，可高于并说明理由。

### 第六步：验证与沉淀

- 路线图 / 台账 / 弃用计划的每次变更写入项目记忆 Decision Record（含撤销条件）。
- 债务偿还后须回归验证（引用 `performance-benchmark.md` 或对应测试套件），并在台账 `closed` 行附证据位置（`文件:行号` 或命令）。

## 输出格式

```
## 技术路线图
| 现在做（事实锚点） | 下一步（启动条件） | 明确不做（理由 + 重估条件） |

## 技术债台账
| ID | 描述 | 来源 | 利息 | 偿还成本 | 触发条件 | 状态 |

## 平台化结论
判断：做 / 不做；依据：三条件逐条结论（重复需求 / 边界稳定 / 收益当期可见）

## 弃用计划
阶段：公告 / 双跑 / 移除；兼容窗口：X；使用方名单：…；豁免名单：…
```

## 质量标准

- 「下一步」无启动条件即不合格，不得以「资源允许时」代替。
- 技术债条目须有利息；无利息者不得登记为债务。
- 平台化三条件须逐条给结论，禁止只写「评估后决定」。
- 弃用必须有使用方名单与豁免名单，禁止「批量下线」式无名单表述。
- 输出不得含排期 / 工时估算（本技能边界外，须转项目管理承接）。

## 失败回退机制

| 步骤 | 失败条件 | 回退目标 | 最大重试 | 不可恢复时升级路径 |
| - | - | - | - | - |
| 第一步：技术路线图 | 「下一步」条件无法量化 | 改为可观察的二值条件（如「出现第 3 个业务方」） | 1 | 标注「条件待定」，交用户确认 |
| 第二步：技术债台账 | 利息无法估算 | 退为「影响面 × 频次」定性排序 | 2 | 标注「利息待量化」，列入 `engineering-metrics` 埋点需求 |
| 第三步：偿还节奏 | 无工程容量数据 | 输出配额规则与所需数据清单 | 1 | 标注「配额未落地」，提示补采集 |
| 第四步：平台化判断 | 业务方数量无法确定 | 列出候选业务方清单交确认 | 1 | 默认「不做」并记重估条件 |
| 第五步：弃用 | 使用方名单不可得 | 先扫描调用点生成名单 | 2 | 标注「名单不全」，禁止进入双跑 |
| 第六步：验证与沉淀 | 项目记忆不可用 | 输出成本地文件并标注未沉淀 | 1 | 提示用户手动保存 |


## 关联 reference

- **architecture-decision**（架构决策）— 单个方案取舍走决策流程；本 reference 管跨期与演进
- **engineering-metrics**（效能与成本度量）— 技术债利息口径、容量与成本数据来源
- **tech-influence**（技术影响力载体）— 弃用公告 / 迁移期推动用 RFC 承载
- **incident-review**（事故复盘与 SLO）— 事故暴露的结构性债务进入台账
- **production-readiness**（生产就绪）— 弃用移除属发布动作，走渐进式路径
- **project-memory-management**（项目记忆管理）— 路线图与台账变更沉淀为 Decision Record
