# core.py — 基础层模块使用说明

factor-flow 各业务模块共用的客户端基础层。Agent 通常不直接操作(所有命令已由 cli.py 封装),本文用于理解错误提示与排查问题。

## 组成与作用

| 组件 | 作用 |
|---|---|
| `FactorError` | 引导式错误:「问题→原因→下一步」,所有命令失败时输出,直接按提示修正即可 |
| `FactorClient` | HTTP 客户端:令牌管理、多服务地址、统一响应解析、401/业务错误转引导提示 |
| 日期工具 | `now_ms_utc` / `to_iso` / `today_str`:时间戳与日期格式转换 |
| 校验工具 | 必填、数值下限/精度、手机号格式 |

## Agent 需要知道的行为

1. **服务地址**:默认直连本机各服务端口,部署环境不同时在 `__init__.py` 中修改 `FactorApi(...)` 的默认地址。
2. **令牌**:由 cli.py 以 `--token <访问令牌>` 注入客户端,获取方式见 usage.md;所有命令都需要认证。
3. **响应解析**:业务接口 HTTP 恒 200,按 `code==0` 判断成功,客户端已自动处理;JWT 失败是真实 401,客户端会提示"重新通过授权与账号技能 login"。
4. **引导错误示例**:

```
调用 采购单.prepare 时出现问题:供应商 sup-1 不供应物料 m-9。
原因:该物料的采购单价须取自该供应商的报价单 cost_sheet,其中没有此物料。
下一步:请先通过「数据管理」技能查询该供应商的报价单,确认其供应的物料后再下单。
```

5. **校验规则速查**(与前端一致,命令执行前本地拦截):

| 场景 | 规则 |
|---|---|
| 需求日期 | 不能早于今天 |
| 明细数量 | ≥1 |
| 明细格式 | `物料ID:数量`,逗号分隔 |
| 联系电话 | 11 位手机号(传了才检查) |
| 总金额 | 客户端自动 Σ(数量×单价),2 位小数 |

6. **日期字段**:需求日期提交为 RFC3339 UTC 时间戳(与前端 `new Date().toISOString()` 一致);列表查询的 `ordered_at` 同样自动转换。

## 跨服务依赖(客户端内部查询,Agent 无需关心)

- `data-service`(8081):供应商详情(含报价单)、仓库详情、物料主数据、成品目录(BOM)。
- `account-service`(8182):当前账号信息(经手人/审批人默认值,从令牌解码 user_id)。
- `audit-service`(8080):审核通过/拒绝(`/audit-logs/approve`、`/audit-logs/reject`)。
