# 追踪总纲:程序检查,LLM 归因,以库存/残次仓对齐为终点

> 本文件定义 factor-flow **追踪类命令的统一方法论**。追踪不是罗列单据,而是**链路审计**:由 python 程序做确定性检查并输出检查点报告,LLM 负责归因分析;最终以库存/残次仓的数量闭合,哪个环节对不上,必须定位到「哪张单、哪个环节、差多少」,并给出明确的下一步。

## 分工模式

- **程序(python)= 确定性检查引擎**:拉取各环节数据,逐检查点判定对错。数据步骤核查是绝对精确的,必须由程序完成。
- **LLM = 归因分析**:直接读取检查点报告——
  - `ok=True` 的检查点,按 `guide` 向用户确认结论;
  - `ok=False` 的检查点,按 `guide`(导引词)用业务查询 API 查证原因,给用户完整解释与建议。
- **查询 API 是给 LLM 分析的工具**:所有业务查询命令(`*-list`/`*-get`/`*-find-for`)的作用就是支撑归因分析。

## 检查点协议(追踪命令的输出格式)

追踪命令输出 `checks[]` 检查点报告:每项含 `ok`(程序判定通过/不通过)与 `guide`(导引词);汇总含 `conclusion`(结论)。程序只判 `ok`,**不代替 LLM 下原因结论**;`ok=False` 时按 `guide` 用查询命令取证归因。

## 各业务链路终点映射(对齐口径)

| 链路 | 起点(应发生量) | 中间环节            | 终点对齐                        |
| ---- | -------------- | ------------------- | ------------------------------- |
| 采购 | 采购单应到量   | 收货单已收量        | 收货仓库存覆盖已收              |
| 销售 | 销售单应发量   | 发货单已发量        | 发货仓库存支撑剩余应发          |
| 生产 | 工单计划量     | 领料出库 / 成品入库 | 领料仓(减)+ 目标仓(加)          |
| 调拨 | 调拨量         | 调出出库 / 调入入库 | 调出仓(减)+ 调入仓(加),总量守恒 |
| 退货 | 退货量         | 退入处理            | 残次仓(加)                      |
| 维修 | 维修量         | 残次仓出库          | 残次仓(减),回正常库存           |
| 报废 | 报废量         | 处理流程            | 残次仓(加),正常库存(减)         |
| 盘点 | 账面量         | 实盘                | 差异量(diff_qty)定位            |

## 专用追踪命令

### po-track(采购到货)

输入采购单 ID 或 CG 单号。检查点:

| 检查点                                    | ok 判定     | 失败导引词(引导 LLM 用什么查)                                     |
| ----------------------------------------- | ----------- | ----------------------------------------------------------------- |
| c1 订单定位与状态                         | 恒通过      | —                                                                 |
| c2 到货进度(已到 vs 应到)                 | 无超额收货  | rn-get 逐张核查收货单,确认是否重复收货/多收                       |
| c3 两口径一致性(采购单已收 vs 收货单汇总) | 全一致      | rn-find-for 核查疑点收货单,inv-warehouse-summary 确认入库是否生效 |
| c4 终点对齐(收货仓库存覆盖已收)           | 库存 ≥ 已收 | inv-warehouse-summary 查库存流水,核查领料/发货单                  |
| c5 收货单状态完整性                       | 全部已完成  | rn-get 查未完成收货单状态(正常在途或流程未走完)                   |

### so-track(销售发货)

输入销售订单 ID 或 XS 单号。检查点:

| 检查点                                    | ok 判定         | 失败导引词(引导 LLM 用什么查)                                     |
| ----------------------------------------- | --------------- | ----------------------------------------------------------------- |
| c1 订单定位与状态                         | 恒通过          | —                                                                 |
| c2 发货进度(已发 vs 应发)                 | 无超额发货      | dn-get 逐张核查发货单,确认是否重复发货/多发                       |
| c3 两口径一致性(销售单已发 vs 发货单汇总) | 全一致          | dn-find-for 核查疑点发货单,inv-warehouse-summary 确认出库是否生效 |
| c4 终点对齐(发货仓库存支撑剩余应发)       | 库存 ≥ 剩余应发 | prd-list 生产中 / tr-list 在途调拨查补货渠道,告知缺货量           |
| c5 发货单状态完整性                       | 全部已完成      | dn-get 查未完成发货单状态(正常在途或流程未走完)                   |

## 无专用追踪命令的链路(用查询命令手动对账)

以下链路目前没有独立的追踪命令,需要时按上述「终点映射」组合查询命令核对:

- **生产**:`prd-get` 取工单 → `dn-get` 领料出库单(delivery_note_id)→ `rn-find-for` 成品入库单(receipt_notes)→ `inv-warehouse-summary` 分别核对领料仓与目标仓;
- **调拨**:`tr-get` 取调拨单 → `dn-get` 调出仓出库单 → `rn-get` 调入仓入库单 → 两仓库存核对总量守恒;
- **退货/维修/报废(残次仓)**:`ro-list`/`rp-list`/`sc-list` 取已完成单据 → 汇总数量与残次库存(`/defective-inventories`)增减核对;
- **库存核对(含盘点)**:`inv-warehouse-summary` 取账面 → `ins-get` 取盘点差异(diff_qty)交叉核对。

## Agent 使用规范

- 追踪命令:**必须给出结论**(`conclusion`),不能只罗列数据;
- 存在 `ok=False` 的检查点时,**按其 guide 用查询命令取证后**再向用户解释(哪张单、哪个环节、差多少、下一步),不要跳过取证直接猜测;
- 中间环节查询失败时以 `error` 呈现,**不阻断**整体结论;
- 终点库存为多单据共用结果,「对齐」指与本次链路的数量口径一致(如剩余应发 ≤ 当前库存),不等同于库存总量由本条链路独占。

## 问题定位话术模板

```
物料 <名称> 的 <源单> 数量(<应发生量>)与 <环节单> 汇总(<已发生量>)不一致。
原因:两处口径相差 <差异量>,可能是 <环节> 未完成/重复入账/漏记。
下一步:核查 <疑点单据单号/ID> 的明细与状态,并对照库存流水确认。
```
