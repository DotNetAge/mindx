# 报废:业务指南


## 核心概念

- **报废单(ScrapOrder)** = 记录物料报废(生产损耗/质量报废/积压/过期等)的单据,由 scraping-service 管理。
- 报废类型:`0` 生产损耗、`1` 质量报废、`2` 积压报废、`3` 过期报废。
- 报废仓库 `warehouse_id/name`,处理方式 `treatment`,处理结果 `result`。
- **报废「已完成」驱动库存出库(负数)**,库存核对时要计入。
- 明细 `items`:`quantity`(报废数量)、`amount`(报废金额)、`reason`(报废原因)。

## 状态机

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | 待审核 | 报废单已提交,待审核 |
| 2 | 已同意 | 审核通过 |
| 3 | 处理中 | 报废处理中 |
| 4 | 已完成 | 报废完成(库存已扣减) |
| 5 | 已拒绝 | 已拒绝 |
| 6 | 已取消 | 已取消 |

## Agent 怎么做

本技能只提供**查询**;报废操作在 WebUI。Agent 的职责是**追踪与核对**:

1. **按状态筛报废单**:`sc-list status=1 --size 20`(待审核)、`sc-list status=4`(已完成,已扣库存)。
2. **看报废明细**:`sc-get <报废单ID>` → 明细 `quantity`/`amount`/`reason`,汇总报废金额 `total_amount`。
3. **按仓库定位**:`sc-list warehouse_id=<仓库ID>`。
4. **核对库存**:报废单已完成时,`inv-warehouse-summary` 中该物料库存应已减少。

## 关键约定

- 报废状态 4(已完成)才代表报废生效、库存已扣减;对账时与 `inv-*` 交叉核对。
- 过滤字段仅 3 个(order_no/status/warehouse_id),其余字段无法按列表过滤。
