# 退货:业务指南


## 核心概念

- **退货单(ReturnOrder)** = 客户退回物料(多为销售退货)的单据,由 returning-service 管理。
- 关联销售订单 `sale_order_id`,退入仓库 `warehouse_id/name`。
- 退货类型:`0` 质量问题、`1` 数量不符、`2` 包装损坏、`3` 发错货、`4` 滞销、`5` 换货。
- 退货「已完成」通常驱动退入仓库的后续处理(入库/报废)。

## 状态机

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | 待审核 | 退货单已提交,待审核 |
| 2 | 已同意 | 审核通过 |
| 3 | 已完成 | 退货完成 |
| 4 | 已拒绝 | 已拒绝 |
| 5 | 已取消 | 已取消 |

## Agent 怎么做

本技能只提供**查询**;退货操作在 WebUI。Agent 的职责是**追踪与核对**:

1. **按状态筛退货单**:`ro-list status=1 --size 20`(待审核)、`ro-list status=3`(已完成)。
2. **看退货明细**:`ro-get <退货单ID>` → 明细 `quantity` 即退货数量,结合 `reason`/`return_type` 了解原因。
3. **按客户/仓库定位**:`ro-list customer_name=客户名`、`ro-list warehouse_name=仓库名`。
4. **追踪退入处理**:结合 `inv-*` 核对退入仓库是否已入库(退货已完成的前提下)。

## 关键约定

- 按退货类型(`return_type`)或退货日期(`return_date`)过滤在服务端未生效,客户端已拦截;需要按类型找单时改用全量列表后按字段人工筛选。
- 退货状态数值与采购/销售不同(采购 3=部分收货,退货 3=已完成),对账时先看模块。
