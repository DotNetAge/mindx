# 销售:业务指南


## 核心概念

- **销售订单(SalesOrder)** = 客户销售与发货安排的单据,单号 `XS...`(sales-service)。
- **销售 → 发货 → 出库是一条链**:销售订单发货由发货单(delivery-note)驱动——发货单「已完成」时销售订单明细的已发货数量(`actual_delivered`)累加并触发库存出库。
- 订单明细字段:`quantity`(销售数量)与 `actual_delivered`(实际发货数量)对比即可判断是否发完。

## 状态机

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | 待发货 | 订单已确认,尚未发货 |
| 2 | 已部分发货 | 部分明细已发,还有剩余 |
| 3 | 已发货 | 全部发货完成 |
| 4 | 已完成 | 订单完成 |
| 5 | 已取消 | 已取消 |

## Agent 怎么做

本技能只提供**查询与追踪**;销售下单/发货在 WebUI。Agent 的职责是**追踪与核对**:

1. **追踪发货链路**:`so-track <销售订单ID或XS单号>` —— 一条命令返回关联发货单列表、每物料已发/剩余应发量、发货仓库库存支撑核对与结论(方法论见 `guides/tracking.md`)。
2. **按状态筛订单**:`so-list status=3 --size 20`(已发货)、`so-list status=1`(待发货,提醒发货)。
3. **看订单明细**:`so-get <订单ID>` → 对比 `quantity` 与 `actual_delivered`,判断是否全部发出。
4. **追踪发货与出库**:按订单的 `delivery_notes`(发货单 ID 列表)用 `dn-find-for` 拉齐发货单,状态 `3`(已完成)即已出库。
5. **核对客户/收货信息**:按 `customer_name`/`receiver`/`receiver_phone` 过滤查询。

## 追踪要点(so-track 的检查点,方法论见 tracking.md)

`so-track` 按「程序检查、LLM 归因」分工模式输出检查点报告 `checks[]`:

| 检查点 | 判定 | 失败导引词 |
|---|---|---|
| c2 发货进度(已发 vs 应发) | 无超额发货 | dn-get 逐张核查发货单,确认是否重复发货/多发 |
| c3 两口径一致性(销售单已发 vs 发货单汇总) | 全一致 | dn-find-for 核查疑点发货单,inv-warehouse-summary 确认出库是否生效 |
| c4 终点对齐(发货仓库存支撑剩余应发) | 库存 ≥ 剩余应发 | prd-list 生产中 / tr-list 在途调拨查补货渠道,告知缺货量 |
| c5 发货单状态完整性 | 全部已完成 | dn-get 查未完成发货单状态(正常在途或流程未走完) |

- 存在 `ok=False` 的检查点时,按 `guide` 用查询命令取证后向用户解释「哪张单、哪个环节、差多少、下一步」,不要跳过取证直接猜测;
- 状态 `3`(已发货)与生产/发货模块同数值含义不同,对账时先看模块。

## 关键约定

- 销售状态 `3`(已发货)与生产 `3`(生产中)、发货 `3`(已完成)含义不同,对账时先看模块。
- 发货单状态 `3` 才代表真实出库;追踪出库明细用 `dn-*`,核对库存用 `inv-*`。
