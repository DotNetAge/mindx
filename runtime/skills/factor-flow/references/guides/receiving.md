# 收货入库:业务指南


## 核心概念

- **收货单(ReceiptNote)** = 采购单「已同意」后**自动生成**的到货接收单据,单号 `JC...`(多批次收货时 `-01`/`-02` 递增)。
- **多批次收货**:收货单确认(Confirm)时若只收部分数量,系统自动生成下一批收货单,当前单置为已完成(3),直至采购量收齐。
- **收货完成驱动下游**:`ReceiptNote.Completed` 事件 → 采购单 `received_qty` 累加(状态变 3 部分收货 / 4 已收货)→ stock-service 库存增加。

## 状态机

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | 草稿/准备中 | 采购单同意后自动生成,列表默认不可见 |
| 2 | 待收货 | 开始(Start)后可见 |
| 3 | 已完成 | 确认(Confirm)收货完成;部分收货时本单完成并自动生成下一批 |
| 4 | 已取消 | 已取消 |

## Agent 怎么做

本技能只提供**查询**;收货操作在 WebUI 完成。Agent 的职责是**追踪与核对**:

1. **追踪到货**:`po-track <采购单ID或CG单号>` —— 一条命令返回关联收货单列表、每物料已收/剩余量、库存核对与结论。
2. **看收货单原始数据**:`rn-list`(按单号/仓库/状态过滤)与 `rn-get <收货单ID>`(明细)。
3. **核对收货仓库库存**:`po-track` 已自动核对;也可用 `inv-warehouse-summary warehouse_id=<仓库ID> item_id=<物料ID>` 单独确认。

## 关键约定

- 收货单由系统自动生成,**不要手工创建**;`document_id` 存采购单 ID,列表接口不支持按它过滤,追踪时用采购单的 `receipt_notes` ID 数组反查。
- 收货单状态 1(草稿)在列表中默认不可见;状态 3 才代表真实入库。
