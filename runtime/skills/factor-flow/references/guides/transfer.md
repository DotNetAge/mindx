# 调拨:业务指南


## 核心概念

- **调拨单(TransferOrder)** = 仓库之间转移物料的单据,由 transfer-service 管理。
- **调拨 → 调出出库 / 调入入库是一条链**:
  - 调出仓出库走**发货单**(`delivery_note_id`),完成 → 「调出完成」;
  - 调入仓入库走**收货单**(`receipt_note_id`),生成 → 「调入开始」,完成 → 「已完成」。
- 调拨类型:`0` 正常调拨、`1` 紧急调拨、`2` 库存平衡、`3` 生产需求。
- 字段:`source_warehouse_id/name`(调出仓)、`target_warehouse_id/name`(调入仓)。

## 状态机

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | 待审核 | 调拨单已提交,待审核 |
| 2 | 已同意 | 审核通过 |
| 3 | 调出完成 | 调出仓已出库 |
| 4 | 调入开始 | 调入仓已生成入库单 |
| 5 | 已完成 | 调入仓已入库,调拨完成 |
| 6 | 已拒绝 | 已拒绝 |
| 7 | 已取消 | 已取消 |

## Agent 怎么做

本技能只提供**查询**;调拨操作在 WebUI。Agent 的职责是**追踪与核对**:

1. **按状态筛调拨单**:`tr-list status=1 --size 20`(待审核)、`tr-list status=5`(已完成)。
2. **看调拨明细**:`tr-get <调拨单ID>` → 明细 `quantity` 即调拨数量。
3. **追踪调出/调入**:按 `delivery_note_id` 用 `dn-get` 看调出是否出库;按 `receipt_note_id` 用 `rn-get` 看调入是否入库。
4. **核对两仓库存**:调出仓应减、调入仓应增,用 `inv-warehouse-summary` 分别核对。

## 关键约定

- 状态 5(已完成)才代表调拨真正闭环。
- 按调拨类型(`type`)过滤在服务端未生效,客户端已拦截;需要按类型找单时改用全量列表后按 `type` 字段人工筛选。
- 状态数值与销售/生产/发货不同,对账时先看模块。
