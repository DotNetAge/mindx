# 发货:业务指南


## 核心概念

- **发货单(DeliveryNote)** = 出库单,由销售订单发货或调拨调出等场景产生,由 delivery-service 管理。
- **发货完成驱动下游**:发货单「已完成」事件 → 库存出库(负数)+ 销售订单已发货数量累加。
- **多批次发货**:确认发货时只发部分数量,单号后缀 `-01`/`-02` 递增(与采购收货规则一致),单号前缀 `CC`+日期。
- 与来源单关联:`document_type`(如 `SalesOrder`/`TransferOrder`/`ProductionOrder`)、`document_id`(来源单 ID)。

## 状态机

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | 待审核 | 发货单已生成,待审核 |
| 2 | 已同意 | 审核通过,待发货 |
| 3 | 已完成 | 发货完成(库存已出库) |
| 4 | 部分发货 | 部分明细已发,还有剩余 |
| 5 | 已拒绝 | 已拒绝 |
| 6 | 已取消 | 已取消 |

## Agent 怎么做

本技能只提供**查询**;发货操作在 WebUI。Agent 的职责是**追踪与核对**:

1. **按状态筛发货单**:`dn-list status=1 --size 20`(待审核,提醒审核)、`dn-list status=2`(已同意,待发货)。
2. **看发货明细**:`dn-get <发货单ID>` → 明细 `quantity` 即本次发货数量。
3. **追踪销售出库**:按销售订单的 `delivery_notes` 用 `dn-find-for` 拉齐,判断是否全部发完(状态 3)。
4. **核对库存**:发货单状态 3 后库存已扣减,用 `inv-*` 交叉核对。

## 关键约定

- 发货单状态 `3`(已完成)才代表真实出库。
- `document_id` 存来源单 ID,列表接口不支持按它过滤;追踪时从来源单(销售/调拨/生产)的关联字段反查。
- 状态数值与销售/生产不同,对账时先看模块。
