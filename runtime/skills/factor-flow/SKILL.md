# 业务流

Factor 平台业务单据的统一**查询与追踪**入口。本技能回答三类问题:**某张单现在什么状态、某条链路哪里对不上、下一步该查什么**。

## 什么时候用

- **用**:用户要求查询/追踪/对账任一业务单据或主数据,如「这批货到齐了没」「销售单为什么没发完」「库存和单据对不上」。
- **不用**:登录与令牌 →「授权与账号」技能;主数据维护(增删改/报价/BOM)→「数据管理」技能(主数据**查询**本技能提供)。

## 能干什么

| 业务     | 前缀      | 能力                                                                      |
| -------- | --------- | ------------------------------------------------------------------------- |
| 采购     | `po-`     | 查询、导出、追踪到货                                                      |
| 收货入库 | `rn-`     | 查询收货单                                                                |
| 库存     | `inv-`    | 查询物理库存与三类摘要(仓库/SKU/供应商)                                   |
| 销售     | `so-`     | 查询销售订单、追踪发货                                                    |
| 生产     | `prd-`    | 查询生产工单                                                              |
| 发货     | `dn-`     | 查询发货单                                                                |
| 调拨     | `tr-`     | 查询调拨单                                                                |
| 退货     | `ro-`     | 查询退货单                                                                |
| 维修     | `rp-`     | 查询维修单                                                                |
| 盘点     | `ins-`    | 查询盘点单                                                                |
| 报废     | `sc-`     | 查询报废单                                                                |
| 主数据   | `<实体>-` | 分类/颜色/客户/物料/成品目录/供应商/计量单位/仓库(list/get/批量/BOM/主仓) |

> 本技能只提供查询与追踪,不含任何写操作;下单/审核/收货/发货等均由 WebUI 完成。

## 怎么干

### 1. 准备(所有命令前置)

- **令牌**:经「授权与账号」技能 login,取输出 JSON 的 `data.access_token`,以 `--token` 传入;有效期 2 小时。
- **主数据 ID**:直接查询获得(`supplier-list`/`warehouse-list`/`material-list`/`catalog-list` 等),不要凭空编造。
- **唯一执行方式**(在技能目录下执行):

```
python ./scripts/api_client/cli.py --token <访问令牌> <命令> [参数]
```

### 2. 通用工作流

1. 按上表选前缀定位命令。
2. 需单据/主数据 ID 时用 `*-list`/`*-get`/`*-find-for`;追踪按单号直接执行 `po-track`/`so-track`,无需先查 ID。
3. 失败按「问题→原因→下一步」提示修正重试。
4. 向用户汇报**结论**,不要罗列原始数据。

### 3. 追踪怎么做(方法论核心,详见 references/guides/tracking.md)

- **分工**:python 程序做确定性检查;LLM 做归因分析。
- **检查点**:追踪命令输出 `checks[]` 报告,`ok` 为程序判定,`guide` 为导引词。`ok=True` 按导引向用户确认结论;`ok=False` 按导引用查询命令**取证后**再解释,不要跳过取证直接猜测。
- **终点对齐**:全部追踪以库存/残次仓数量对齐为终点(采购→收货仓、销售→发货仓、生产→领料仓/目标仓、调拨→两仓守恒、退货/维修/报废→残次仓)。
- **专用命令**:`po-track`、`so-track`;其余链路按 tracking.md 组合查询手动对账。

### 4. 关键约定

- **过滤字段受限**:列表接口只支持文档列出的字段(客户端白名单拦截),传其他字段报错。
- **状态数值跨模块含义不同**:如销售 3=已发货、生产 3=生产中、发货 3=已完成;对账前先看模块状态表。
- **写操作在 WebUI**:查询到异常时告知用户处理,不代行操作。
