## 报告文件

- 路径：`<项目目录>/.agents/reports/<agent_name>@<YYYY-MM-DD>.md`
- `agent_name`：报告人身份。当前Agent的名称
- 同日同名已存在：追加序号 `-2`、`-3`，禁止覆盖已有报告。
- `.agents/reports/` 不存在时先创建。
- 报告语言：中文。

## 报告结构（固定）

```markdown
---
- 时间：<YYYY-MM-DD HH:mm>
- 报告人：<agent_name>
---

# 日报 @<YYYY-MM-DD>

## 总述

<一到三句话概括本次复盘周期做了什么、最重要的结果是什么>

## 正文

### 目标
<本周期的工作目标，对齐 AGENTS.md 的工作目标段（若有）>

### 工作事项
<逐条列出：做了什么、为什么做>

### 结果
<每项事项的实际产出：文件、代码、技能、决策，附路径或链接>

### 状态
<每项：已完成 / 进行中 / 受阻；受阻必须写明阻塞点>

### 当日轮次记录
<当天对话轮次的合并去重摘要：按主题归并，同一件事多轮讨论合并为一条并注明轮数；
这是"当天实际干了什么"的事实依据，来自收割的轮次日志>

### 下一步建议与计划
<结合项目目录 TODO.md 的未完成事项与本次复盘发现，给出事项与顺序；禁止任何时间估计>
```

## 输入来源（按优先级）

1. 当日轮次日志：在项目目录运行 `mindx report collect --date <日期>`，收割结果
   默认落在 `.agents/logs/collected-<日期>.md`，读完后删除该收割文件；
2. 调用方传入的复盘材料（deep-review 传入的分析结论与产出清单）；
3. 项目目录 `TODO.md` 的未完成事项（"下一步建议与计划"的依据）；
4. `.agents/notes/` 中本周期新增的踩坑记录；
5. git 提交记录（`git log --since="<日期> 00:00" --oneline`）作为工作事项证据；
6. 当前会话的工作记录（任务清单）。

无输入来源时如实报告"本周期无可用复盘材料"，禁止编造事项。

## 轮次日志边界

- 轮次日志（`.agents/logs/`）是日报专用事实流：daemon 每轮对话后自动写入原文，
  collect 收割时源文件即被删除；收割文件（`collected-*.md`）读完后也删除，不留副本；
- 轮次日志不进复盘原料：不要把其中内容转写进 `notes/`（notes 由复盘流程另行收集）；
- 轮次日志或 TODO 中出现凭据、密钥、令牌等敏感内容时，日报必须脱敏并标注"已脱敏"，
  禁止原样引用。

## Leader 汇总模式

当被要求"汇总团队报告 / 生成最终报告"时：

1. 读取 `.agents/reports/` 内本周期全部成员报告；
2. Leader 自身先完成复盘（同样走本技能生成 Leader 自己的报告）；
3. 生成汇总报告：报告人写 Leader 名，正文按成员逐个摘录结果与状态，末尾"下一步建议与计划"给出团队级排序；
4. 汇总文件名：`<leader_name>@<YYYY-MM-DD>.md`，正文开头列出所引用的成员报告文件名。

## 硬约束

- 禁止任何时间估计（人天/天/周/小时）——"下一步建议与计划"只写事项、顺序与依赖；
- 禁止编造未发生的工作事项；无据可写时显式注明；
- 状态为"受阻"的事项必须在下一步建议中给出解锁路径；
- 敏感内容必须脱敏后才能进入日报。
