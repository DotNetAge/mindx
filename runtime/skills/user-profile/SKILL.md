# 用户画像建档

## 档案定位

`~/.mindx/USER.md` 是「用户的灵魂档案」，与 Agent 的 SOUL 同一地位：Agent 的灵魂有锁定规格，用户的画像同样有锁定规格——不同模型写出的画像必须长得一样，差异只允许出现在内容里。

- 写：秘书（assistant）独家维护——默默记录、建档、更新。
- 读：全体 Agent 只读。AGENTS.md 公共纪律已声明：涉及用户偏好的决策先读 USER.md，缺失或未覆盖时如实说明，不臆测。
- 格式规格见 [user-md-spec.md](references/user-md-spec.md)，章节与条目句式以它为准，禁止自由发挥结构。

## 何时写

三种触发，共用一套收集纪律：

1. **首次建档**：用户目录还没有 USER.md 时，按规格建骨架——只写已有证据的条目，没有证据的章节留空注明「暂无记录」，禁止凭空填满。
2. **日常流露**：对话中用户自然表达的偏好（称呼、口味、否决、纠正），随手落盘——这是主路径，一个好画像是一句一句攒出来的，不是一次问出来的。
3. **缺口补齐**：当前任务因画像缺信息拿不准，且默认选项会不可逆地影响交付时，借对话的自然时机用选项式提问补齐（见下）。

## 收集纪律（怎么巧妙地了解）

- **默默记录为主**：用户主动说出口的不用问；从用户的否决、纠正、重复动作里反推，落盘时标注观察来源。
- **借题发挥**：缺Info时把提问藏进正事里——正要设计方案，顺口给两个风格选项让他挑，挑完既推进了任务又攒了画像。
- **选项式兜底**：确实要直接问时，一次只问一个维度，给 2-3 个具体选项外加开放式补充，禁止把画像问卷一次性甩给用户填。
- **不臆测不代写**：没有证据的条目不落笔；推断出来的条目必须带「推测」标注与观察依据，下次得到证实或证伪时更新。
- **宁缺毋滥**：一条错误画像比十条缺失危害大——错误画像会让所有 Agent 自信地做错事。

## 条目写法

按规格句式落盘：**结论——证据**。证据写清观察来源（哪次对话、哪个项目、用户原话）。

- 合格：`结论先行，简短回答，像人类一样说话——全局军规定案（2026-10）`
- 不合格：`用户喜欢简洁的回复`（无来源、无措辞依据，日后无法核实也无法修订）

## 维护

- 更新时优先合并进既有条目，同一偏好只保留一条最完整的表述，避免膨胀。
- 被证伪的条目当场改写或删除，保留一句修订缘由——画像的演进史比快照更防错。
- 文件始终保持在百行以内：画像要的是高信噪比，不是大而全。
