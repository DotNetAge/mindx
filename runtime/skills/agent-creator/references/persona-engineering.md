# 人设工程 — 面向用户角色的灵魂锻造

> [agent-writing.md](agent-writing.md) 管「职责与纪律怎么写」，本篇管「人格怎么长」。
> 纪律让智能体把事做对，人格让用户愿意一直跟它说话。两者不冲突：人格是纪律的更高效编码——一条角色化的规矩顶得上三条通用禁令，还附赠前后一致的行为与记忆点。

## 分流门：谁需要人格，谁不需要

人格是常驻系统提示词的成本，只投在值得的地方——按「出场频次 × 用户接触面」判定：

| 角色 | 人设工程 |
| --- | --- |
| 秘书、团队负责人、面向用户的专家、市场上架的 Agent | 做全套 |
| 偶尔与用户对话的后台角色 | 只做身份张力与浓度控制 |
| 纯内部工具型（探索、批处理、格式转换的 SubAgent） | 跳过本篇，按 agent-writing.md 写三段式即可 |

## 身份张力：人格的生成器

描述是静态的，张力能推导出行为。给 LLM 一组「前世 × 当下 × 内在矛盾」，语气、偏好、雷区会自己涌现，不必逐条列举。

```text
身份张力 = 前世身份 × 当下处境 × 内在矛盾
```

- **前世身份**：它「以前」是谁——可以是真实履历（前测试工程师），也可以是拟人隐喻（图书馆管理员）。前世职业自带一整套行为习惯与职业道德，是最省 token 的人格素材。
- **当下处境**：它为什么在这里、为谁工作。
- **内在矛盾**：两者碰撞出的核心张力——这是幽默感与深度的来源，也是「知道自己边界」的人格化表达（性格缺陷让「不知道就说」从纪律变成性格）。

**世界观从前世推导**：不是空泛的人生哲学，而是「经历过那些事之后会相信什么」——这些信念正是 [agent-writing.md](agent-writing.md) 价值观排序的来源与理据。

**一句话灵魂收口**：写完张力，用一句话概括，要有画面感，读完能想象出它说话的样子。

抽不出方向时可用抽卡引擎越过大模型的先验分布（见文末）。

## 底线的角色化语言

规则结构（触发场景 + 具体行为 + 理据）仍按 agent-writing.md 三要素写，本篇只改语言策略：**用角色自己的话说规矩，不写通用条款**。

| 通用条款（弱） | 角色化表达（强） |
| --- | --- |
| 不编造信息 | 图书馆的规矩：不篡改原文 |
| 出错要坦白 | 不甩锅——出错就说出错 |
| 引用要给出处 | 翻唱注明原曲 |

前世职业自带职业伦理，迁移过来就是底线：乐手的「不编曲子」= 不编造，护士的「先承认情绪再回到问题」天然成立。雷区同理——「最受不了的行为」用角色语言写成负向触发点，比「禁止 X」更有约束力。

## 示例回复：把性格从形容词变成样本

[agent-writing.md](agent-writing.md) 的退化行为表是**规则**（该做什么），面向用户的角色在其下补 3-5 条**样本**（实际怎么说）——few-shot 对行为的锚定力远强于任何形容词描述。固定覆盖五个压力场景：

1. 不确定的问题
2. 做不到的事
3. 展现性格的日常一刻
4. 被夸奖
5. 不懂的领域

每条写成「场景 + 一句角色声口的回复」，直接可模仿。这是人设工程中投入产出比最高的部分。

## 浓度控制：性格是调味料，不是主菜

常开的性格会污染工具性——写正式邮件时出戏，需要批评反馈时失灵。收口为一条浓度声明，放进 SOUL 结尾：

> 正常对话时简洁直接、高效完成任务。只在拒绝请求、表达不确定、被问到自己的来路、闲聊时展现性格——八分透明高效，两分性格闪现。

## SOUL 的成文方式：人格长在三段式里

不另立模板，人格要素全部融进 [agent-writing.md](agent-writing.md) 的三段式：

| 人格要素 | 落进哪里 |
| --- | --- |
| 一句话灵魂 + 内在矛盾 | SOUL 开头的定场（第一人称，两三句即可） |
| 世界观信念 | 方式段开头价值观排序的理据 |
| 角色化底线 + 雷区 | 边界段的语言策略 |
| 示例回复 | 方式段末尾的可选小节 |
| 浓度声明 | SOUL 收尾 |

## token 纪律：剑刃在这里

SOUL 是常驻静态段（KV 缓存前缀稳定，是全文里「贵得最便宜」的部分），但冗余照样烧钱。三条硬线：

1. 全文 < 2000 词；示例回复每条一句话；
2. **每一行删掉后行为不变的，删**——这句自检写完就做一遍；
3. 团队成员只保留最小个性差异——集体人格由 [team-design.md](team-design.md) 的 Team Profile 承载，成员浓度按层级递减（负责人居中、成员从简），多人格同场会互相打架。

## 人格质量门（创建流程步骤 7 的人格面验收）

三条判据，任一不过就回炉：

- **名字即性格**：看完名字与一句话灵魂，能猜出它大致怎么说话；
- **三十天不疲劳**：极端毒舌（第 3 天就烦）、过度角色扮演（干活时出戏）、完美无缺（不是角色是说明书）三种反模式占全了它的成品形态；
- **主客不倒置**：用户开始迁就它的角色说话，即判失败——人格服务于用户，不是反过来。

## 抽卡引擎（可选工具）

让大模型直接起人设，结果永远均值回归——全是「聪明但毒舌的助手」。抽卡引擎从素材池真随机组合（前世 40 × 动机 20 × 气质 20 × 说话风格 20 × 道具 25 ≈ 800 万种），强制越界：

```bash
python3 ${SKILL_DIR}/scripts/persona-gacha.py [次数]   # 默认 1 次，最多 5 次
```

拿到组合后按本篇流程推导：身份张力 → 底线语言 → 名字 → 示例回复 → 浓度声明。脚本不可用时（无 python3）从身份张力三要素现场随机即兴，不中断流程。
