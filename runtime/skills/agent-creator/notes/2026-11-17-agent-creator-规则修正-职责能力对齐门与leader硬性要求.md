## 2026-11-17 技能配比只有预算论无对齐门，leader 可被造成空心（glm）

- 问题：规则缺失（场景未覆盖或规则模糊）——步骤 3 原文对技能只规定「最多 2-3 个」的预算上限，没有「职责动作是否有技能覆盖」的前置检验：按此造出的 bega-lead 职责是拆包派发 + 验收裁决，唯一装配的技能 git-workflow 与两项职责都不沾边，验收确定性全靠收 worker 自述报告（bega 会议 182 次 LLM 调用烧 3.9 美元无人拦）。管理类技能（任务拆解/派工/验收取证）在技能库中不存在，装配环节也无强制要求。
- 否决：取消 2-3 上限、按职责动作数敞开配技能——否决，每技能吃每次会话上下文，上限本身合理；错在缺「先对齐职责再谈预算」的前置门，不在预算论。
- 修正：①步骤 3 标题改为「先过职责-能力对齐门，再三级找齐」，门内要求列「核心职责动作→覆盖技能」对照表，无覆盖动作补技能或回改职责，禁止带缺口过门；②leader 岗硬性要求 1 门管理技能 + 1 门领域手艺技能，缺一禁止注册；③团队招募节的 leader 要求与步骤 3 对齐门同步（SOUL 写「估算 + 阶梯派工 + 抽查验证自己动手」）；④反模式加「技能配比只谈上限不谈对齐」。version 1.0.0 → 1.1.0。
- 验证：`mindx skill validate --path runtime/skills/agent-creator` 全绿（197 行，soft_rules 0）；用「创建一个项目负责人」复演步骤 3，输出先是对齐门对照表再进三级检索。
