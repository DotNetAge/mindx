# 2026-10-18 确定性操作必须脚本化（glm）

- 问题：规则缺口——scripts 判据只有效率视角（高频/费算力/专业操作），缺确定性视角；Agent 创建技能时不主动考虑写 scripts，检验、盘点、处置、发布等操作全靠 LLM 读文档临场拼命令，又浪费又抖动（用户多轮实践反复发现，本轮 market-release 技能现场治理为直接诱因：纯文档技能导致 COS 签名手写两次才对、检验清单无法稳定复现）。
- 否决：不采用"只在反模式里加一条提醒"（无判定动作，治标）；不采用"把判定标准写进 best-practices 副本而不进正文工作流"（创建时不会读到，等于没写）。
- 修正：①三层结构 scripts 行扩为四类，新增第④类确定性操作判据（可重复执行、不容抖动、结果需可信断言——检验/盘点/处置/发布/部署/签名/带鉴权调用，即使单次简单也必须脚本化）；②创建工作流步骤 5 新增「动作面脚本化判定」前置段（确定性四问 + 脚本硬性要求：写操作回读校验、检验输出 PASS/FAIL/SKIP 与退出码、破坏性动作确认阀 + SKILL.md 必附「执行铁律」节）；③审查步骤 C 新增动作面脚本化核查项；④反模式新增两条（确定性操作临场拼命令 / 脚本只执行不校验）。version 1.4.7 → 1.5.0。
- 验证：四处修改均在 SKILL.md 正文可检索；lint 警告均为存量历史格式问题（MD012/MD027/MD040），无新增实质缺陷。
