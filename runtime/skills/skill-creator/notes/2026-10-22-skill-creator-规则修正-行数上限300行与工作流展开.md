# 2026-10-22 skill-creator 规则修正：行数上限放宽至 300 行与创建工作流展开

## 触发

用户定案（2026-10-22）：`maxBodyLines` 200 → 300（quality.go 由用户修改），要求 SKILL 正文至少能把基本工作流说明清楚——1.8.0 版工作流每步仅一行，缺「怎么做」的具体动作，自足率不足。

## 修正内容

1. **行数口径同步**：正文内 4 处「≤200」全部更新为 300（五项自检、文件结构约定、反模式过度膨胀防线、纪律边界）；核心原则新增「行数上限定案」条目，与自足率并列为体量控制上下界
2. **创建工作流展开**（185 → 250 行，v1.8.0 → 1.9.0）：
   - 步骤 1 补三个前置问题（解决什么/谁触发/验收标准）与素材收集两路（对话提取/项目产物综合）
   - 步骤 2 新增三层分配判定表（按「内容回答什么问题」分配去处）与三路径路由清单（正常/失败/输入不全）
   - 步骤 4 自检从五项扩为六项（增自足率判定），各步骤补具体命令
   - 速查节补「失败模式写法示例」
3. **修一处引用含糊**：refcheck 标注全路径（实存于 retrospect 技能 scripts/ 下）

## 效果

validate PASS（250/300 行）；重编译后 300 上限在 daemon 与 CLI 生效。5 条 soft-rule 告警中 4 条为词面误报（「修改建议」名词用法、词表行自指），1 条为重编译前的旧二进制 size 告警，重编译后消除。

## 经验

改校验实现（Go 常量）后必须 make restart 重编译，否则 daemon 与 CLI 仍跑旧值——validate 输出与源码不符时先怀疑二进制未更新。
