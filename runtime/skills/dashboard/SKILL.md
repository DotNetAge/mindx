## 何时用

用户想要任何「仪表板 / 数据面板 / 监控墙 / 可视化卡片」时。本技能单点收口全部仪表板场景：本文件是工作流程与引文地图——**格式规范、设计规范、控件手册、场景指引全部在 `references/`，按工作流程指示的时机读取，未读不得开工**。

## 主题澄清（动手前必做）

用户未指明仪表板主题、场景或数据来源时，禁止自行猜测。先用 AskUser 提供 2-4 个假设选项让用户选择，用户不选再开放提问：

- **主题不明**（"做个仪表板"未指明看什么）→ 列出候选：按用户上下文推断的场景（项目进度 / OKR / 需求池 / 任务看板 / 人力 / 缺陷 / 架构拓扑 / 自定义）。
- **数据来源不明** → 列出候选：项目内数据文件 / 已有报告与 notes / 用户口述数据 / 留占位卡。
- **用途不明** → 列出候选：日常监控 / 汇报展示 / 决策支持。

每项给具体选项 + "其他（自由输入）"兜底。主题与场景明确后进入工作流。

## 工作流程

进入工作流前先 `TaskCreate` 建立任务清单（场景分析 → 读设计规范 → 布局设计 → 取数 → 生成 → 落盘，含每步产出），推进中用 `TaskUpdate` 标记完成状态，中断恢复时用 `TaskList`/`TaskGet` 读取进度，不凭回忆对齐工作点。

1. **场景分析**：从对话判断业务场景，按「场景路由」读对应 `references/scene-<场景>.md`（该仪表板给谁看、布局设计语言、部件内容引导、语义色映射、取数来源）。自定义领域参照最接近的场景自由设计。
2. **通读设计规范**：读 `references/design-spec.md`（颜色 token、文字层级、图表、红线纪律）——**任何仪表板生成前必须通读，写死色值是红线错误**。
3. **布局设计**：以场景指引的「布局设计语言」为起点，结合对话场景增删部件、调整占比。一屏讲完核心信息，不要堆卡。
4. **取数**：按场景指引的取数来源收集真实数据内联为静态值。绝不编造数据；缺数据就留占位卡并告诉用户。
5. **生成**（二选一）：
   - **脚本生成**（默认首选，标准部件为主时）：写一份仪表板 spec（JSON，格式见 `scripts/new_board.py --help`），跑脚本产出 `.dash`——部件 HTML 由脚本内建渲染（已符合样式规范），Agent 只写数据与结构，大幅节省上下文。
   - **手写**（布局/部件定制化强时）：先读 `references/dash-spec.md`（.dash 格式完整规范：元素属性、版式栅格、解析行为、卡内运行环境），控件写法查 `references/card-cookbook.md`，场景范例 `references/example-<场景>.dash`。
6. **落盘**：默认写 `.agents/dashboards/<名字>.dash`（约定落点）；项目内任意目录的 `.dash` 都会被宿主自动发现并进入侧栏（递归扫描，自动跳过 node_modules/.git 等）。单文件即生效，用户端自动刷新。更新 = 重写该文件（只改受影响卡片的标记）。

## 核心概念速览

一个 `.dash` 文件 = 布局 + 共享样式 + 全部卡片内容，自包含。`<board>` 是根（全局属性 + board 级共享 `<style>`），`<card>` 是卡片（24 栏栅格占位，内容为自由 HTML，渲染在独立 iframe 文档中，宿主注入 UIKit `--mx-*` 设计 token，卡高自动跟随内容）。最小样例：

```html
<board name="缺陷总览" gap="12" class="qa">
  <style>
    .stat .n { font: var(--mx-font-title); }
    .stat .d { color: var(--mx-text-secondary); font-size: 12px; }
  </style>
  <card id="open" class="stat" span="6" title="待处理">
    <div class="n">11</div><div class="d">含 2 个 P1</div>
  </card>
</board>
```

属性值域、缺省、解析行为、卡内运行环境的**完整契约**见 `references/dash-spec.md`。

## 场景路由（读哪份场景指引）

| 业务场景                                   | 场景指引                      | 版式要点                             |
| ------------------------------------------ | ----------------------------- | ------------------------------------ |
| 项目跟踪、迭代进度、任务分工、敏捷、里程碑 | `references/scene-project.md` | 左右双通栏：左全局甘特，右部件栈     |
| 个人 OKR、目标跟踪、待办驱动               | `references/scene-okr.md`     | 概览 stat 行 + 目标达成列 + 分布双列 |
| 需求管理、需求池、优先级与状态跟踪         | `references/scene-req.md`     | 概览 stat 行 + 分布双列 + 明细表     |
| 任务看板、看板视图、卡片流、泳道分列       | `references/scene-kanban.md`  | 概览 stat 行 + 状态列 flow 大通栏    |
| 人力盘点、团队画像、组织架构、招聘进度     | `references/scene-hr.md`      | 概览行 + 分布/漏斗双列 + 成员墙      |
| 缺陷管理、质量监控、问题跟踪               | `references/scene-bug.md`     | 概览行 + 趋势/分布双列 + 流转 + 明细 |
| 架构总览、服务拓扑、Archify 产物植入       | `references/scene-arch.md`    | 主体架构图大通栏 + 清单与分布        |

自定义领域仪表板：参照最接近场景指引的布局语言自由设计部件，控件写法查 card-cookbook。

## 引文地图（按需读取，勿整读）

| 引文                                   | 内容                                                                                                                                         | 读取时机                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `references/design-spec.md`            | 设计规范：颜色 token 表、文字层级、图表、共享样式、红线纪律                                                                                  | **每次生成前必读**           |
| `references/dash-spec.md`              | .dash 格式完整规范：元素属性值域、版式栅格、解析行为、运行环境                                                                               | 手写 / 调试解析 / 设计新控件 |
| `references/card-cookbook.md`          | 标准控件写法手册（结构 + 要点 + token 骨架）                                                                                                 | 手写或设计新控件时           |
| `references/scene-<场景>.md`（×7）     | 场景指引：给谁看、布局语言、部件引导、语义色映射、取数来源                                                                                   | 工作流程第 1 步              |
| `references/example-<场景>.dash`（×7） | 场景完整范例——是结构与效果参考，**禁止照抄数据与布局**                                                                                       | 手写时对照                   |
| `scripts/new_board.py`                 | 模板化输出脚本（stat/progress/bars/funnel/flow/table/timeline/gantt/members/raw 渲染器），`python3 scripts/new_board.py --help` 看 spec 格式 | 脚本生成时                   |
