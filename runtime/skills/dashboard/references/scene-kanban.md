# 场景指引：任务看板仪表板

通用规范（工作流程、文件协议、设计规范、红线）见技能主文件 SKILL.md，本文只补本场景约定。

## 这个仪表板给谁看

任务的执行者与协调者。他们打开看板想立刻知道：**每一列有多少、卡卡在哪一列、每张卡是什么优先级、做了多久**。看板是「以列为主角」的版式——列 = 状态/阶段，卡 = 条目，全板就是一条流动的管线。

## 取数来源（由 Agent 调用时决定）

数据源不写死：issue/任务文件、Excel/CSV 导出、对话上下文中的任务清单均可。有结构化表格就按列映射（标题、优先级、状态、耗时、类别各一列）；自由文本清单的行尾标记方案参照 scene-okr.md。唯一原则不变：内联静态值，绝不编造。

## 布局设计语言

常见版式起点：

- **首屏概览 stat 行（3~4 张）**：全部 / 各关键状态计数（未开始、进行中、已完成，阻塞非零单独一张警示卡）——先给池子规模。
- **主体：状态列 flow 大通栏（span 24）**：3~6 列，每列 = 一个状态；列头自动带计数徽标（flow 渲染器内建）；列内卡片 = 条目。
- **卡内信息三段**：条目标题（text）→ 优先级/分类徽标（tag + tone）→ 耗时·日期·类别等辅助行（meta，一行拼完）。
- **可选收尾**：状态分布 bars 或负责人维度 table（参照 scene-req.md），用户只要看板时省略。
- **这不是死规定**：列名按对话中的实际生命周期措辞（待办/进行中/已评审/已完成，或 待评审/开发中/已发布）；卡片少时列内可放大留白；强调某列就把关键 stat 换成该列的警示色。

## 部件内容引导

| 部件 | 显示什么 | 注意什么 |
| --- | --- | --- |
| 概览 stat | 全部 / 未开始 / 进行中 / 已完成 | 阻塞数非零用 danger 单独成卡 |
| 状态列 flow | 列 = 状态，卡 = 条目 | 列不超过 6；列头计数由渲染器自动生成，不手写 |
| 看板卡 | 标题 + 徽标 + meta 一行 | 标题一行省略；meta 拼接「耗时 · 日期 · 类别」，不写长文 |
| （可选）分布 bars | 各列计数柱状 | 与 flow 列头数字必须对账 |

## 语义色映射（全板一致）

通用纪律见 SKILL.md「设计规范」。本场景语义色映射：

| 语义 | token |
| --- | --- |
| 阻塞 / 最高优先 | `var(--mx-danger)` |
| 临近 / 次高优先 | `var(--mx-warning)` |
| 进行中 | `var(--mx-accent)` |
| 已完成 / 健康 | `var(--mx-success)` |
| 未开始 / 常规 | 中性（脚本 neutral tone） |

对应脚本 tone：阻塞卡→danger、紧急卡→danger、常规卡→neutral；进行中列强调→accent、已完成→ok。
