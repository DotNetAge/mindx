# 场景指引：项目跟踪仪表板

通用规范（工作流程、文件协议、设计规范、红线）见技能主文件 SKILL.md，本文只补本场景约定。

## 这个仪表板给谁看

项目管理相关人员（项目经理、研发负责人、PMO）。他们打开仪表板想立刻知道：**进度是否可控、谁在忙什么、什么延期了、目标达成没有**。布局与措辞都围绕这四个问题组织——最重要的信息放首屏视线落点。

## 布局设计语言

常见版式起点：**左右两个垂直大通栏**。

- **左栏（约 10/24）**：全局甘特图贯穿上下——任务排期一屏总览，按人或按模块分行，条形上标任务名，今日线竖穿全图。这是项目管理者视线的锚点：整体节奏一眼可见。
- **右栏（约 14/24）**：自上而下布局多个小部件，按「结论先行」排序：
  1. 达成目标（目标 + 完成度进度条）——先给结论
  2. 人员组成 / 负载（成员 + 手头任务 + 负载条）——资源视角
  3. 延期事项（红黄标 + 延期天数 + 原因）——风险视角
  4. （可选）顶部一行迭代概览 stat（需求总数 / 进行中 / 已完成 / 阻塞）
- **这不是死规定**：对话里用户只关心某几件事就砍掉其余部件；用户强调某主题（如「这周谁活太多了」）就把对应部件提到首屏并放大；小项目可以把甘特改半宽、右栏改双列。

## 部件内容引导

| 部件          | 显示什么                               | 注意什么                                                           |
| --------------- | ---------------------------------------- | -------------------------------------------------------------------- |
| 甘特图        | 任务名、起止、负责人、今日线           | 行按人/模块分组；行多时只放关键路径与近两周任务；今日线必须画      |
| 达成目标      | 目标名、衡量口径、当前值、完成度       | 目标必须可量化；完成度用进度条；未启动与已完成视觉区分             |
| 人员组成      | 姓名、角色、手头任务数、负载           | 负载超 100% 用警示色；只列本迭代相关成员                           |
| 延期事项      | 事项、原计划日、延期天数、原因、责任人 | 按延期天数降序；原因要具体（「等第三方网关限流确认」而非「待定」） |
| 迭代概览 stat | 总数 / 进行中 / 已完成 / 阻塞 四张     | 阻塞数非零时用警示色；数字必须来自真实取数                         |

## 语义色映射（全板一致）

通用纪律见 SKILL.md「设计规范」。本场景语义色映射：

| 语义              | token               |
| ------------------- | --------------------- |
| 进行中 / 当前关注 | `var(--mx-accent)`  |
| 已完成 / 健康     | `var(--mx-success)` |
| 延期 / 阻塞       | `var(--mx-danger)`  |
| 风险 / 临近截止   | `var(--mx-warning)` |
