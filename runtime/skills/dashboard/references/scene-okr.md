# 场景指引：个人 OKR 仪表板

通用规范（工作流程、文件协议、设计规范、红线）见技能主文件 SKILL.md，本文只补本场景约定。

## 这个仪表板给谁看

个人贡献者、独立开发者——管理自己的目标与待办。他们打开仪表板想立刻知道：**目标进展如何、今天该干什么、什么拖了**。与项目跟踪场景的区别：没有团队角色与人员负载，主角是「目标 → KR/任务」两级树。

## 取数来源（由 Agent 调用时决定；下面给两档推荐方案）

数据源**不写死**——按对话场景取最容易取得的真数据，唯一原则不变：内联静态值，绝不编造。两档推荐：

### 方案 A：树状 TODO.md + 轻度标记（轻量档；工作目录已有 TODO.md 时首选）

树状 checkbox 清单为骨架，行尾标记为渐进增强。**不改变纯清单的可读性**——没有标记的 TODO.md 一样能出板。mindx-work 产物栏的待办面板（TodoPanel）按本方案同一套约定解析与呈现（树状缩进 + 标记徽标），界面与仪表板口径一致。

### 树状映射

| 清单结构 | 语义 |
| --- | --- |
| 一级条目（无缩进的 `- [ ]`） | 目标 O |
| 缩进子条目 | 该目标的 KR / 任务 |
| `- [x]` | 已完成（优先于一切行尾标记） |

### 行尾标记（可选，空格分隔，写在行末）

| 标记 | 维度 | 含义 | 无标记时 |
| --- | --- | --- | --- |
| `@today` / `@week` / `@later` | 时间 | 今日 / 本周 / 将来 | 视为 `@later` |
| `@doing` / `@defer` | 状态 | 主动推进中 / 延期搁置 | 正常进行 |
| `@ahead` / `@ontrack` / `@behind` | 品质（**只标 O 级行**） | 领先 / 正常推进 / 落后 | 未评估 |

### 解析规则

1. **只认行尾标记**：出现在行末、以空格与正文分隔；正文中间的 `@` 词不算标记。
2. **勾选优先**：`- [x]` 行无视一切行尾标记，直接计已完成。
3. **每维度每行至多一个标记**，重复出现取第一个。
4. **不解析日期**：`@today/@week/@later` 是语义标签，不是日期计算。
5. **未标记不报错**：全无标记的清单照样出板——时间全部落「将来」、状态全部「正常」、品质维度留空态。

### 统计口径

| 指标 | 口径 |
| --- | --- |
| 目标数 | 一级条目数 |
| KR / 任务数 | 全部子条目数（含已完成） |
| 近期待办 | 未完成子任务中 `@today` + `@week` 的数量 |
| 目标完成度 | 该目标下已完成子任务 ÷ 该目标全部子任务 |
| 品质评估 | 只统计 O 级行的标记；无标记的目标**不计入**品质卡，卡内注明「N 个目标未评估」 |

### 方案 B：结构化表格（结构化档；数据量大或需要持续维护时推荐）

一张表格讲全部字段，列直接映射语义，无需行尾标记解析。Excel / CSV / Markdown 表格 / 飞书表格导出均可（Excel 先转 CSV 再读）：

| 列 | 语义 | 取值与缺省 |
| --- | --- | --- |
| 目标 | 一级目标 O | 文本 |
| KR / 任务 | 该目标下的子任务 | 文本 |
| 状态 | todo / doing / done / defer | 缺省 todo |
| 时间窗 | today / week / later | 缺省 later |
| 品质（只填目标行） | ahead / ontrack / behind | 缺省未评估 |

统计口径与方案 A 完全一致（见下方统计口径表）：完成度 = 该目标下 done ÷ 全部；近期待办 = 时间窗 today+week 的未完成任务。字段齐就出全板，缺列就按缺省处理，同样不报错。

## 布局设计语言

常见版式起点：

- **首屏概览 stat 行（4 张）**：目标 / KR·任务 / 近期待办 / 已完成——三个问题里最直接的数字结论。
- **中部双列**：
  - 左列「目标达成」：每个目标一条进度条，结论先行；
  - 右列「分布」：时间分布（今日/本周/将来）+ 状态分布（正常/延期）两块 bars。
- **品质评估卡**：有标记才成卡；全部未评估时留空态卡，写明「暂无品质评估——在目标行行尾加 @ahead/@ontrack/@behind」。
- **底部整行**：目标明细表（目标、KR 数、已完成、近期动作、品质徽标）。
- **这不是死规定**：目标很少（1~2 个）时进度条可并入 stat 行下方的单卡；用户只关心「今天干什么」就把时间分布与近期动作提前放大。

## 部件内容引导

| 部件 | 显示什么 | 注意什么 |
| --- | --- | --- |
| 概览 stat | 目标 / KR·任务 / 近期待办 / 已完成 四张 | 近期待办 = `@today`+`@week` 未完成子任务；全部来自真实清单 |
| 目标达成 progress | 每目标一条：目标名 + 完成度 | 完成度 = 子任务完成比；延期搁置的目标用警示色标出 |
| 时间分布 bars | 今日 / 本周 / 将来 | 只统计**未完成**子任务 |
| 状态分布 bars | 正常 / 延期 | `@defer` 计延期 |
| 品质评估 bars | 领先 / 正常推进 / 落后 | 只计有标记的 O；未评估不计入；全未评估时空态 |
| 目标明细 table | 目标、KR 数、已完成、近期动作、品质徽标 | 未评估显示中性「未评估」徽标；近期动作取该目标下 `@today`/`@week` 的任务名 |

## 语义色映射（全板一致）

通用纪律见 SKILL.md「设计规范」。本场景语义色映射：

| 语义 | token |
| --- | --- |
| 进行中 / 当前关注 / 领先 | `var(--mx-accent)` |
| 已完成 / 健康 / 正常推进 | `var(--mx-success)` |
| 延期搁置 | `var(--mx-danger)` |
| 落后 / 风险 | `var(--mx-warning)` |
| 未评估 / 空态 | `var(--mx-text-tertiary)` |

对应脚本 tone：`@today`→accent、`@week`→info、`@later`→neutral；正常→ok、`@defer`→danger；`@ahead`→accent、`@ontrack`→ok、`@behind`→warn；未评估→neutral。
