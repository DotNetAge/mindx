# 场景指引：需求管理仪表板

通用规范（工作流程、文件协议、设计规范、红线）见技能主文件 SKILL.md，本文只补本场景约定。

## 这个仪表板给谁看

产品负责人、项目负责人——管理需求池。他们打开仪表板想立刻知道：**池子多大、什么优先做、卡在哪一环、谁在做什么**。与项目跟踪场景的区别：主角是「需求条目」及其生命周期（待评审 → 待启动 → 设计中 → 开发中 → 已完成），不排期到人天甘特，重点是优先级与状态流转的全局分布。

## 取数来源（由 Agent 调用时决定）

数据源不写死，按对话场景取最容易取得的真数据：issue/需求文件、Excel/CSV 导出、对话上下文中的需求清单均可。能取到**结构化表格就优先用列映射**（编号、标题、优先级、状态、负责人各一列）；只有自由文本清单时，行尾标记方案参照 scene-okr.md。唯一原则不变：内联静态值，绝不编造。

## 布局设计语言

常见版式起点：

- **首屏概览 stat 行（4 张）**：需求总数 / 进行中 / 待评审 / 已完成——池子规模与健康度先给结论。P0 数非零值得单独一张警示卡。
- **中部双列分布**：优先级分布（P0/P1/P2）+ 状态流转分布（按生命周期各阶段计数）——两块 bars，回答「什么优先、卡在哪」。
- **负责人维度**：一张 table，行 = 负责人，列 = 各状态计数与合计——回答「谁在做什么」。
- **底部整行明细表**：需求条目清单，P0 置顶；行内徽标标优先级与状态。
- **这不是死规定**：需求少（<10 条）时负责人维度可并入明细表；用户强调某个状态（如「设计积压了」）就把对应分布提前放大。

## 部件内容引导

| 部件 | 显示什么 | 注意什么 |
| --- | --- | --- |
| 概览 stat | 总数 / 进行中 / 待评审 / 已完成，P0 数可选第五张 | 进行中口径 = 已进入执行管道的阶段合计；数字来自真实清单 |
| 优先级分布 bars | P0 / P1 / P2 | 建议只统计未完成口径（已完成不参与优先级焦虑） |
| 状态流转 bars | 待评审 → 待启动 → 设计中 → 开发中 → 已完成 | 阶段名按对话中的实际生命周期措辞，不硬套 |
| 负责人维度 table | 行 = 人，列 = 各状态计数 + 合计 | 覆盖全部需求，合计必须与总数对账 |
| 明细表 table | 编号、标题、优先级徽标、状态徽标、负责人 | P0 置顶；编号用等宽字体 |

## 语义色映射（全板一致）

通用纪律见 SKILL.md「设计规范」。本场景语义色映射：

| 语义 | token |
| --- | --- |
| 最高优先 / 阻塞（P0） | `var(--mx-danger)` |
| 次高优先 / 临近（P1） | `var(--mx-warning)` |
| 进行中（设计中 / 开发中） | `var(--mx-accent)` |
| 已完成 / 健康 | `var(--mx-success)` |
| 待评审 / 低优先（P2） | 中性（脚本 neutral tone） |

对应脚本 tone：P0→danger、P1→warn、P2→neutral；设计中/开发中→accent、待评审→neutral、已完成→ok。
