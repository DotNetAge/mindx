## 2026-11-17 去掉技能内的执行方枚举与查询命令（workbuddy）

- 问题：指令冲突——0.8.1 用 `mindx agent list --json` 当候选执行方来源，越出计划技能的职责：①计划能力只该规定「必须点名到具体执行方」，不该定义候选池长什么样；②团队会话里编制已在上下文（蓝图、项目说明、成员职责），清单命令一跑就把候选池重定义成本机已雇佣名单，与上下文分工冲突时会让 LLM 用命令结果覆盖已知的人；③清单是 mindx 的事实，换个运行环境即死指令，撞上「写死环境专属路径」反模式。与 0.5.5「同伴技能不指名道姓」同源，是同类越界的另一种形式。
- 否决：删掉选岗规则、回到凭印象指派——那正是 0.8.1 之前缺规则时的病，等于用取消规则换来「不越界」；只在命令前加一句「优先用上下文的」——仍然留着一个会覆盖已知的强指令源，优先级靠自觉不能靠排序。
- 修正：`dispatch-matching.md` 第一节改为候选来源优先级链（用户点名 > 上下文已载入的分工 > 运行环境提供的清单 > 无对口三出口），明写「后层不得覆盖前层，清单只补齐不重定义」，并删除全部环境快照（原 15 岗 4 领域一段）与具体命令；第二节比对改为「职责描述 + 能力标签 + 触发语」，落笔要求由「执行方 + 命中依据」扩为「执行方 + 命中依据 + 依据来源」；第四节把 `CollectResults` 等实现细节抽象为「异步派发 + 收割 1 轮」；失败模式补「技能里跑清单命令覆盖上下文分工」一条。SKILL.md 第四步、S2 判据、档位表注、反模式、templates 负责人列统一去掉 `agent_name`，改称执行方。version 0.8.1 → 0.8.2。
- 验证：`mindx skill validate --path mindx/runtime/skills/goal-planner` 全绿（150 行、soft_rules 0）；`grep -rn "agent list\|agent_name\|mindx \|bega-\|本机"` 在 SKILL.md 与 references 零命中；7 条 markdown 链接零断裂。
