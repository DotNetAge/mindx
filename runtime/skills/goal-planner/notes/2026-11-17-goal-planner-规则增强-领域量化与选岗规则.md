## 2026-11-17 补齐领域量化与选岗规则（workbuddy）

- 问题：规则缺失——三处缺口同源：「派给谁」没有可复算依据。①领域全文无定义却当闸门用（S2 判据「跨 ≥3 领域」、2 档「>8 或跨 ≥3 领域」），且 estimation-method 明写「探测点按动词定义、不按领域定义」，方法论回避领域、闸门却依赖领域，互相矛盾；②`SubAgent` 的 `agent_name` 是必填参数，正文只写「具名智能体」，不给检索命令、不给匹配规则、不给无对口时的出口，执行到这一步只能凭印象猜，名字错了被柔性拒绝白耗一轮；③派单固有成本未计入决策——`SubAgent` 异步派发需 `CollectResults` 收割，子代理另需装配 10-30k 基础上下文，而 4-8 点档（12-25 轮）直接派单，没算这笔启动成本。另发现 S1「自己干」与 S2「派 ≥2 个 Agent」之间留空档：只派 1 个岗无归属。
- 否决：保留「跨 ≥3 领域」并给领域下定义——实测 `mindx agent list --json` 本机仅 4 个 category（产品研发 9 / 市场营销 3 / 内容创作 2 / 办公提效 1），偏斜严重，「跨 3 领域」几乎等于「跨全公司」，现实极少触发，定义得再准也是空转的闸门。用 category 去重代替 agent_name 去重——同领域多岗交接（如 bega-domain → bega-qa）只会算 1 个领域，而真正决定派单规模的是要惊动几个岗。
- 修正：新增 `references/dispatch-matching.md`（领域只作检索入口、任务→候选岗三级查并落笔命中依据、无对口三出口、派单净收益判定、四条失败模式）；第四步改为「选岗并判定执行方式」，要求负责人栏写 `agent_name` + 命中依据，并加派前三问（有对口岗 / 净收益为正 / 值得断线），单任务预算 <8 轮不派；S2 与 2 档闸门由「跨 ≥3 领域」改为「涉 ≥3 个岗」；S1 补「或只派 1 个岗」填补空档；estimation-method 第三节补「派单是双份基础会话」；templates 负责人列改「agent_name + 命中依据」；反模式补「派给相关专家」「小活派大岗」；team-creator 中断链引用「派工前估算定档」改指现有章节名。version 0.8.0 → 0.8.1。
- 验证：`mindx skill validate` 对 goal-planner（148 行）与 team-creator（129 行）均全绿；技能内 7 条 markdown 相对链接全部实存、零断裂；`mindx agent list --json` 实测 15 岗 4 领域、全部 hired，作为判据依据写入 dispatch-matching 第一节。
