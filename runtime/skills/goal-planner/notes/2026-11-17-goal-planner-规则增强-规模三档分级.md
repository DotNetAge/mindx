## 2026-11-17 加规模三档分级，小活不再走全流程（workbuddy）

- 问题：规则缺失——技能只对「任务」估档，对「目标」没有规模判定，任何目标一律五步 + 落盘 + 建账。按技能自身数字算账：固定开销约 4-6 轮（意图卡 1 + 分解 1 + 逐任务列探测点 1 + 写计划文件与任务书 1-2 + 建账 1），已接近 0 档全部预算下限 6 轮，规划成本吃掉甚至超过执行预算。同时「不使用：会话内即时协作（不建账）」与账本「意图卡成形后立即入账」互相矛盾，而「即时协作」全文无定义，执行者只能凭感觉选路。
- 否决：只修矛盾句、让执行者自行把握——判据仍留在脑子里，等于没修。把轻量场景写进 description 的「不使用」——那 3 个任务的清单就完全无流程可依，用户随后要派人时也没有升级入口。沿用 L0/L1/L2 命名——与任务估算档 0/1/2 档同形，会产生「L2 的 0 档任务」这种要读两遍的句子，改用 S 前缀并在正文声明这是两套刻度。
- 修正：新增第零步规模预判（S0 清单直答：任务 ≤3 且无依赖，不落盘不入账；S1 轻量计划：4-8 任务或存依赖、仍自己干，落盘简版不入账；S2 完整计划：跨 ≥3 领域 / 派 ≥2 个 Agent / 总预算 >25 轮 / 需批准才动手 / 有实质歧义），配强制升档（被问工期、要派人、发现跨领域或真依赖即升）、不许为省事降档、S0 清单即交付物而 S1 等一句确认再动手；第一步按档裁剪意图卡（S0 跳过、S1 只填目标与判据）；澄清门只对 S2 强制，轻档在回答里一句话带问；第三步允许 S1 按表取区间不列探测点清单；账本准入只收 S2（删除「不使用」节里重复且矛盾的建账句）；templates 补轻量档模板；evals 补一条 S0 触发句；反模式补「小活走全流程」「轻档硬扛重活」。version 0.7.2 → 0.8.0。
- 验证：`mindx skill validate --path mindx/runtime/skills/goal-planner` 全绿（139 行、soft_rules 0）；`grep -n "L0\|L1\|L2"` 在 SKILL.md 与 references 零残留；建账准入规则全文只剩账本节一处，与「何时使用」不再互相矛盾。
