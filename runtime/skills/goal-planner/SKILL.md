# 目标规划师

本技能做的是一件事：**把老板的目标变成可检查的账本条目，并把工作安排到人**。秘书不做具体的事——入账、意图、分解、排程、检查、汇报，全是安排与核对；具体执行交给被安排的负责人。

## 账本（唯一事实源）

位置：`<项目>/.agents/plans/goal-ledger.md`。目标的记录、回顾、检查、汇报全部以它为准——不凭记忆，不散落在对话里。

一目标一节，条目格式：

```markdown
## G-20261013-01 <目标标题>
- 状态：进行中
- 原话：<老板原话逐字>
- 意图：<一句话>
- 成功判据：<什么样子算达成，具体可检查>
- 不做：<明确排除的范围>
- 分解：
  - [ ] T1 <领域任务> → <负责人>（cron：<表达式>）验收：<标准>
- 进展：
  - 2026-10-13 <一句话>
```

规则：

- **原话逐字录**——原话是第一事实；意图与分解都允许修正，原话永远不改写
- 状态只有四种：进行中 / 已完成 / 暂缓 / 已取消
- 进展倒序追加、一行一条，不改写历史；忘记就如实说，不补写编造
- 编号 G-YYYYMMDD-序号，全仓唯一
- **建账时机**：用户下达目标、方向、要求"落实 / 安排 / 推进"时；会话内即时协作不建账
- 与 TODO.md 分工：TODO.md 是项目杂项待办，账本只管老板目标与其派工跟踪，不互相搬运
- 与 deep-review 分工：本技能管目标从入账到验收核对的全程安排（下一步做什么）；deep-review 管做完之后的沉淀——从笔记与记忆提炼规则、技能与报告。复盘提出的新目标须经用户认可后回到本技能入账，deep-review 不直接改账本

## 第一步 意图分析（原话 → 意图卡）

从原话提炼四项，写入账本条目：

1. **收益方与场景**——谁因此受益，什么场景
2. **成功判据**——具体到可检查，"变好"不是判据，"上线后每周至少 X 次"才是
3. **范围边界**——明确"不做的事"，防发散
4. **含糊点**——表述模糊不臆测，整理成一次澄清提问单次问清，不拆多轮问卷

## 第二步 目标分解（意图卡 → 任务清单）

分解为领域任务，每个任务四件套（与 scheduler 技能的派工日志规范一致）：

1. **目标**——一句话说清要达成什么
2. **验收标准**——干成什么样算成
3. **上下文位置**——材料在哪些文件目录（绝对路径）
4. **产出与去向**——结果写到哪、给谁看

分解原则：

- **派给谁**：对照已装 agent 的 IDENTITY 画像匹配负责人；没有合适的如实标注"需先建能力"，不硬派
- **领域名不是任务**——"项目管理"不是任务，"带状态流转的缺陷清单"才是
- 每个任务可独立验收，依赖顺序在任务行标注

## 第三步 排程执行（账本 → Cron）

- 任务四件套原文即派工日志的 Content，排程章法由 scheduler 技能承载
- 循环例行用 cron_expr，单件用 scheduled_at
- 排程完成后把表达式回写账本任务行，保持账本可追溯

## 每日检查例行（秘书自己的循环任务）

每天固定时刻自唤醒执行（用 Cron 工具给自己 create 循环任务，`session_id` 用 `new`）：

1. 读账本，列出全部进行中目标
2. 对照各任务状态：执行产出、负责人反馈
3. 收集各项目状态
4. 进度再排程：延误的改期或加派，新任务按分解补充
5. 更新账本进展行
6. 汇总当日简报汇报用户

## 注意事项

- **检查是核对不是重做**——发现偏差回到排程层处理，不亲自下场执行
- **汇报说人话**——老板视角：推进到哪、卡在哪、需要老板决策什么；不堆术语

## 反模式

- **目标记在对话里或散落 TODO**——账本才是事实源
- **意图未澄清就分解**——臆测的目标安排是空转
- **分解成领域名词**——不是可验收任务
- **秘书下场干活**——职责越界，执行属于负责人
