# 派工

本技能做的是一件事：**安排工作，不干工作**。把已经分解好的工作排给合适的负责人，并让它按时发生。 Cron 工具是唯一通道——不落 shell、不经 CLI。

## 何时派工（调度判断）

适合派工的活：

- **可异步完成**——不需要用户在场，不依赖当前会话的上下文
- **验收标准明确**——干没干成有客观判据
- **重复发生**——例行工作用循环任务承载

不适合派工的活，如实告知用户改走会话内协作：需要用户即时裁决或多轮确认的；上下文大量留在当前会话里、一条派工日志装不下的。

## 派给谁（负责人匹配）

- 先对能力：查候选负责人的 IDENTITY 画像，能力不匹配的人不派
- 再看过载：`Cron` list 查该负责人现有排程，同一时段已有任务的避开或改期
- 未雇佣的负责人先确认其存在，再派工

## 工作日志怎么写（Content 规范）

Content 是负责人被唤醒时看到的**全部上下文**，必须自足。一份合格的派工日志四件套：

1. **目标**——一句话说清要达成什么
2. **验收标准**——干成什么样算成
3. **上下文位置**——去哪些文件与目录找材料（写绝对路径）
4. **产出与去向**——结果写到哪、给谁看

反模式：一句话派工（"写博客文章"）——负责人醒来不知道给谁写、写到哪、什么标准，注定空转。

## 三种形态

- **例行（循环）**：固定节奏的工作，用周期 cron 表达式，如每天 09:00
- **单件（定点）**：某时刻干一次，用 `scheduled_at` 指定时间点（如 2026-10-13T14:30:00），到点执行一次后**自动禁用**，无需手动删除
- **即时（下一秒）**：马上要干，`scheduled_at` 写最近的时刻即可——派工即发生，用户体感是直接指挥

## 排程卫生

- **先查后建**：create 前先 list，同一负责人同时段不得双任务撞车
- **一次性任务自动禁用，残留要清**：`scheduled_at` 创建的任务到点自动禁用，事后从 list 里看到 disabled 残留时 delete 掉
- **失效例行及时停**：不再需要的循环任务 update `enabled=false` 或 delete
- **自我唤醒**：给自己排任务时，Content 写清"继续什么工作、上下文在哪"，`session_id` 用 `new`——每次新会话，不占主会话

## Cron 工具速查

四个操作：`list`（列全部）、`create`（agent + content 必填，cron_expr 与 scheduled_at 二选一）、`update`（id + 要改的字段）、`delete`（id）。参数细节以工具定义为准，此处不重复。

cron 表达式 6 字段：秒 分 时 日 月 周，支持秒级。常用模式：

| 用途                      | 表达式            |
| ------------------------- | ----------------- |
| 每天 09:00                | `0 0 9 * * *`     |
| 工作日 10:00              | `0 0 10 * * 1-5`  |
| 每 30 分钟                | `0 */30 * * * *`  |
| 10 月 13 日 14:30（单件） | `0 30 14 13 10 *` |
