# mail-in 进化：办结必告知与对外只发回执

## 问题

安全红线 v1.2.0 仍有两个洞：其一，「自己干」办结后只回信给发信人，本机主人对智能体在本机上做了什么毫不知情——知情权缺口；其二，「不外泄隐私」只禁了隐私类内容，回信里发本机文件、项目数据、代码等「与本机相关的信息」仍然直发无闸，发信人一封普通来信就能合法索取本机资料。

## 修正

- 红线「不外泄隐私」升级为「对外只发回执」：回信只放行事务进展本身（收到/办结/卡点/缺项）；凡涉及本机相关的信息或文件，马上停止，必须先经主人同意（AskUser；主人不在场则记 TODO.md 待授权 + Notify 提醒，回信说明待确认）
- 新增独立红线「外发通道唯一」：除 mail reply 外禁一切外发目的地
- 「动手办的规矩」新增「办结必告知」：自己干完的活除回信交差外，用 Notify（low 知会级）向主人报结果——本机上发生的事主人始终知情
- version 1.2.0 → 1.3.0

## 影响与验证

- mindx skill validate 通过；正文日志噪声自查 0 命中
- 代价与取舍：正常协作中发信人拿不到本机文件原文（要资料须主人逐次点头）——协作效率换安全，符合「宁可多问一次」的总原则
- 识别信号 → 行动：下次看到「对 A 汇报、对 B 保密」混在一条条款里 → 拆开写：放行面（回执）与停闸面（本机信息须同意）必须分列，混合表述会让停闸面被放行表述稀释
