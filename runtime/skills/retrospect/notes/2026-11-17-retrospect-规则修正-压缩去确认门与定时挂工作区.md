## 2026-11-17 压缩去掉确认门、定时改挂工作区级（workbuddy）

- 问题：指令冲突——①2.2 要求「压缩前向用户说明哪几个会话要动」，但压缩的是窗口不是数据：消息不删、会话文件保留完整历史、摘要落 `.agents/memory/`，事前确认属多余打断，与「用户无感」目标直接抵触；②「定时触发由运行环境机制承载」未限定层级，若被理解成按 Agent 建 cron，十个 Agent 就是十份重复自省——自省管的是整个工作区，挂错层会线性放大成本。
- 否决：保留一句话确认——一句话也是打断，不是无感；完全放开不限条件——会把正在推进的会话压掉，后续推理只剩摘要而用户无从察觉，这是真正的风险点。
- 修正：2.2 改为「自动执行，不询问用户」，保留预检（免费）作为唯一前置；新增「只压空闲会话（最后活动 ≥1 小时）」，进行中的跳过并进报告；`scan.py debt` 增 `idle_hours` 与 `safe_to_compact` 两个字段供判定；「何时跑」补「定时检测挂工作区级，不挂 Agent 级」并写明按 Agent 建 cron 会在数量上放大；定时任务 prompt 同步去掉人工确认。version 2.3.0 → 2.3.1。
- 验证：`mindx skill validate` 全绿（162 行、soft_rules 0）；`scan.py debt` 实测 11 个超阈会话全部 `safe_to_compact=true`（最长空闲 340 小时、最短 6 小时），字段可判；`mindx session` 子命令核对确认无 cursor 回退手段，故「窗口不可逆、数据可逆」的表述与实现一致。
