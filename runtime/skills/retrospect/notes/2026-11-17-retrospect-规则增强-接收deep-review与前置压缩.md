## 2026-11-17 接收 deep-review、前置会话债务压缩、出口扩至五类（workbuddy）

- 问题：流程漏洞 + 指令冲突——①治理链缺入口减债：会话上下文过期后重拾要按全价重放历史，而用户不会主动压缩，技能里也没有压缩这一步（全库 `grep compact` 在 retrospect 命中 0 次）；②与 deep-review 影子重叠：两者都对 notes/memory 聚类、都产出技能沉淀与插件提议，`grep` 显示两技能互不提及，description 又都抢「复盘」，同一句话必然双命中；③两边出口清单各残一半——retrospect 只有技能/文章/插件三类，deep-review 独有 AGENTS.md 规则与角色招募；④同一批 notes 处置相反：deep-review 写「只读不删」，本技能写「直接删除」，与项目规则「notes 提取后即删」冲突。
- 否决：保留两个技能各管一段（划界方案）——知识层（L1/L2→L3）与时机（存量超阈）完全重叠，划界只是把重复藏进 description；把压缩做成独立技能——压缩产出摘要直落 `.agents/memory/`，本身就是记忆生产，与治理同层同时机，独立反而制造第三个影子。
- 修正：①新增「何时跑」节，把触发信号与阈值（会话窗口 >100,000 tokens、notes ≥30 条、长期闲置、用户要求）与计量方式收进技能，声明这是唯一定义处，规则文件只留指针；②步骤 2 改为「盘债与装载素材」，先 2.1 盘会话债、2.2 预检后压缩（说明游标前移不可逆、摘要落 memory 所以必须先压再装载、未达阈值被拒属正常返回、可整会话丢弃时不必压缩）、再 2.3 装载；③分流由三类扩至五类，补 AGENTS.md 规则修订与角色招募（三条件门）；④接收 deep-review 的主题澄清（对象不明先确认项目、范围可收窄）与「跨会话重复 ≥2 次」的提炼门；⑤报告增加会话债务一项；⑥反模式补三条盘债与压缩相关。version 1.2.0 → 2.0.0。
- 验证：`mindx skill validate` 全绿（143 行）；`mindx skill add` 后运行时副本与源逐字节一致（diff 0）；`mindx session compact --help` 实测确认预检/不可逆/摘要落盘三条机制。
