# 能力搜索

按语义一次检索一类对象，凭分数决定认不认，装了才用。

## 何时使用

- 「有没有能做 X 的技能 / 智能体 / 团队 / 插件」
- 「怎么实现 X」「你能做 X 吗」，而 X 可能是市场里已有包的常见任务
- 想复用别人的成品，而不是从零创建
- 想扩展宿主能力（面板、连接器、编辑器类功能）
- 执行普通任务时上下文里没有技能清单，需要判断本机是否已有对口技能

## 核心决策路由

### 第零步：本地优先

检索市场之前先看本机：

```bash
mindx skills discovery
```

- 仅当当前上下文中没有任何技能清单时执行一次；清单已在上下文中则跳过。
- 只取名称与描述列表用于比对，禁止扩成正文。
- 本地清单里有对口技能，直接按名加载执行，不再进市场检索。
- 本地没有对口的，才进第一至五步。
- 需要的对象不是 skill（岗位、班底、插件）时，跳过本步直接定 kind。

### 第一步：定 kind

从需求里判断要找哪类对象，只搜真正对应的一类：

| 需求特征                      | kind     |
| ----------------------------- | -------- |
| 某个领域的做法、流程、模板    | `skill`  |
| 某个岗位、角色、专业身份      | `agent`  |
| 一整套协作班底（负责人+成员） | `team`   |
| 宿主里的界面/功能扩展         | `plugin` |

判不出类别时先搜 `skill`，最多再补一类，禁止四类全发。

### 第二步：语义检索

```bash
mindx market search --kind <kind> --k 5 "<整句需求>" --json
```

- query 传整句：场景 + 要的产出，例如「把一份财报拆成收入利润变动和毛利率归因」。
- 必须用长参数 `--k`，短参数 `-k` 未注册会报 `unknown shorthand flag`。
- 需要 daemon 在跑；报连接失败先 `mindx start`。
- 返回字段只有 `kind / name / description / score`。

### 第三步：凭分数裁决

| score       | 动作                                     |
| ----------- | ---------------------------------------- |
| ≥ 0.75      | 强命中，直接呈现候选                     |
| 0.65 – 0.75 | 中等命中，呈现时说明「相关但不完全对口」 |
| < 0.65      | 视为未命中，不出现在候选里               |

实测基线：无关意图也会硬凑出 0.56–0.63 的包，所以 0.65 是下限而非参考值。

分数只是入场券，不是结论。每个过线候选再核对一遍 `description` 是否真的覆盖需求；分数高但职责不对口的（实测出现过 0.70 分的包实为另一领域），按未命中处理，不出现在候选里。

未命中先换一种说法重搜一次；仍无对口候选的，如实回答市场没有，禁止把低分包说成「差不多能用」。

### 第四步：对照本机是否已装

```bash
mindx skill get <name>      # skill
mindx agent get <name>      # agent
mindx team get <name>       # team
```

返回配置即已装；报不存在即未装。plugin 无本地查询命令，只按 market 结果记录包名。

呈现候选时标注「已装 / 未装」：

```
<name>（score 0.8x，已装）— <一句话能力>
<name>（score 0.7x，未装）— <一句话能力>
```

### 第五步：安装（用户要调用时才装）

搜完不装。用户明确要使用某个未装包时，才执行对应命令：

```bash
mindx market install skill <name>    # 落全局技能库
mindx market install agent <name>    # 落 ~/.mindx/agents/，默认未雇佣
mindx market install team <name>     # 落 ~/.mindx/teams/<name>/
mindx agent hire <name>              # agent 包安装后必须雇佣才进会话
```

- plugin 的 `market install` 不接受（只认 agent/skill/team），只给包名让用户在宿主插件市场装。
- skill 安装后当前会话仍不识别时，用回去的技能目录注册：

```bash
mindx skill add <技能目录绝对路径>
```

`mindx reload skills` 不存在，禁止写这条命令。

### 第六步：装完再用

- skill：按名加载后再执行其流程。
- agent：`hire` 之后按其 IDENTITY/SOUL 执行，或交给用户直接对话。
- team：会话解析到 leader，等同于与该 leader 对话。

## 纪律边界

- **禁止全量列举本机库**：`mindx skill list --json` 会把数百条描述灌进上下文，本技能只按需单个查询。
- **禁止低于 0.65 硬凑**：宁可回答没找到，也不把沾边的包推给用户。
- **禁止编造包名**：只呈现 market 真实返回的 `name`。
- **禁止擅自安装**：安装会改动本机库与雇佣状态，必须由用户提出使用意图后执行。
- **一次检索一类**：`market search` 一次只搜一个 shelf，四类分别调用不等于一次并行查四类。
- **禁止重复取清单**：上下文已有本地技能清单时，不再执行 `mindx skills discovery`。

## 失败模式

- 现象：`Error: kind 必须为 agent、skill 或 team`。原因：用 plugin 调了 install。
  动作：plugin 只检索不安装，向用户说明需在宿主插件市场安装并给出包名。
- 现象：`包详情 API 响应状态 400`。原因：包名拼错或该包已下架。
  动作：回到检索结果核对 `name` 原样重试；仍 400 则告知该包当前不可安装。
- 现象：检索返回全部低于 0.65。原因：市场确实没有对应能力。
  动作：换一种说法重搜一次，仍空则如实告知，转为用通用能力直接完成或提议新建。
