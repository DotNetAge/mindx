# 寄信

本技能做的是一件事：**把话说清楚，寄给对的人**。信是组织内跨机器沟通的唯一载体——收信人的智能体会第一手阅读你的信，并判断怎么处置。你写什么，决定对方做什么。

## 寄信前想清楚（收件人判断）

- 收件人写**组织成员的显示名**（如「积木君」），拿不准组织里有谁时先问本机主人，不猜名字
- 一封信说一件事：安排是安排，汇报是汇报，知会是知会，不混装
- 琐事不必写信——当面能说清的（同一台机器）直接说，走对话不走信

## 信怎么写（正文规范）

信的正文就是对方做事的全部依据。安排类的信务必写全四件套：

1. **目标**——一句话说清要达成什么
2. **验收标准**——干成什么样算成
3. **上下文位置**——材料在哪、找谁问、有哪些前提（写绝对路径）
4. **产出与去向**——结果交到哪、什么时间前要

求助类的信至少说清：请对方做什么、为什么找对方、希望什么时候有回音。汇报类的信务必**按信件编号回信**（见下），让寄件人对上号。

反模式：一句话派活（「帮忙查个东西」）——对方醒来不知道查什么、给谁用、什么时候要，注定空转一轮再返工。

## 命令速查

```bash
# 寄新信（正文直接写在命令行）
mindx mail send <收件人> "<主题>" <正文...>

# 长正文走文件或管道
mindx mail send <收件人> "<主题>" --body-file /path/to/body.md
cat body.md | mindx mail send <收件人> "<主题>"

# 按信件编号回信（回复原信，寄件人自动对上号）
mindx mail reply <信件编号> <正文...>

# 查收件箱 / 发件对账
mindx mail inbox
mindx mail sent
```

寄出后的回执会告知「已直送对方智能主机」还是「留在对方信箱等对方上线收取」——两条路都会送到，无需重发。

## 交差纪律

- 别人托你办的事，办完**必须回信**（`mindx mail reply <信件编号> "..."`），办到什么程度就说什么程度，不夸大不含糊
- 办不成也要回信说清卡在哪，让对方有时间改道
- 收到新信还没办完、对方又来信催，先回信说明进展再继续办
