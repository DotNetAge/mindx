# PR : Agent 自进化 —— 由对话自省生成技能

> 本 PR 从 PR-PROMPTS.md 的讨论中拆分而来。技能生成的依据是 Agent 的"自进化"能力，不是随便一说就有的想法，需要深入且专门的探讨。它不影响到本次提示词解耦与存储重构（见 PR-PROMPTS.md）的范围，故独立成篇。

## 背景

Skill 是一种经验升级机制，与人的经验获得非常相似。其中 Agent 级与项目级技能的来源，是一种全新的获取渠道：不是官方内置、不是市场安装、也不是用户手工编写，而是 Agent 在对话过程中"自己悟出来"的。

## 粗略想法

在上下文压缩时增加一种"自省"能力：从上下文中总结

- 是否存在相同的执行逻辑；
- 是否有可重复多次运用的逻辑；
- 不同轮次间是否具有类似的推理路径或推理目标。

当这些信号出现时，将其提炼为一个 Skill。此时生成的技能存于 ProjectDir 的 `.skills` 隐藏目录中（项目级"动态 Skill"），只有在特定的 ProjectDir 中才会被发现。

## 方向性共识（已对齐部分）

- 触发点倾向挂在全量压缩（TryCompact）的摘要环节——那里本来就有一场"对整段上下文的总结"，顺带提取重复的推理路径 / 可复用逻辑，边际成本最低。
- 产物带来源元数据（生成 Agent、时间、revision），同名版本递增而非覆盖，防止自省反复产出同名技能互相冲掉。
- 晋升由用户裁决：Agent 级 → 全局级的提取、项目级 → 装配的裁决，均在界面中由用户决定（存储结构与晋升管线见 PR-PROMPTS.md 第三节）。

## 遗留开放问题

1. Agent 级与项目级技能是否为同一自省机制的两个落点？判定标准（实践验证程度、用户确认时机）待定。
2. 自省产物生成时是否自动沉淀，还是需要用户确认后才生效。
3. 自省提炼的判定标准：什么样的"重复"才值得固化为技能，避免把偶发路径固化成错误经验。
4. 项目级技能的防膨胀上限与清理策略。
